# Roadmap: Helix v1.12 — Bench Stack & Tool Evaluation

**Milestone:** v1.12
**Start phase:** 75 (continuing from v1.11 last phase 74)
**Phase count:** 15 (Phases 75–89)
**Granularity:** coarse (config.json)
**Total v1 requirements:** 63
**Coverage:** 63/63 mapped (100%)
**Created:** 2026-06-13

---

## Headline Claim This Milestone Must Land

> "Same model + same budget — with Helix the agent solves more tasks, with fewer tokens, fewer files read, and fewer destructive edits."

The 15-phase shape is strictly bottom-up: the result-JSON schema + fairness contract land first, kernel-level ablation disable flags land second, and every later phase writes into the stable schema or consumes the stable kernel surface. The reports phase is last because it aggregates everything.

### Phase 75: Schema, Fairness Contract & Tree Skeleton
**Goal**: Every downstream phase has a versioned `result.v2.json` schema to write into and a single `fairness_contract.go` struct to load model config from — so no benchmark adapter ever defines its own model snapshot, temperature, or cost row.
**Depends on**: v1.10 Phase 67 (`internal/eval/` patterns — sandbox, trace tap, score DSL)
**Requirements**: BENCH-01, BENCH-02, BENCH-03, BENCH-06, FAIR-01, FAIR-02, FAIR-03, COST-01, INFRA-01, INFRA-02, INFRA-03
**Success Criteria** (what must be TRUE):
  1. `tree -d -L 2 bench/` shows the canonical six-dir layout `bench/{datasets,runners,languages,evaluators,reports,schema}/` — the five runtime dirs plus the `schema/` **contract-only** dir (D-07; `bench/BENCH.md` documents the runtime-vs-contract distinction). `eval/` source/runtime code is byte-identical to pre-milestone HEAD; the single permitted change is the one-paragraph INFRA-03 reciprocal pointer added to `eval/EVAL.md` (D-08/INFRA-03).
  2. `helix-bench --help` lists 5 subcommands (`run`, `fetch-datasets`, `doctor`, `report`, `validate-cost-table`); `helix-bench doctor` succeeds on a clean Linux host with documented prereqs.
  3. A golden `result.v2.json` fixture validates against `bench/schema/result.v2.schema.json`; the schema version field is required and a backwards-incompatible change bumps the major version.
  4. Every benchmark adapter loads its effective config from `bench/runners/fairness_contract.go`; the loader refuses to start if any mode overrides without `WaiverReason`; the deprecation-calendar gate fails when the pinned snapshot is within 30 days of EOL.
  5. `make verify-tos` and `make validate-cost-table` exit non-zero when an attestation is older than 90 days or when `cost-table.yaml` `valid_until` is past; `bench/PROVIDERS.md`, `bench/LICENSES.md`, `bench/BENCH.md` (with eval↔bench separation note) all render.

  - [x] 75-02-PLAN.md — Wave 1: six-dir bench/ skeleton + BENCH.md/PROVIDERS.md/LICENSES.md + eval cross-link + REQUIREMENTS v1→v2 (BENCH-01/06, INFRA-01/02/03)
  - [ ] 75-03-PLAN.md — Wave 1: result.v2.schema.json + golden-validate test (TDD; BENCH-03, FAIR-03)

### Phase 76: Ablation Profiles + Kernel Subsystem Disable Flags
**Goal**: Land the only invasive code paths inside the daemon (kernel-level `disable_lsp_subsystem` / `disable_structured_edit_subsystem` flags) plus the 4 new bench profile YAMLs, with a static `vet-ablation-leakage` analyzer so they are stable before any downstream phase consumes them. `no_semantic` flag is intentionally deferred to Phase 81 because it depends on the v1.10 Phase 65 SemanticLookup wiring being un-wired cleanly.
**Depends on**: Phase 75, v1.10 Phase 65 (SemanticLookup seam — read for context only)
**Requirements**: ABLATE-02, ABLATE-05, ABLATE-07, ABLATE-08
**Success Criteria** (what must be TRUE):
  1. 4 new profile YAMLs (`bench-full.yaml`, `bench-no-lsp.yaml`, `bench-no-semantic.yaml`, `bench-no-structured-edit.yaml`) ship under `internal/profile/profiles/`; profile-filter golden tests cover each; the loader rejects unknown mode names.
  2. With `disable_lsp_subsystem: true`, an E2E `no_lsp` task emits **zero** `lsp.*` OTel spans (trace-tap assertion is a hard fail); `lspProbeForEdges`, RepoMap `SetEnrichFn`, and live-update OnEdit hooks are no-ops.
  3. With `disable_structured_edit_subsystem: true`, structured-edit tools (`replace_symbol_body`, `fuzzy_edit`, `insert_before_symbol`, `insert_after_symbol`) return `Unsupported` with a documented kind; `replace_in_file` falls through to exact-match only.
  4. `vet-ablation-leakage` static analyzer in `internal/lint/` is wired into `make vet`; a deliberate test-case violation makes `make vet` fail with a clear diagnostic.

### Phase 77: Bench Runtime & First E2E Smoke
**Goal**: Stand up the bench orchestrator end-to-end on a single Go ToolBench task in a single mode — no container, no per-language sprawl — so the runtime shape is forced into existence and proven before evaluators or ablations land on top.
**Depends on**: Phase 75 (schema, tree), Phase 76 (bench profile YAMLs exist so daemon subprocess can be started with `--profile=bench-full`)
**Requirements**: BENCH-04, BENCH-05
**Success Criteria** (what must be TRUE):
  1. `cmd/helix-bench run --benchmarks=toolbench-go --modes=your_agent_full --tasks=<one>` completes ≤ 30 s and writes a schema-valid `result.v2.json`; one daemon subprocess per `(task × mode)`; no port collisions on `--parallel=4`.
  2. `make bench-quick` exits 0 with ≥ 1 task succeeding in CI in ≤ 90 s; `make bench` and `make bench-<suite>` invoke `cmd/helix-bench run --benchmarks=…` as documented.
  3. `bench/runtime/sandbox/` thin-wraps `internal/eval/sandbox/` (path-traversal hardening + lstat-symlink rejection carry forward); `bench/runtime/subprocess/` spawns `helix daemon` and (eventually) `claude` CLI with PID-gated per-cell JSONL paths.
  4. The first E2E smoke run produces a merged OTel trace (daemon-tap + agent-tap) verifiable in Jaeger import with zero orphan spans and zero PID cross-talk.

### Phase 79: Evaluators & Result-Schema Metrics Layer
**Goal**: Every per-task `result.v2.json` is populated with all 17 normalized metrics from real graders — including the load-bearing `tokens_input/output` from the provider's `usage` block (not Helix's MCP counter), `edit_locality_given_solved` as the headline locality metric, and a single merged OTel trace per `(task, mode, run_index)`.
**Depends on**: Phase 77 (bench runtime), Phase 78 (Go ToolBench produces real test results to grade)
**Requirements**: METRIC-01, METRIC-02, METRIC-03, METRIC-04, METRIC-05, METRIC-06
**Success Criteria** (what must be TRUE):
  1. `bench/evaluators/{test_runner,patch_validator,token_meter,tool_trace_analyzer,regression_checker}/` produce all 12 base metrics + 5 extended metrics (`semantic_tool_calls`, `edit_distance_patch`, `retry_count`, `compile_errors_before`, `compile_errors_after`) on a real task; missing metrics are explicit nulls, not omissions.
  2. A regression test asserts `tokens_input/output` source-of-truth is the provider response's `usage` block, NOT Helix's MCP-side counter; cached-input tokens (`tokens_input_cached_read`, `tokens_input_cache_write`) are reported as separate columns.
  3. `edit_locality` definition (`1 − (modified_files / total_files_in_repo_subtree)`) and `regression_rate` definition (`(failing_pre-existing_tests_post_patch / passing_pre-existing_tests_pre_patch)`) are unit-tested at edge cases (root-only = 1.0, all-files ≈ 0.0, synthetic regression case); both definitions documented in `bench/evaluators/METRICS.md`.
  4. Trace merging produces a single merged trace per `(task, mode, run_index)` from Helix daemon OTel + agent CLI subprocess + bench harness span; Jaeger import shows full continuity from `bench.run_id` root to LSP leaves; no orphan spans, no cross-cell PID leakage.

### Phase 80: Five-of-Six Ablation Runners + Fairness Enforcement
**Goal**: All 6 ablation modes are operational end-to-end on the Go ToolBench corpus, holding the same-model-same-budget invariant via the Phase 75 fairness contract. `your_agent_full` + `baseline_plain` + `no_lsp` + `no_structured_edit` produce real per-mode `result.v2.json` rows; `no_semantic` scaffolding is in place but the kernel flag (ABLATE-06) lands in Phase 81; `baseline_rag` runner stub exists but its real implementation lands in Phase 83.
**Depends on**: Phase 76 (bench profile YAMLs + no_lsp / no_structured_edit kernel flags), Phase 79 (evaluators produce real metrics), Phase 78 (Go ToolBench is the corpus)
**Requirements**: ABLATE-01, ABLATE-03
**Success Criteria** (what must be TRUE):
  1. Each of 6 modes runs end-to-end on a smoke task; mode definition lives in `bench/runners/<mode>/MODE.md`; ablation runs produce schema-valid `result.v2.json` rows tagged with the mode.
  2. `baseline_plain` reuses existing `internal/profile/profiles/baseline.yaml` (no new YAML); tool inventory for `baseline_plain` is empty except for the shell/grep/read/edit/test that the agent runtime exposes natively (documented decision in `bench/BENCH.md`).
  3. Same-model-same-budget invariant is enforced at runner-startup: per-task token budget is identical across modes; CI contract test asserts every runner's effective `(model_id, temperature, max_tokens, system_prompt_hash, retry_policy, cache_policy)` equals the fairness contract.
  4. Ablation deltas (`your_agent_full` − `baseline_plain`, `full` − `no_lsp`, `full` − `no_structured_edit`) compute correctly on the Go ToolBench corpus and surface in the per-mode result rows.

### Phase 82: Multi-Run Aggregator, BCa Bootstrap, pass@k, Cost Rollup, First Leaderboard
**Goal**: First externally-publishable artifact — `bench/aggregator/` consumes N ≥ 3 runs per (task, mode), computes BCa bootstrap CIs (≥ 10,000 resamples) and `pass@k` via the HumanEval closed-form, rolls up `cost_per_solved_task` against the Phase 75 cost table, and emits the first `leaderboard.md` from internal-ToolBench-Go data only.
**Depends on**: Phase 80 (real ablation data for `your_agent_full` + baselines), Phase 79 (metrics layer feeds the aggregator)
**Requirements**: STATS-01, STATS-02, STATS-03, STATS-04, COST-02, COST-03
**Success Criteria** (what must be TRUE):
  1. Default `N ≥ 3` runs per (task, mode) is enforced by the matrix runner; the aggregator refuses to write `reports/` if any cell has fewer than the configured minimum; schema validates `runs` array length ≥ N.
  2. BCa (bias-corrected accelerated) bootstrap CIs with `N_resamples ≥ 10,000` compute for every metric on every leaderboard row; unit tests pass against a closed-form known distribution; reports flag any cell where the BCa CI overlaps a neighbor (no claim of "X > Y" without non-overlapping CIs).
  3. `pass@1` and `pass@k` computed per HumanEval closed-form `1 − C(n-c, k)/C(n, k)`; unit test against published reference values passes.
  4. `cost_per_solved_task` = (sum across solved tasks of provider-`usage`-derived USD cost) / count(solved); matches a hand-computed example for a known run; `cost_quality.md` renders cost-per-solved-task per mode × benchmark with BCa CIs.

## Phase Ordering Rationale

- **Phase 75 (Schema + Fairness + Tree)** is first because every downstream phase writes `result.v2.json` or loads `fairness_contract.go`. Schema-first means every later phase is schema-validated; fairness-first means no adapter ever defines its own model config.
- **Phase 76 (Ablation profiles + 2/3 kernel flags)** lands the only invasive code paths inside the daemon early. `no_semantic` flag (ABLATE-06) is deliberately deferred to Phase 81 because it requires un-wiring v1.10 Phase 65's SemanticLookup and benefits from soaking the simpler `no_lsp`/`no_structured_edit` flags first.
- **Phase 77 (Bench runtime + first smoke)** stands up the orchestrator on one Go task in one mode — no container, no per-language sprawl — to force the runtime shape before evaluators or ablations land on top.
- **Phase 78 (Go ToolBench first)** dogfoods Helix's own language for the tightest debug loop; validates the per-language test-runner pattern before generalizing.
- **Phase 79 (Evaluators)** must precede more runners — unscored results are useless. The provider-`usage` token-counting boundary (METRIC-03) is the load-bearing token-attribution invariant; landing it early prevents Pitfall 5.
- **Phase 80 (5-of-6 ablations)** unlocks the attribution story on Go ToolBench alone (no new infra needed); `no_semantic` is the trickiest mode and gets a phase to itself.
- **Phase 81 (`no_semantic` flag)** is a dedicated phase because the strangler-fig in `get_repo_map`/`get_context` can only be un-wired by a kernel config gate, not a profile YAML.
- **Phase 82 (Aggregator + first leaderboard)** renders against ToolBench-only data first; public-benchmark phases write into a stable consumer.
- **Phase 83 (baseline_rag)** soaks the cheaper subsystem before public benchmarks land. Self-contained; standalone `cmd/helix-bench-rag` binary; chromem-go + OpenAI/Ollama embedding pipeline drags in real complexity that must NOT be folded into the ablation-mode phase.
- **Phase 84 (Container runtime)** lands after ToolBench + Aider Polyglot subset can run container-free; runtime hardened against Aider Polyglot Python slice first.
- **Phase 85 (Aider Polyglot + 7 ToolBench langs)** is the cheapest external benchmark (no Docker, no upstream Python harness, just per-language test runners) — it's the natural target for the earliest "land an external number" phase, and the per-language image pre-bake work is the same dependency as the remaining 7 ToolBench languages.
- **Phase 86 (CrossCodeEval + RepoBench)** are completion-only via `dataset-loader-only`; mid-size; cover C# (only public coverage we ship).
- **Phase 87 (SWE-bench Verified + UTBoost)** is the load-bearing external claim; UTBoost rescorer ships in the same phase as the adapter because they are intrinsically coupled — shipping one without the other regresses `verified_correctness`.
- **Phase 88 (Multi-SWE-bench + Terminal-Bench)** is final external coverage; both via `subprocess-shellout`; per-language slicing is the v1.12 contribution.
- **Phase 89 (Reports + CI policy + canary)** is last because reports aggregate every input. CI cost-policy split protects the milestone budget; contamination canary closes the loop on Pitfall 1.
