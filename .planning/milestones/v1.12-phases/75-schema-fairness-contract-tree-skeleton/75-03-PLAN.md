<objective>
Wave 1 of Phase 75: author the versioned `result.v2.json` result-schema contract that every
downstream phase (76-89) writes into, plus the golden-fixture validation test that keeps the
schema self-enforcing. This is the BENCH-03 deliverable. Per D-03/D-04 the version surfaces as
a single required top-level greppable string `schema_version: "v2"`; `required` is kept MINIMAL
so new fields land OPTIONAL (additive-only = minor; breaking changes bump to v3 major).

FAIR-03 SCOPE (substrate only): this plan delivers ONLY the FAIR-03 schema substrate — the
cached-input token columns (`tokens_input_cached_read`, `tokens_input_cache_write`, D-12) and a
`fairness.overrides[]` array (D-10) as schema fields. It does NOT implement the >5% between-run
variance DETECTOR or the `cost_quality.md` fairness WARNING (the FAIR-03 acceptance test). Those
land downstream: the variance gate consumes STATS-01 N≥3 in Phase 82; the warning renders in the
reports phase (Phase 89). Verify-phase must grade FAIR-03 as "schema substrate present" here, NOT
as the full FAIR-03 acceptance criterion.

TDD: RED = a golden-validates test that fails because no schema exists; GREEN = author the
schema so the golden fixture validates; REFACTOR = tighten `required`/`$comment` while keeping
green. Use `santhosh-tekuri/jsonschema/v6` (already vendored), Draft 2020-12, OFFLINE.

Purpose: the stable result contract is the keystone of the whole milestone — 14 later phases
depend on metric stability across v2.
Output: schema document, golden fixture, validation test.
</objective>
