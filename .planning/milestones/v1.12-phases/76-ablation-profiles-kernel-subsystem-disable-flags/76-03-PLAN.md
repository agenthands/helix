<objective>
Land the `vet-ablation-leakage` static import-boundary analyzer in
`internal/lint/ablationleakage/`, its `cmd/vet-ablation-leakage` singlechecker
entrypoint, a deliberate `testdata/` violation proving a green→red flip, and the
`make vet` wiring — a near-clone of `internal/lint/noduckdb` (ABLATE-08, D-07).

Purpose: A compile-time structural guard (the house import-boundary pattern)
that fails the build if an ablation-gated tool package imports a
disabled-subsystem package it must not reach. This is the static complement to
the kernel `Unsupported` runtime guard (Plan 76-01); the analyzer's honest v1
scope is compile-time import leakage only (D-08).

Forbidden-edge decision (LOCKED per D-07 / RESEARCH Q2 / Pitfall 5): pin a
genuinely-architectural edge — the bench-runner namespace
`github.com/agenthands/helix/bench/runners` MUST NOT import the two
disabled-subsystem packages `github.com/agenthands/helix/internal/kernel/lspool`
or `github.com/agenthands/helix/internal/semantic/store`. This edge is correct
today and forever architectural (a bench runner orchestrates a daemon subprocess;
it never links the kernel pool or the semantic store directly). Do NOT pin
`internal/kernel/* → internal/fuzzy` — the structured-edit tools legitimately
import `internal/fuzzy` in the enabled build, so that edge is flag-conditional,
not architectural (Pitfall 5). The real `bench/runners/*` packages land in Phase
80; correctness this phase is proven entirely by the `testdata/` fixtures (the
go tool ignores `testdata/`), so the green→red flip is demonstrable now without
a real consumer.

Output: analyzer.go + test + testdata fixtures; cmd main; Makefile wiring.
