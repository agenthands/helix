    `if semanticStore != nil`, not by `effSemanticDisabled`.

via `GetLatestFileFact`, `LatestCommittedSnapshot`, `QueryEffectiveAdjacency`,
`CountStaleScoreRows`. It is LATENT today only because the shipped five_of_six
smoke uses a store-OFF seed (five_of_six_test.go:40, seed IT-go-patch-apply-1) so
the store never opens — but a store-ON no_semantic cell (an incremental_update
task) WOULD read through these ungated pipelines.

Remediation (verifier's preferred option, 81-VERIFICATION.md:147-149 + the
planning constraint): GATE the reads structurally so the guarantee holds for any
corpus, NOT just rely on the current store-OFF seed. Gate the SetActivateCallback
background pipelines + SetFileFactStore on effSemanticDisabled, forcing them
off / Noop under build-but-block. CRITICAL: respect D-04 — the store stays BUILT
and the bundle stays NON-nil; gate the READ-DRIVING CALLS, do NOT nil the store
or the bundle (81-CONTEXT.md D-04; the build-but-block guards at daemon.go:324 and
daemon.go:518 stay untouched, exactly as Plan 81-04 left them).

ordered AFTER 81-06 (depends_on) because of the masking interaction at
81-VERIFICATION.md:113: CR-01 and WR-02 mask each other — the store-ON proof only
has teeth once 81-06 made the runtime assertion fail-CLOSED on a real run.

for a store-ON arm, and prove it dynamically now that 81-06 gave the assertion teeth.
Output: gated background read pipelines + a store-ON no_semantic end-to-end proof.
