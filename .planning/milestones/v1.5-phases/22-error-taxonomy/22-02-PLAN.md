    ```go
    package mcp

    import (
        "encoding/json"

        serr "github.com/postfix/serena/internal/errors"
    )

    // Domain sentinel errors -- re-exported from internal/errors for backward compatibility.
    // Callers should migrate to serr.ErrXxx in Phase 23.
    var (
        ErrSessionExpired    = serr.New(serr.Timeout, "session expired")
        ErrWorkspaceNotReady = serr.ErrNoWorkspace
        ErrToolNotAvailable  = serr.ErrUnsupported
        ErrProjectNotFound   = serr.ErrNotFound
        ErrLSCrashed         = serr.New(serr.Internal, "language server crashed")
    )

    // ErrorDetail provides structured error info for MCP responses.
    // Deprecated: will be superseded by serr.Error in Phase 23.
    type ErrorDetail struct {
        Code       string `json:"code"`
        Cause      string `json:"cause"`
        Suggestion string `json:"suggestion,omitempty"`
    }

    // MarshalJSON returns the JSON encoding of ErrorDetail.
    func (e ErrorDetail) MarshalJSON() ([]byte, error) {
        type Alias ErrorDetail
        return json.Marshal((*Alias)(&e))
    }
    ```

    **Mapping rationale:**
    - `ErrSessionExpired` -> `serr.New(serr.Timeout, "session expired")` -- session expiry is a timeout-class event
    - `ErrWorkspaceNotReady` -> `serr.ErrNoWorkspace` -- direct Kind match
    - `ErrToolNotAvailable` -> `serr.ErrUnsupported` -- tool unavailable in current mode = unsupported
    - `ErrProjectNotFound` -> `serr.ErrNotFound` -- direct Kind match
    - `ErrLSCrashed` -> `serr.New(serr.Internal, "language server crashed")` -- LS crash is internal error

    **Note:** `ErrSessionExpired` and `ErrLSCrashed` use `serr.New()` (not sentinel re-export) because they need a specific message. `ErrWorkspaceNotReady`, `ErrToolNotAvailable`, `ErrProjectNotFound` use sentinel re-exports since they map directly to a Kind.

    **Important behavioral change:** The re-exported sentinels are now `*serr.Error` instead of `*errors.errorString`. Code using `errors.Is(err, mcp.ErrWorkspaceNotReady)` will match any `serr.Error` with `Kind: NoWorkspace` (because `serr.Error.Is()` compares Kind). This is the desired behavior -- Kind-based matching is more flexible than pointer equality. However, verify no code depends on pointer identity.

    Keep `ErrorDetail` struct for now -- Phase 23 removes it when tools switch to `serr.Error`.
