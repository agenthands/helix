## Implementation Decisions

### Product Identity & Tone
- **D-01:** Keep the existing hero tagline "Serena is the IDE for your coding agent" — it's concise and memorable
- **D-02:** Add a secondary subtitle emphasizing the code intelligence angle (e.g. "Code intelligence platform for MCP — 41+ tools across 52 languages")
- **D-03:** Product-aware technical tone — developer audience with clear value props and benefit statements, not dry or marketing-heavy
- **D-04:** Python legacy acknowledgment is a single footer one-liner ("Originally inspired by Python Serena") — not in Acknowledgements section, not prominent

### Structure & Section Order
- **D-05:** Add explicit table of contents near the top for navigation
- **D-06:** Restructure section order: hero -> TOC -> how it works -> advantages -> quick start -> features/highlights -> RepoMap -> production/obs -> languages -> tools -> architecture -> acknowledgements -> legacy footer
- **D-07:** Quick start moves up after the advantages table (currently buried after language/tool tables at line 186)
- **D-08:** Full Production & Observability section stays in README (signals production-readiness for adoption)

### Content Depth
- **D-09:** Language table (52 rows) and tool table (35+ rows) stay inline, not collapsed — auto-gen markers preserved
- **D-10:** Architecture section stays brief — 4-layer ASCII diagram + 2 paragraphs on daemon/pool. No expansion
- **D-11:** Quick start leads with `serena setup <client>` as primary install path; manual JSON configs go in a collapsed section or link to INSTALL.md

### New Capabilities Coverage
- **D-12:** RepoMap gets a dedicated subsection explaining get_repo_map + get_context capabilities (structural overview + task-focused context via PageRank)
- **D-13:** v1.7 features (fuzzy editing, smart errors, progressive descriptions, health tools, lazy init) get a "Key Features" or "Highlights" section with concise one-liners each

### Claude's Discretion
- Exact wording of subtitle line (D-02)
- Placement and naming of highlights section (could be "Key Features", "Highlights", or integrated into a broader section)
- How to present the collapsed/linked manual JSON configs in quick start
- Whether RepoMap subsection goes before or after production/obs

</decisions>
