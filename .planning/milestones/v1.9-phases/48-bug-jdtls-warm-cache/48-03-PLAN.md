<objective>
Wire the Java integration tests to the warm jdtls cache produced by Plans 01 and 02:

1. Drop `//go:build integration` from exactly five files — the minimum transitive closure
   required to compile `java_test.go` under default `go test ./...`:
   `java_test.go`, `harness.go`, `harness_test.go`, `helpers.go`, `a_doc.go`.
2. Leave the tag on the other 16 integration files (per CONTEXT D-11 / RESEARCH Pitfall 2).
3. Remove the `testing.Short()` skip from both Java tests (per D-09).
4. Add `Options.JdtlsDataDir` to the harness and make `StartTestDaemon` set
   `SERENA_TEST_JDTLS_DATA_DIR` on the daemon's process environment when the field is non-empty.
5. In each Java test, resolve the warm dir via `jdtlscache.ResolveDataDir` and pass it via `Options.JdtlsDataDir` before `StartTestDaemon`.

Purpose: Deliver success criterion #1 — `go test ./...` (no flags) includes the Java
integration suite, and second consecutive runs reuse the warm cache.

Output: Java tests runnable under default `go test ./...`; Pitfall 1 (build-tag
asymmetry) verified resolved; Pitfall 2 (harness_test.go speed) verified acceptable.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI / developer shell → test process | Invokes `go test`; path to jdtls comes from PATH |
| Test process → in-process daemon | Sets SERENA_TEST_JDTLS_DATA_DIR via t.Setenv |
| Daemon (same process) → jdtls subprocess | JdtlsAdapter reads env var and passes `-data <dir>` to the child |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-03-01 | Tampering | Attacker plants a malicious `jdtls` on PATH to have its content hashed + launched | accept | Same risk exists pre-phase (`requireLS` already uses `exec.LookPath`). No new attack surface — any malicious PATH entry already owns the developer's jdtls invocation. |
| T-48-03-02 | Information Disclosure | Newly-tag-free `harness_test.go` tests leak internal state in test logs | accept | These tests use `SkipLS:true` (verified via read_first) and operate on ephemeral `t.TempDir()` fixtures. Logs go to `go test` stdout only. No PII involved. |
| T-48-03-03 | Denial of Service | Dropping Short() skip + `-tags=integration` gating causes default `go test ./...` to take &gt;5min on a developer without jdtls | mitigate | `requireLS(t, "jdtls")` causes a clean skip when jdtls is absent — wall-clock impact is negligible. With jdtls present, the warm cache (Plan 02) ensures second-run performance; first run is intentionally scoped to the CI workflow (Plan 05). |
| T-48-03-04 | Repudiation | Test env var changes are not audit-logged | accept | `t.Setenv` automatically reverts at test end; Go runtime records env changes in test stderr on failure. Acceptable for test infra. |
| T-48-03-05 | Elevation of Privilege | Drops of `//go:build integration` inadvertently expose helpers (e.g. `StartTestDaemon`) to production binaries | mitigate | `test/integration/` is a `_test` package — files still only compile for `go test`, never `go build ./cmd/serena`. | T-48-03-06 | Tampering | Other integration tests (`concurrency_test.go`, etc.) accidentally lose their tag | mitigate | Explicit grep acceptance criterion: exactly 17 files must still have the tag. CI build (Plan 05) runs `go build ./test/integration/...` AND `go build -tags=integration ./test/integration/...` to catch either direction of asymmetry. |
