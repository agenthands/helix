# Phase 51.1: cgo-treesitter-gate - Context

**Gathered:** 2026-04-29
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase delivers **Path 2 of DEF-51-02**: gate the entire `internal/treesitter`
package behind `//go:build cgo` with a `//go:build !cgo` stub, so that
`CGO_ENABLED=0 go build ./cmd/serena` exits 0 and goreleaser can produce the
6 platform/arch archives required by Phase 51 SC-1. CGO=1 builds remain
byte-identical with all 23 tree-sitter languages registered.

**In scope:**
- Split `internal/treesitter/registry.go` (and any sibling files importing CGO bindings) into `_cgo.go` / `_nocgo.go` pairs (or equivalent file split) using `//go:build cgo` and `//go:build !cgo` tags.
- Provide a `!cgo` stub for `GrammarRegistry` whose public methods (`NewGrammarRegistry`, `GetLanguage`, etc.) **return an error / sentinel "tree-sitter unavailable in this build" rather than a silent empty registry**.
- Wire a daemon-level guard that **refuses to start** under `CGO_ENABLED=0` with a clear, actionable error directing users to the CGO=1 release binary or to build from source with `CGO_ENABLED=1`.
- Tag `internal/treesitter/registry_test.go` (and any downstream tests that exercise tree-sitter directly, e.g. `internal/repomap/extractor_test.go`, `internal/kernel/edit/treesitter_test.go`) `//go:build cgo` so `CGO_ENABLED=0 go test ./...` compiles and runs without those tests. Do NOT add `!cgo` "asserts empty registry" tests — there is nothing meaningful to assert on a build that refuses to start.
- Flip the existing release-snapshot dry-run job (currently flagged "expected to fail until DEF-51-02" per Phase 51 commit 1a1ce93a) to expected-pass; this serves as the CGO=0 build smoke gate. No new dedicated CI workflow.
- Update `.planning/phases/51-packaging-goreleaser/deferred-items.md`: flip DEF-51-02 status from OPEN → RESOLVED with a pointer to this phase.

**Out of scope (other phases or future milestones):**
- Vendor + stub all 19 upstream tree-sitter Go bindings (DEF-51-02 Path 1) — explicitly rejected by the roadmap entry for 51.1 (Path 2 chosen).
- Re-enable CGO in goreleaser with a per-target cross-toolchain (DEF-51-02 Path 3) — would produce *functional* CGO=1 archives but breaks the CLAUDE.md "single Go binary, no CGO dependencies" invariant. Tracked separately as a follow-up (DEF-51-03 candidate; planner records if not already filed).
- Pure-Go tree-sitter runtime via WASM (DEF-51-02 Path 4) — upstream not yet API-compatible.
- Homebrew / Scoop / native Linux package channels (PKG-02/03/04 → Phase 52).
- Restoring R/Swift to the `!cgo` registry (already a no-op via 51-03's `binding_nocgo.go`; no longer relevant once the whole package is gated).

</domain>

<decisions>
## Implementation Decisions

### Stub Semantics
- **D-01:** The `!cgo` stub for `internal/treesitter` exposes the same public API surface but **every public method returns an error / sentinel** ("tree-sitter unavailable in this build"). No silent empty registry, no degraded "RepoMap falls back to LSP only" path. Rationale (user, verbatim): *"it's pointless to do anything without CGO"* — CGO=0 binaries are placeholders that satisfy the goreleaser archive-count requirement, not functional builds. Surface the unavailability loudly, don't pretend.
- **D-02:** The daemon **refuses to start** under `CGO_ENABLED=0`. At bootstrap (in `internal/daemon/daemon.go` near step 12 where `treesitter.NewGrammarRegistry()` is called), detect the `!cgo` build and exit with a clear error pointing to the CGO=1 release binary or to building from source with `CGO_ENABLED=1`. Acceptance criterion 1 ("CGO=0 build exits 0") is satisfied because the *build* succeeds; the *runtime* honestly refuses. The exact mechanism (build-tagged `init()` constant, sentinel returned from `NewGrammarRegistry()` checked at the call site, or a dedicated `treesitter.IsAvailable()` probe) is planner discretion.

### Test Gating
- **D-03:** Tag `internal/treesitter/registry_test.go` and any downstream test that exercises tree-sitter directly with `//go:build cgo`. Under `CGO_ENABLED=0 go test ./...` those tests are excluded at compile-time and the suite stays green. Do NOT add `!cgo` tests asserting "empty registry" or "stub returns error" — given D-02 (daemon refuses to start), there is no meaningful runtime path to test. Researcher/planner enumerates the exact set of test files that need the tag during research.

### CI Smoke Gate
- **D-04:** The CGO=0 build smoke gate is the existing **release-snapshot dry-run job**, currently flagged "expected to fail until DEF-51-02" per Phase 51 commit 1a1ce93a. This phase flips it to expected-pass. Rationale: the goreleaser snapshot path tests the full cross-compile matrix (6 archives, all GOOS/GOARCH combos) — strictly stronger than a `CGO_ENABLED=0 go build ./cmd/serena` step on a single host arch. No new dedicated CGO=0 CI workflow is added in this phase.

### Defect Bookkeeping
- **D-05:** On phase completion, update `.planning/phases/51-packaging-goreleaser/deferred-items.md`: DEF-51-02 status flips from `OPEN` → `RESOLVED` with a pointer to phase 51.1's PLAN/SUMMARY. Phase 51 VERIFICATION.md / VALIDATION.md gaps that depended on DEF-51-02 (notably SC-1's end-to-end UAT being "structurally blocked") are addressed by reference; no rewrite of Phase 51 artifacts.
- **D-06:** If during planning or execution it becomes clear that the goreleaser archives produced under CGO=0 are problematic to *publish* (e.g. users would download a binary that refuses to start) — that is a downstream concern for Phase 52 / a future DEF-51-03 (Path 3 re-enable-CGO-in-goreleaser). Phase 51.1 does NOT decide whether to publish CGO=0 archives on real `v*` tags; it only ensures the build succeeds and produces archives. Capturing that concern in `deferred-items.md` is in scope; resolving it is not.

### Claude's Discretion
The planner / researcher have authority on:
- Exact file split shape inside `internal/treesitter/` (single `registry_cgo.go` + `registry_nocgo.go` vs per-feature splits) — pick what minimizes diff churn against the current registry.
- The exact mechanism by which the daemon detects the `!cgo` build (build-tag-gated constant, `IsAvailable()` probe, error returned from `NewGrammarRegistry()`).
- The exact wording of the runtime refusal message, as long as it (a) names the cause ("tree-sitter / CGO"), (b) names a concrete remediation ("use the CGO=1 release binary" / "rebuild with `CGO_ENABLED=1`"), and (c) exits non-zero.
- The exact set of test files to tag `cgo` (researcher enumerates).
- Whether `internal/treesitter/bindings/{r,swift}/binding_nocgo.go` files (added in 51-03) survive as-is, get folded into the package-level gate, or are removed — they become dead code under D-01 since the whole package's `!cgo` path is the stub. Planner picks the cleanup with the smallest diff.
- Whether to file a follow-up DEF-51-03 entry now (CGO=0 archives are placeholders) or leave that to a Phase 52 spec.

### Folded Todos
None — no relevant todos for phase 51.1 in the queue.

## Reusable Assets & Patterns

- **Build-tag pattern from 51-03:** `internal/treesitter/bindings/r/binding.go` (`//go:build cgo`) + `binding_nocgo.go` (`//go:build !cgo`, `Language() unsafe.Pointer { return nil }`) is the proven pattern. Phase 51.1 applies it one level higher (whole package vs single binding) AND swaps "return nil" for "return error / refuse".
- **`(lang, ok)` idiom:** `GrammarRegistry.GetLanguage(name) (*tree_sitter.Language, bool)` is already used by callers (RepoMap, edit). Under D-01 the `!cgo` stub can preserve the signature but `ok` is always `false` AND a sibling error path surfaces — exact API tweak is planner discretion.
- **Daemon bootstrap order:** `internal/daemon/daemon.go` step 12 creates `GrammarRegistry`. Step 14+ install middleware. The `!cgo` refusal must fire BEFORE any optional-degraded-mode logic kicks in — fail fast.
- **Callers to verify under `!cgo` compile path:** `internal/repomap/extractor.go`, `internal/kernel/edit/treesitter.go`, `internal/skill/repomap/skill.go` and their `_test.go` siblings. Researcher confirms none import treesitter symbols that would force them under `cgo`-only constraint themselves.
- **CI job to flip:** the release-snapshot dry-run added in Phase 51 commit 1a1ce93a. Researcher locates the exact workflow file and the line/marker that flags it as expected-fail.
