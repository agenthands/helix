**Capture procedure (D-20, RESEARCH Pitfall #11):**

1. **Spin up Prometheus locally** scraping the Helix admin listener. Quick path:
   ```bash
   # In one terminal, run helix daemon with the admin listener enabled
   # (refer to USAGE.md Observability Quickstart for the exact flag/config)
   helix daemon --admin-addr=127.0.0.1:9091  # or whatever the current flag is

   # In another terminal, run a Prometheus instance with a scrape config pointing at 127.0.0.1:9091/metrics
   docker run --rm -p 9090:9090 -v $PWD/prom-tmp.yml:/etc/prometheus/prometheus.yml prom/prometheus:v3.x
   # prom-tmp.yml: scrape_configs: [{ job_name: 'helix', static_configs: [{ targets: ['host.docker.internal:9091'] }] }]
   ```

2. **Spin up Grafana 10+ locally** wired to the Prometheus from step 1:
   ```bash
   docker run --rm -p 3000:3000 grafana/grafana:10.4.0
   # Open http://localhost:3000, login admin/admin
   # Add Prometheus datasource at http://host.docker.internal:9090
   ```

3. **Populate the registry with realistic data** (Pitfall #11 - flat-zero graphs are not screenshot-worthy):
   ```bash
   # LOCAL ONLY - never on CI per project rule
   make bench
   # Plus exercise a few MCP tools - e.g., from a local Claude Code session, run:
   #   mcp__helix__find_references on a Go symbol in this repo
   #   mcp__helix__get_repo_map on this repo
   #   mcp__helix__list_file_outline on internal/obs/metrics.go
   ```
   Let bench + tool exercises run for 60-120 seconds so the rate(...)[5m] expressions have data.

4. **Import the dashboard**:
   - Grafana UI > Dashboards > New > Import
   - Upload `deploy/grafana/helix-overview.json`
   - When prompted for `DS_PROMETHEUS`, pick the Prometheus datasource added in step 2.
   - The dashboard should render with non-empty graphs.

5. **Capture the screenshot** at 1600x900 (D-20 - the default Grafana viewport):
   - Resize browser to ~1600x900 (or use a viewport tool).

   - macOS: Cmd+Shift+4, drag to capture; or `screencapture -R0,0,1600,900 docs/images/helix-overview-dashboard.png`.
