<objective>
Build `cmd/helix-cligen` — a build-time generator that emits a committed
`internal/cli/verbs_gen.go` populating the Phase 90 `verbSpecs` catalog with one
`helix <verb>` subcommand per callable tool in the live registry. The generator
recovers the tool-name → `*Args` struct binding (the one genuinely hard problem,
VERB-04) via a `go/packages` + `go/ast` scan of the `AddTool` call sites, derives
cobra flags from the struct's `json`/`jsonschema` tags with required-ness, and is
guarded by a `helix-cligen --check` drift gate that mirrors `cmd/docgen --check`.
The generated verbs flatten onto the ROOT command grouped by capability (per the
ROADMAP `helix <verb>` wording), replacing the single representative spine verb.
This plan also exports `internal/cli.VerbToolNames()` — a read-only accessor over
the catalog — so the 91-03 integration tests can read the verb surface from
outside the package without reaching into private state.

Purpose: VERB-01/02/03/04 — turn the 90-03 one-verb spine into the full
always-visible verb surface, drift-gated so a future `*Args` edit cannot silently
skew the CLI. This is the prerequisite the SEC-01/02 enforcement (91-02/03/04)
protects.
Output: `cmd/helix-cligen/{main,scan,render}.go`, the committed
`internal/cli/verbs_gen.go`, the exported `VerbToolNames()` accessor in
`internal/cli/verb.go`, parity + scan + accessor tests, root-command wiring, and a
`make verify-cligen` target + CI step.
</objective>
