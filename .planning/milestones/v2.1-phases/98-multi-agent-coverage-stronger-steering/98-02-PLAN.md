<objective>
AGENT thrust: surface the generated reference to non-Claude agents (AGENT-01), add
an idempotent sentinel-delimited instruction-file writer that never clobbers a
user's AGENTS.md/GEMINI.md/generic file and caps Codex AGENTS.md at 32 KiB
(AGENT-02), and add a new `codex` client that writes AGENTS.md + a `hooks.json`
pointing at `helix nudge` (reusing the ONE nudge engine) while Gemini/generic get
instruction-file steering only with NO fabricated hook (AGENT-03).

Purpose: Today the four non-Claude clients (gemini-cli, vscode, jetbrains, opencode,
generic) are teardown-only — they remove any prior helix MCP entry and write nothing
else. This plan flips codex + gemini-cli + generic to ALSO write a per-agent
instruction file, adds a brand-new `codex` client (the only one with a PreToolUse
equivalent), and reuses the existing `nudge` envelope for it. Every primitive needed
already exists in `internal/cli/` (idempotent managed-block write, atomic temp+rename,
JSON-via-marshal, path containment, embed accessor) — the new code is wiring + one
append helper, not new infrastructure.

Output: `EmbeddedReference()` in skill.go; new `setup_agents.go` (the idempotent
sentinel writer + Codex hooks.json writer) + `setup_agents_test.go`; `CodexRegistrar`
in setup_clients.go + flipped gemini-cli/generic registrars; `codex` in setup ValidArgs.
A blocking human-verify checkpoint confirms the Codex hooks.json / AGENTS.md byte-shape
and discovery path (research flags A1/A2 as not live-verified) before they are pinned.
</objective>
