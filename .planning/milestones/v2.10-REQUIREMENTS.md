# Requirements — Milestone v2.10 trace-data-flow verb (DATA_FLOWS read surface)

## Overview

**Goal:** make v2.9's DATA_FLOWS substrate consumable by an agent — a dedicated
`trace-data-flow` verb that answers *"from this seed, what is reachable via
interprocedural data flow?"* v2.9 emits the edges; v2.10 gives them a verb.

**Why a new verb (not extending get-change-impact-graph):** the blast-radius tool
is hardcoded to the `call_graph` projection and rewrites every edge `Kind` to
`"calls"` (per `explain_symbol_relatededge_test.go:11-13`) — a deep D-09 rework
with real regression risk to a review+ tool. `trace-data-flow` has different
semantics (reachability over data-flow edges, read+ tier) — conflating it with
blast-radius would mix two tools. A dedicated verb is additive + clean.

**Frozen-50 cost (accepted):** `reference_contract_test.go:58` anchors
`require.Equal(t, 50, len(VerbToolNames()))` *by design* — "a future verb
addition without a reference regen must trip this gate." Adding the 51st verb
deliberately bumps that anchor (the sanctioned mechanism), regenerates
`verbs_gen.go` + `reference.md`, and adds the verb to the SKILL decision matrix
(`querySet`/`actionSet`, `TestSkillMatrixClassificationComplete`).

## Locked design (grounded at HEAD)

| # | Decision | Grounding |
|---|---|---|
| L1 | New `DataFlowReachabilityAccessor` interface (additive — does NOT touch `SymbolEdgesAccessor`/its implementers) with `ReachableFrom(ctx, repoID, seed, maxHops) ([]ReachableNode, error)` | `accessors.go:272` (the accessor pattern); promotes the `reachable` BFS helper from `dataflow_edges_test.go` |
| L2 | `ReachableFrom` = BFS over the EXISTING `OutgoingEdgesOf` (no kind filter → returns DATA_FLOWS edges), filtered to `InternalKind=="DATA_FLOWS"`, seeded at a **parameter** node | `accessors.go:282` OutgoingEdgesOf → `store.QuerySymbolEdgesOutgoing` (`effective_graph.go:1111`, filters `src_node_id=seed`); `explain_symbol_relatededge_test.go:10-13` (no kind filter) |
| L3 | **Seed = a PARAMETER** (the taint entry point), resolved via SymbolID (the param's stable_key) or a `(file_path, function_name, param_name)` tuple. A *function* seed is NOT sufficient at HEAD: `QuerySymbolEdgesOutgoing(functionNode)` returns the function's own CALLS/IMPLEMENTS edges (src=function node), NOT its params' DATA_FLOWS edges (src=param node); and there is no query-time function→params path (`OwnerSymbolID` unpopulated per v2.9; `nodeToParams` is build-time only). Function-seed support is a future enhancement once owner-resolution exists | `tools_explain_symbol.go` seed resolution; `effective_graph.go:1111` (src_node_id filter); v2.9 D1b finding |
| L4 | Tier = **read+** (not review+) — reachability is a read | mirrors explain_symbol_deep (read+) |
| L5 | Bounded + deterministic: hop cap (`maxHops`, default ~5, max ~10), visited-set, node/edge caps; stable ordering | mirrors `bfsExpand` / D3 caps |
| L6 | Honest: no DATA_FLOWS edges from the seed → empty reachable set (not an error); external/unresolved seeds degrade gracefully | v2.9 honesty discipline |
