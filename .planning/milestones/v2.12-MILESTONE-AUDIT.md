## Honest limitations (stated, in-scope)

1. **C is the proven language.** C++/C#/Java share the identical batch wiring +
   ChainTokens path, but only C has co-capture linkage (Phase 135 scoped B3 to C) and
   a dedicated real-binary E2E fixture. C++/C#/Java var→type linkage is a fast-follow.
2. **Latent v2.11 crash fixed as a deviation:** C `signatureHash` truncates at `{`, so
   a struct definition + type-use collided on SymbolID → PK violation once B1 routed C
   into the committed path. Fixed by a deterministic snapshot-level SymbolID dedup
   (prefer-richer definition). The deeper cause (C emits struct type-uses as
   `definition.struct` symbols) is a documented deferred follow-up (would churn the
   `with_fields` golden).
3. **Deferred surfaces (unchanged):** Tier-1 LSP short-circuit
   (`QueryEffectiveEdges` stub, L5); the `type_chain` response field + its Schema-v6
   migration (L6, also unblocks v2.11 Tier-5 comment); cross-package/cross-TU
   resolution (batch typeIndex is intra-package/TU only, v2.11 M1 limit).
4. **The seed path is absolute:** `explain-symbol-deep`'s `file_path` seed must be
   absolute (`semantic_files.path` is stored verbatim from the full-walk). Documented
   in the E2E; not a defect, a usage contract.
