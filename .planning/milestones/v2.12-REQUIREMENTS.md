# Requirements — Milestone v2.12 Production wiring for the type resolvers (C-family E2E)

## Red-team fold — `agent://RedTeamV212` (verdict: REWORK → REWORKED) — supersedes prior scoping where noted

An independent pre-mortem (`agent://RedTeamV212`) found the original 5-piece spine
**necessary but insufficient**: as drafted, v2.12 could not produce a single real
(resolved, non-zero-target) RESOLVES_TO edge from real extractor output — for ANY of
the 12 languages, because the milestone rested on a **latent v2.11 resolver↔extractor
contract break** that only surfaces once wired. The "tiers 2-6 work in production"
proof (`type_resolver_plumbing_test.go:25`) used a **fabricated** signature
(`"var x Foo"`) that no real extractor emits. Findings, all verified against code:

### Blockers (all additive — must ALL be fixed)
- **B1 (BLOCKER) — extraction gate.** `langFromExt` (`semantic_wiring.go:1812-1825`)
  is a 4-language allowlist (`.go/.ts/.tsx/.js/.jsx/.py`); `classifyAndExtract`
  (`:1865-1868`) `continue`s on `lang==""`, so C-family files are dropped **before**
  the (registered) extractor runs. A lone C fixture yields zero symbols. **Fix
  (option-independent, folded):** extend `langFromExt` to the C-family
  (`.c/.h→c`, `.cpp/.cc/.cxx/.hpp/.hh/.hxx→cpp`, `.cs→c_sharp`, `.java→java`), a
  daemon-layer change, with an explicit determinism/perf note. This is now a named
  Phase-135 build item.
- **B2 (BLOCKER) — the Signature↔type contract break (the make-or-break).** Every
  resolver's Tier-2 does `parseAnnotation(sym.Signature)` on the **referencing**
  symbol (`c/resolver.go:76-82` et al.), but the extractors commit that symbol's
  `Signature` as a **bare name** with the type stripped (field `int x` →
  `"x"`; param `struct Person* p` → `"p"` — goldens `c/testdata/*/expected.json`),
  because variable/field/parameter captures have **no `@def.*.body` group**
  (`queries.scm`). `parseAnnotation("x")==""` → Tier-7 → `typeIndex` never consulted
  → `Target=0` → edge invisible on read. **This is a design fork — see below.**
- **B3 (MAJOR) — no (referencing-node, type-name) linkage.** `ReferenceFact.ContainerID`
  (`fact.go:145`) and `TypeFact.SubjectID` (`fact.go:171`) are **unpopulated** by the
  C-family extractors (goldens show `subject: "0"`). So the reference producer has no
  valid `RefNodeID` that both resolves at Tier-2 AND is readable (has a stable key).
  Coupled to the B2 fork; its resolution depends on the chosen option.

### Option-independent fixes (folded into the phases now)
- **D1 (MAJOR) — determinism.** `EdgeID` is a dense slice-index stamp
  (`semantic_wiring.go:1610-1612`); a driver that ranges a `map[groupKey][]…` appends
  in randomized order → permuted EdgeIDs → non-byte-identical snapshot (breaks SC6).
  **Fix:** the driver MUST iterate groups in **sorted key order** and refs in a stable
  order (by RefNodeID, then type name) before the EdgeID stamp; Phase 135 asserts it.
- **E1 (MINOR) — anti-vacuity must be differential.** With everything at Tier-7 today,
  "no spurious has_type edge" passes vacuously. **Fix:** SC5 becomes DIFFERENTIAL — the
  same suite asserts (i) a positive fixture yields **exactly one** has_type edge to the
  expected type AND (ii) a negative fixture yields zero; the positive (SC4) gates first.
- **L4 wording correction.** dst=0 edges are **WRITTEN** but rendered invisible at
  **read** time by `assembleEdgeRows` (`semantic_wiring.go:2595-2622`, the SymbolEdges
  adapter), not rejected at write. typeIndex-backed Target population is required for
  the edge to be **readable**. (Consider gating dst=0 rows out pre-append to avoid row
  bloat.)
- **SC2 wording.** Drop `EmitEdges/` — `EmitEdges` writes to the OVERLAY
  (`semantic_live_overlay_edges`), the WRONG path per L1; acceptance references only
  "the batch converter is invoked."
- **136 E2E flag.** `explain-symbol-deep` takes a single `--seed-json` flag
  (`verbs_gen.go:56`), e.g. `--seed-json='{"file_path":"…","symbol_name":"…"}'`.
- **Exit-gate honesty.** Phase 135's proof MUST run the **real C extractor** in-process
  (extractor → factsFromExtracted → WriteSnapshotFacts → QuerySymbolEdgesOutgoing) —
  NOT hand-built Facts. A test on fabricated signatures is not proof (it is what hid
  the contract break for a whole milestone).

### The B2/B3 design fork (routed to the co-driver — see decision record below)
How does the declared type name reach a resolvable, readable edge? Three options,
resolved in this milestone's decision record; the phases below assume the CHOSEN
option. The `L8` "daemon + small types helper" leaf-boundary claim is relaxed
accordingly (options (a)/(b) edit `internal/semantic/types/*` and/or the extractors).

## Overview

**Goal:** make the type-resolver subsystem actually run in production so a C-family
(C / C++ / C# / Java) type reference becomes a real, queryable `RESOLVES_TO` graph
edge — proven end-to-end through the `helix` CLI against a live daemon.

**Why this milestone exists (the true state, verified at HEAD):** v2.11 shipped
*unit-tested* C-family resolvers, but the entire type-resolver subsystem is
**orphaned from production**. Three independent code traces (archived at
`agent://ProdEdgePath`, `agent://ResolverWireGap`, `agent://VerbsAndE2E`) confirm:

- The 12-language dispatcher is constructed at daemon bootstrap
  (`internal/daemon/daemon.go:603-628`, held on `d.typeResolver`) and then **never
  consumed**: `Daemon.TypeResolver()` and `Daemon.SetSemanticGraph()` have ZERO
  non-test callers.
- `internal/semantic/types/emit.go:EmitEdges` — the only resolver→edge bridge — has
  ZERO production callers.
- Production has **no working `RESOLVES_TO` producer at all.** Path A (tree-sitter
  `factsFromExtracted`, `semantic_wiring.go:1934`) emits IMPLEMENTS/EXTENDS/IMPORTS/
  CROSS_*/DEFINES/MEMBER_OF/TESTS/HANDLES/SIMILAR_TO/… but **never** RESOLVES_TO or
  USES_TYPE. Path B (LSP cascade) has `Definition()` as a nil-stub AND every cascade
  edge collapses to `src=dst=0` (functionally dead).
- Each resolver's `typeIndex map[string]graph.NodeID` (the parsed-type-name → NodeID
  map that gives an edge a real target) is populated **only in `_test.go`** — nil in
  production.

**Consequence:** even a perfectly set-up E2E against today's binary shows zero
`has_type` edges and an empty `type_chain`. "Production E2E" is therefore **build
the integration spine, then prove it** — not "test an existing feature."

## What is already built (no work / no migration needed)

- **The resolver engine is complete and resolver-agnostic:** `Dispatcher`,
  `ResolveChain`/`ResolveSymbol`, `FixpointResolve` (`fixpoint.go`),
  `ResolveAccessChain` (`chain.go`), the 7-tier ladder (`ladder.go`), `EmitEdges`
  (`emit.go`). All 12 languages register.
- **Resolver tiers 2–6 are live** (v2.11 Phase 130 wired
  `typeStoreAdapter.QueryEffectiveSymbol` → `Store.QueryEffectiveSymbolFact`).
- **The read surface is production-wired with NO schema migration:**
  `explain-symbol-deep` → `SymbolEdgesAccessor.IncomingEdgesOf/OutgoingEdgesOf`
  (`semantic_wiring.go:285` wired) → `QuerySymbolEdgesOutgoing/Incoming` (NO
  edge_kind filter) → `MapInternalKind(RESOLVES_TO) → has_type`. Any `RESOLVES_TO`
  row in the committed snapshot surfaces to an agent as a `has_type` edge.

## The integration spine (Option A — ChainTokens feed the resolver)

> NOTE: the Red-team fold section (top of this doc) + `v2.12-ROADMAP.md` govern.
> The original 5-piece spine below is updated for Option A: the resolver's annotation
> tier is fed the linked type name via `ChainTokens` (fixing B2), and the producer
> gets its (var-node, type-name) tuples from the B3 linkage helper.

1. **Extraction reachability (B1)** — extend `langFromExt` (`semantic_wiring.go:1812`)
   so C-family files are extracted at all.
2. **var→type linkage (B3)** — in `factsFromExtracted`, pair each var/field/param
   symbol with its co-located `reference.type` by range → `(refNodeID, typeName)`
   tuples (deterministic; no signature/StableKey change).
3. **Resolver ChainTokens consumption (B2)** — each full resolver's annotation tier
   uses `req.ChainTokens[0]` (the linked type) when present, else falls back to
   `parseAnnotation(Signature)`. Touches `go/typescript/python/java/csharp/c/cpp`.
4. **Reference producer** — build `[]types.ChainRequest` from the tuples
   (RefNodeID = referencing symbol node, RefKind=`RESOLVES_TO`, ChainTokens=[type],
   FilePath via `fileIDToPath` `:2351`).
5. **typeIndex injection** — inject each resolver's parsed-name→NodeID map from the
   existing `nameToNode` index (`:2355`), honoring the `nameCount>1` anti-mis-bind
   guard. Needs a production injection path (exported setter / `NewResolverWithIndex`).
6. **Driver** — group refs per (package, language) in **sorted key order**, refs in
   a stable order (RefNodeID, then type name); `FixpointResolve`; apply
   `MinConfidenceForEdge` / `EmitUnresolvedEdges` (D1 determinism).
7. **Converter + wire** — `[]ChainResponse` → `[]semanticstore.EdgeFact` appended to
   `out.Edges` before the dense EdgeID stamp; runs inside `factsFromExtracted` after
   `nameToNode` + `resolvePendingDst` (`:2374`), giving the dispatcher a real consumer.

## Phases (see `v2.12-ROADMAP.md` for full detail)

- **Phase 135 — Extraction foundation:** B1 (`langFromExt`) + B3 (var→type linkage
   helper). Proven in-process against the REAL C extractor: non-empty C symbols +
   correct deterministic `(var, "Foo")` tuple + anti-vacuity guard. No StableKey churn.
- **Phase 136 — Resolver ChainTokens + producer + driver + emit:** B2 + spine pieces
   4–7. Proven in-process (REAL extractor → factsFromExtracted → WriteSnapshotFacts →
   QuerySymbolEdgesOutgoing): a committed `RESOLVES_TO` edge with a real DstNodeID;
   dispatcher has a real consumer; differential anti-vacuity; determinism.
- **Phase 137 — Real-binary C-family E2E + docs:** the headline deliverable — a real
   `helix` binary returns a `has_type` edge from `explain-symbol-deep` after a full
   index; differential anti-vacuity + determinism guards; `docs/type-resolution.md`
   updated + "7 languages" doc-drift fixed.

## Success Criteria

1. After Phase 135, `index-semantic-graph` on a real C fixture with a resolvable
   cross-file type reference produces a committed `RESOLVES_TO` edge whose DstNodeID
   resolves to the correct type symbol (proven in-process, real `*Store`).
2. The orphaned dispatcher has a real production consumer: `factsFromExtracted`
   drives it; `EmitEdges`/the batch converter is invoked on every build.
3. `typeIndex` is populated in production from `nameToNode`, honoring the
   `nameCount>1` anti-mis-bind guard; ambiguous / out-of-repo targets ⇒ no edge
   (DstNodeID stays 0, edge correctly dropped by L4) — never a fabricated endpoint.
4. Phase 136: a **real `helix` binary**, driven as a subprocess, returns a
   `has_type` edge from `explain-symbol-deep` for a C-family fixture after a full
   index — the production E2E the milestone is named for.
5. Anti-vacuity: a no-signal reference produces no spurious `has_type` edge
   (both in-process and via the real binary).
6. Determinism preserved: repeated index over the same fixture yields a
   byte-identical edge set (reproducibility invariant unbroken).
7. D-12 held (always emit; worst case unresolved). Confidence gate
   (`MinConfidenceForEdge`) applied.
8. Zero new Go deps; **no schema migration**; `make vet` (8 vettools) clean;
   affected-package `go test` green; docs updated + doc-drift fixed.
