## Refinement check — does the concrete system satisfy the abstract intent?

**Milestone intent (locked):** model flow originating **mid-body** — the return of an
in-body call (`y := producer(); sink(y)`), not just a parameter — and make it queryable
across **all 11 languages**, using the **no-schema-change** cut (edges anchor on existing
function + parameter symbol nodes).

**Delivered — confirmed against real code + a fresh run:**
- **In-body origins modeled.** `internal/semantic/dataflow/summary.go` widened the taint
  origin space to `Origin{Param, Callee}` (param ∪ callReturn), records `InBodyFlow{Producer,
  Consumer, ArgPos}`, with D-COMPOSE strict-whitelist unwrap. The `y:=producer();sink(y)`
  case that yielded NO edge at HEAD now records the in-body flow.
- **Emitted at existing symbol nodes, no schema change.** `inBodyDataFlowEdges`
  (producer.function → consumer.param, `def_use_inbody`) + `returnBridgeEdges`
  (param → enclosing-function, `def_use_return`) in `semantic_similarity_edges.go`. `EdgeFact`
  unchanged; `internal/semantic/store/` byte-unchanged (confirmed empty diff). Wired strictly
  after `dataFlowEdges` (semantic_wiring.go:2541-2542, M1 preserved — EdgeIDs unshifted).
- **All 11 languages, proven E2E.** `langFromExt` now maps .rs/.kt/.kts/.php/.rb (Path B,
  co-driver-approved). `TestCLI_E2E_InBodyDataFlow` = **11/11 PASS, 0 skip** through the real
  `helix` binary at audit time (go/ts/java/csharp/kotlin/php/python/ruby/rust/c/cpp).
- **Multi-hop reachability.** `def_use_return` is the composable connector:
  `producer(fn) → transform.param → transform(fn) → sink.param`. Proven in-process (139
  FLOW-05g) AND through the real binary via a function-seeded `trace-data-flow`
  (`TestCLI_E2E_InBodyMultiHop` PASS; broken-hop → unreachable).
- **Invariants held.** Zero new Go deps (go.mod/go.sum byte-unchanged); deterministic
  (re-index → identical edge set); the v2.9 `def_use` param→param SET byte-unchanged for the
  6 already-working langs (go/ts/java/csharp/php/rust).

## The one scope deviation (honest, co-driver-approved)

Phase 140 discovered that the daemon file-walk gate `langFromExt` did NOT map .rs/.kt/.php/.rb
— so rust/kotlin/php/ruby, though proven at engine+emission level (138 unit + 139 emission),
could NOT index through the real binary. The 138 all-11 matrix ran on bare parse trees and
never exercised this daemon-layer gate — an M5-class gap at a layer the unit test didn't cover.
This was escalated as a genuine design fork; the **co-driver chose Path B** (wire the 4 langs,
achieve 11/11 E2E). Verified: wiring adds ZERO new `has_type` edges (their type resolvers are
nil-stubs, double-guarded), and an independent regression pass confirmed no pre-existing
daemon/skill test broke.
