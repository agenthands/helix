# Requirements — Milestone v2.13 True intraprocedural DATA_FLOWS (in-body origins, variable-level)

## Red-team fold — `agent://RedTeamV213` (verdict: PROCEED-WITH-FIXES) — supersedes prior scoping where noted

An independent pre-mortem (`agent://RedTeamV213`, oracle) ran the REAL
`dataflow.AnalyzeFlow` against the pinned tree-sitter grammars and **refuted the
milestone's headline de-risking premise**. The depth cut is sound; the **all-11
breadth was NOT free** — the flow engine's tree-sitter kind unions only cover 6 of 11
languages, so 5 languages could not emit the in-body edge (and Ruby emitted *nothing*
since v2.9). All findings are folded below.

### Blocker (must be fixed, moved EARLIER)

- **B1 (BLOCKER) — the kind unions cover only 6/11 languages; the "unions are already
  cross-language" premise is false.** Empirically, `local := producer(); sink(local)`
  is **undetected** for:
  - **Python / Ruby** — `local = producer()` parses as node kind `assignment`, which
    is ∉ `assignKinds` (`summary.go:64-70`, has `assignment_expression`/`_statement`,
    not bare `assignment`).
  - **Ruby (worse)** — params parse as `method_parameters`, ∉ `paramListKinds`
    (`summary.go:55-59`) → `collectParams` empty → `AnalyzeFlow` bails
    (`summary.go:98-100`). **Ruby has produced ZERO DATA_FLOWS since v2.9** — not just
    in-body; even param→param.
  - **C / C++** — `int local = producer()` emits `declaration > init_declarator`, but
    `assignKinds` contains the typo-adjacent `init_declaration` (declaratION), which
    matches nothing in the grammar (`summary.go:68`).
  - **Kotlin** — `val local = producer()` is `property_declaration` with a *sibling*
    split: the `variable_declaration` child holds ONLY the LHS ident; the
    `call_expression` is a sibling. `splitAssignment` (`summary.go:216-222`) sees
    `NamedChildCount==1` → no bind. Separately, Kotlin call args are `value_arguments`,
    ∉ `argListKinds` (`summary.go:79-82`).
  - **Fix (folded into Phase 138, verified at the cheapest phase — see FLOW-04i):**
    extend the unions — `assignment` (Python/Ruby), `init_declarator` (C/C++),
    `method_parameters` (paramListKinds, Ruby), `value_arguments` (argListKinds,
    Kotlin) — and add a `property_declaration`-aware split for Kotlin. **Disclosure
    (FLOW-05e):** widening also retroactively gives Ruby/Python/Kotlin their v2.9
    param→param edges (they emit nothing today) — a latent-v2.9-bug-fix riding along;
    it is stated, not silent, and does NOT mutate existing Go/TS/Java/C#/Rust/PHP edges.

### Majors (folded)

- **M1 — "byte-identical snapshot"/"byte-identical v2.9 edges" is ill-defined.** EdgeID
  is a dense 1-based index over ALL edges in final append order
  (`semantic_wiring.go:1626-1628`); appending new edges shifts RESOLVES_TO /
  FILE_CHANGES_WITH EdgeIDs on any mixed repo → a whole-snapshot byte-identity claim is
  impossible. **Reframed (FLOW-05e):** the `Source=="def_use"` param→param edge **SET**
  (by content Src/Dst/SrcKind/DstKind/Source/Confidence/Weight/Reason) is unchanged;
  new passes append **strictly after** `dataFlowEdges` (`semantic_wiring.go:2534`) —
  a hard wiring constraint, with an explicit subset assertion (no golden guards a
  mis-wire today).
- **M2 — the producer→transform hop of a multi-hop walk needs a FUNCTION seed.** The
  in-body source is a call-return (no param to seed at); the first edge is
  `producer.function → transform.param0`. `trace_data_flow`'s documented contract is a
  PARAM seed. But `resolveSeed`/`handleTraceDataFlow` have **no kind gate** on the seed
  (`tools_trace_data_flow.go:91-164`, `seed_resolve.go:71+`) → a function seed is
  already ACCEPTED and, post-v2.13, returns non-empty. **Folded (FLOW-06c):** seed the
  real-binary multi-hop at the producer FUNCTION node (mechanically already works) and
  fix the stale docs (M3); the narrow function-seed slice is un-deferred for this proof
  only (full verb function-seed support stays a fast-follow).
- **M3 — two code-comment invariants + one test name go FALSE post-v2.13.**
  `accessors.go:287-293` and `semantic_wiring.go:2810-2813` assert "DATA_FLOWS edges
  are param-anchored / a function seed cannot reach them" — false once
  `function → parameter` in-body edges exist. `TestDataFlowReachability_FunctionSeedEmpty`
  (`dataflow_reachability_test.go:138-161`) encodes the now-false invariant. **Folded
  (FLOW-05h):** correct both comments and rename/repurpose the test in Phase 139.
- **M4 — return-bridge determinism landmine.** Emission ORDER is load-bearing (EdgeID
  is a slice-position stamp). **Folded (FLOW-05b):** the bridge pass MUST iterate the
  same sorted `withFlow` node list as `dataFlowEdges` (`semantic_similarity_edges.go:484`)
  and use `nodeToParams`/`nameToNode` for LOOKUP only — never range a Go map.
- **M5 (single highest-value change) — breadth risk is invisible until Phase 140.**
  138 and 139 are Go-only; the 5-language union gap surfaces only at the most expensive
  phase. **Folded (FLOW-04i):** a cheap all-11 summary-level unit test in Phase 138
  runs `AnalyzeFlow` on the in-body fixture across all 11 grammars — B1 surfaces at the
  cheapest phase; Phase 140 becomes confirmation, not discovery.

### Minors (folded)

- **m1 — drop the unbacked "total-edge budget" claim.** `dataFlowEdges` has no fan-out
  cap by design (`semantic_similarity_edges.go:466-468`); return-bridge volume is
  O(#params × #functions) — linear, bounded, not explosive. FLOW-05b relies on
  `(src,dst)` directed dedup, not a budget.
- **m2 — D-COMPOSE unwrap is a knife-edge; add guard fixtures.** The "RHS unwraps to a
  call" step MUST whitelist ONLY `expression_list` / `parenthesized_expression` and
  NEVER descend into `selector_expression` / `member_expression` / index / binary.
  `y := producer().field` must NOT bind `callReturn(producer)`; `a, b := f(), g()`
  must yield no origin. Folded into FLOW-04h as explicit RED guards.

## Overview

v2.9 (Phases 125–126) gave `DATA_FLOWS` a real producer: **case-1 param→param**
interprocedural flow. v2.10 (127–129) made it agent-consumable via the
`trace_data_flow` verb + BFS reachability. Both explicitly deferred **in-body
origins** and **variable-level precision** as "needs variable-level nodes."

v2.13 closes that gap with the **cheaper honest cut the co-driver locked**: model
in-body origins by **widening the flow-summary origin space** — *not* by extracting
locals as persistent graph nodes. A value that originates **mid-body** (the return
of an in-body call, e.g. `y := producer(); sink(y)`) is tracked and emitted as a
`DATA_FLOWS` edge that **anchors on existing symbol nodes** (the producer's
*function* node → the consumer's *parameter* node). This preserves every v2.9/v2.12
invariant: **zero new Go deps, no schema migration, binding = symbol-node identity.**

Breadth (co-driver): **all 11 languages proven end-to-end** — but this is NOT free
(red-team B1): the flow engine's tree-sitter kind unions must first be **extended and
per-language-verified**, because they currently cover only Go/TS/Java/C#/Rust/PHP.

### The gap, grounded at HEAD

| Fact | Evidence |
|---|---|
| Taint origins are param indices ONLY | `AnalyzeFlow` seeds `taint: map[var]map[paramIdx]bool` (`summary.go:102-110`); a mid-body call return is never an origin |
| `y := producer(); sink(y)` yields NO edge | `processAssignment` → `collectOrigins(rhs)` finds no tainted identifier in `producer()` (`producer` ∉ taint) → `y` untainted → `sink(y)` records nothing (`summary.go:181-196`) |
| `ParamFlow.Returns` is computed but NEVER emitted | `dataFlowEdges` consumes only `pf.CallArgs`, never `pf.Returns` (`semantic_similarity_edges.go:490-531`) — dead signal, reclaimable as the multi-hop bridge |
| The kind unions cover only 6/11 languages | red-team B1: empirical `AnalyzeFlow` on Python/Ruby/Kotlin/C/C++ → nil (`summary.go:54-83`) |
| Edges are param→param, `Source:"def_use"` | contract `semantic_similarity_edges.go:519-529` |
| `trace_data_flow` seed has NO kind gate | `resolveSeed` (`seed_resolve.go:71+`), `handleTraceDataFlow` (`tools_trace_data_flow.go:91-164`) — a function seed is already accepted (M2) |

## Locked decisions (co-driver + grounded at HEAD, red-team-folded)

- **D-DEPTH (co-driver):** in-body origins modeled **inside the flow summary**;
  **no persistent variable-level graph nodes, no schema migration.** Edges anchor on
  the existing producer **function** node and consumer **parameter** node.
- **D-BREADTH (co-driver):** **all 11 languages proven E2E** — via the folded union
  extension (B1) + the cheap all-11 summary test at Phase 138 (M5).
- **D-ANCHOR:** an in-body origin's source identity is the **producer function node**
  (its return value has no distinct node; the function node is the honest available
  identity — exactly what the v2.10 function-seed deferral anticipated).
- **D-BRIDGE:** the currently-dead `ParamFlow.Returns` flag is reclaimed to emit a
  **return-bridge** edge `param → own-function node` (Source `def_use_return`) iff the
  param's value reaches the function's return. Minimal zero-schema connector that makes
  in-body origins **composable for multi-hop reachability**
  (`producer(fn) → transform.param → transform(fn) → sink.param`). Confirmed necessary
  + correct by the red-team (BFS is node-ID adjacency, kind-agnostic, visited-set
  terminates).
- **D-CASE1:** case-1 discipline preserved — a mid-body origin is recorded only for
  **exact syntactic** data dependence. No over-approximation; ambiguity ⇒ no origin.
- **D-COMPOSE:** when RHS is a call `C(args)`, LHS origin = **`callReturn(C)`** (the
  outermost call's return) — NOT the inner args' origins (those flow *into* the call,
  captured by `processCall`). Unwrap whitelist is STRICTLY
  `{expression_list, parenthesized_expression}` (m2); selector/member/index/binary/
  multi-call RHS ⇒ no in-body origin.
- **D-HONESTY:** producer/consumer callee names resolve via the existing `nameToNode`
  + `nameCount==1` anti-mis-bind discipline; external/overloaded/unresolved callees ⇒
  **no fabricated edge** (endpoint 0 ⇒ gated out).
- **D-INVARIANTS:** zero new Go deps; no schema migration (`EdgeFact` unchanged;
  binding = node identity); deterministic (byte-identical snapshot for a fixed input);
  existing extractor goldens byte-unchanged; **the v2.9 `def_use` param→param edge SET
  unchanged for the 6 already-working languages** (M1 reframing).

### Edge contracts (the load-bearing shapes)

```
# NEW — in-body-origin edge (producer's return flows into a consumer arg)
SrcNodeID  = producer callee's FUNCTION node        (resolved via nameToNode, nameCount==1)
DstNodeID  = consumer callee's PARAMETER node j      (emit-order adjacency; D1b, as v2.9)
SrcKind    = "function"
DstKind    = "parameter"
EdgeKind   = "DATA_FLOWS"
Source     = "def_use_inbody"                        (NEW marker — distinct edge set)
Confidence = ~0.50                                   (function-node approximation of a return value)
Reason     = "return of {producer} -> {consumer} param{j}"

# NEW — return-bridge edge (a param's value reaches its own function's return)
SrcNodeID  = the parameter node
DstNodeID  = the enclosing FUNCTION node
SrcKind    = "parameter"
DstKind    = "function"
EdgeKind   = "DATA_FLOWS"
Source     = "def_use_return"                        (NEW marker — the multi-hop connector)
Confidence = ~0.55
Reason     = "param{i} -> return"

# UNCHANGED — v2.9 param->param edge (Source "def_use") stays set-identical for the
#   6 already-working langs; NEWLY appears for Ruby/Python/Kotlin as a folded v2.9 fix.
```

### FLOW-04: Origin-space widening + kind-union extension in the flow engine (Phase 138)

- [ ] **FLOW-04d (return-bridge, D-BRIDGE):** record, per parameter, whether it reaches

- [ ] **FLOW-04e:** carry the new summary fields on `SymbolFact.FlowSummary`, computed

- [ ] **FLOW-04g (anti-vacuity):** `f(){ y := producer(); return }` with `y` unused →

## Out of Scope (this milestone)

- **Persistent variable-level graph nodes** — locals do NOT get node identity/stable
  keys; edges anchor on function + param nodes only (D-DEPTH). Which *local* carried
  the value is deferred.
- **Field/heap flow** — struct-field / receiver-state propagation (field/index LHS
  still degrades to no-edge).
- **Source/sink/sanitizer taint modeling** — the "taint" security axis is a separate
  future milestone; v2.13 is pure data-dependence reachability.
- **Cross-package/cross-TU** callee resolution (intra-batch `nameCount==1`).
- **Full `trace_data_flow` function-seed support in the verb** — v2.13 only proves a
  function seed is *accepted and returns non-empty* (M2); promoting the verb's contract
  + docs for general function-seed use, and the `get-change-impact-graph`
  multi-projection rework (the v2.10 deferral), remain fast-follows.
- **A `semantic_edges` metadata column / queryable arg-param position** — deferred.
