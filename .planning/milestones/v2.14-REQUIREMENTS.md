# Requirements — Milestone v2.14 Codebase-Map Re-mapping (Go tree)

## Why this milestone

The v2.13 MILESTONE-AUDIT flagged, as its top-priority (HIGH) documentation-integrity
follow-on, that `.planning/codebase/` still describes the **removed pre-Go Python
`serena` tree** (`src/serena/`, `src/solidlsp/`, `SerenaAgent`, `*_tools.py`) as it
stood on **2026-04-07** — the map's sole `git` commit. That tree was deleted (v1.9
rename + pre-v1.12 legacy removal); Helix now ships as a **single Go binary**
(`cmd/helix`, `internal/**`). The map has NOT tracked the v1.9→v2.13 Go rewrite
(~13 milestones).

Measured drift (2026-07-01):

| File | Lines | Python-tree hits | Go hits | Verdict |
|---|---|---|---|---|
| STRUCTURE.md | 362 | 131 | 10 (v2.13 addendum only) | stale below addendum |
| ARCHITECTURE.md | 260 | 70 | 0 | fully stale |
| CONCERNS.md | 210 | 52 | 0 | fully stale |
| CONVENTIONS.md | 225 | 26 | 0 | fully stale |
| INTEGRATIONS.md | 158 | 36 | 0 | fully stale |
| STACK.md | 149 | 19 | 0 | fully stale |
| TESTING.md | 484 | 89 | 1 | fully stale |

A codebase map is a claim the team acts on. A confident map that is wrong removes
caution exactly where it was needed — the map currently describes a codebase that
does not exist. This milestone makes it honest.

This is an **assess-and-document** milestone (per `docs/05-team-workflow.md` milestone
shapes). The re-mapped files are **phase deliverables**, verified by a source-grounding
gate — not flat files authored off to the side.

## Milestone intent (locked)

Re-map all 7 `.planning/codebase/*.md` files to the **current Go tree** at HEAD:
every architectural, structural, stack, integration, convention, concern, and testing
claim is grounded in real Go source at a citable path, the Python-serena-tree residue
is gone, and the staleness banners are removed because the staleness is gone.

**Ground truth (current tree, measured):** 85,472 non-test LOC across 24 `internal/`
packages + 16 `cmd/` binaries + `api/proto` + `protocol/` + 291-file `bench/` +
`tools/dspy-tune/`. Largest subsystem: **`internal/semantic/` at 30,814 LOC** (the
semantic graph index — barely present in CLAUDE.md's architecture section, so it MUST
be surveyed fresh, not parroted). 51 frozen `helix` verbs (`internal/cli/verbs_gen.go`).
590 `*_test.go` files. 0 TODO/FIXME/HACK in `internal`+`cmd`. Go 1.25.1, CGO=1.

## Requirements

### Codebase Map (MAP)

- [ ] **MAP-01**: `STRUCTURE.md` reflects the current Go directory layout — `cmd/*`
  (17 binaries), `internal/*` (24 packages with per-package purpose), `api/proto/`,
  `protocol/{gen,patch}/`, `bench/`, `tools/dspy-tune/` — with the 4-layer architecture
  mapping and LOC/scale context. Zero Python-tree layout.
- [ ] **MAP-02**: `ARCHITECTURE.md` documents the Go architecture — the 4 layers
  (MCP runtime, kernel, skills/multi-lang, profiles/setup), the daemon bootstrap +
  middleware stack (LIFO order), the semantic index subsystem, key abstractions
  (Skill/ToolProvider, kernel tools, worker pool), entry points (`cmd/helix/main.go`
  + cobra), error handling (`internal/errors`), and cross-cutting concerns (obs,
  guardrails, degrade). Grounded in real source.
- [ ] **MAP-03**: `STACK.md` documents the real stack — Go 1.25.1, CGO=1 split-runner
  build, direct deps (MCP go-sdk, cobra, koanf v2, tree-sitter + 23 grammars, modernc
  sqlite, duckdb, chromem-go, prometheus/otel, sigstore, arrow, anthropic/openai SDKs
  for dev-time bench/tools), no runtime Python. Sourced from `go.mod`.
- [ ] **MAP-04**: `INTEGRATIONS.md` documents external integrations — LSP servers
  (three-tier installer, 52-lang registry), tree-sitter grammars, gRPC IPC, sigstore
  keyless attestation, prometheus/otel telemetry, container engines (Podman/Docker
  auto-detect for bench), LLM provider SDKs (dev-time only), MCP client setup targets.
- [ ] **MAP-05**: `CONVENTIONS.md` documents Go conventions — package/file/symbol
  naming, gofmt + go vet + custom vet gates (`cmd/vet-*`), import organization,
  typed-error handling (`internal/errors`), skill `init()` registration pattern,
  table-driven tests, generated-code discipline (`verbs_gen.go`, `protocol/gen`).
- [ ] **MAP-06**: `CONCERNS.md` documents real tech debt / fragile areas / security
  posture grounded in the current tree — architectural invariants enforced by vet
  gates, the CGO=1 constraint, the retained-lineage naming artifacts (`SerenaMCPServer`,
  proto `serena/v1`), documented deferred items, and genuine fragile seams. No invented
  debt; cite source or omit.
- [ ] **MAP-07**: `TESTING.md` documents the Go test architecture — `go test`, testify,
  `testdata/` fixture convention, the vet-gate suite, real-binary E2E tests, the
  `bench/` milestone-bench harness + CI workflows (`.github/workflows/`), coverage posture.
- [ ] **MAP-08**: **Verification + integrity** — every claim in MAP-01..07 is
  source-grounded to a citable path at HEAD (spot-checked); all staleness banners
  removed; zero `serena`/`solidlsp`/`SerenaAgent`/`*_tools.py`/Python-runtime residue
  remains (grep-clean, allowing only the deliberately-retained lineage artifacts named
  in MAP-06); each file's `Analysis Date` updated to the re-map date.

## Success criteria

1. All 7 `.planning/codebase/*.md` files describe the current Go tree; grep for
   Python-serena residue returns only the explicitly-retained lineage artifacts.
2. Every structural/architectural claim is grounded in a real Go path at HEAD
   (verifier spot-checks a sample; no fabricated paths).
3. `internal/semantic/` (the 30.8k-LOC largest subsystem) is documented as a
   first-class layer, not omitted.
4. Staleness banners removed from STRUCTURE.md and any others; `Analysis Date`
   refreshed on all 7.
5. The stale `ROADMAP.md` `## Phases` detail section (still describing v2.5-era
   phases 115-126) is regenerated so `anvil-cc state json` / `roadmap analyze` stop
   manufacturing phantom incomplete phases (planning-integrity fix bundled in).
6. No source code changed (documentation-only milestone); `go build`/`go vet`/`go test`
   remain green (unchanged — nothing touched them).

## Out of scope

- Any source-code change (this is documentation-only; the map describes, it does not fix).
- The `docs/` contributor-facing docs (edge-types.md, type-resolution.md, runbooks) —
  those are current (v2.13 refresh); not re-touched.
- New `.planning/codebase/` files beyond the existing 7 (no schema expansion).
- Deep security audit (the tree carries no runtime attack surface change; CONCERNS.md
  documents posture, it does not run an audit — that is the security-engineer's separate span).
