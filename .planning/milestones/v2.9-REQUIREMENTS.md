# Requirements — Milestone v2.9 Interprocedural DATA_FLOWS (param-flow reachability substrate)

## Overview

**Goal:** Give the `DATA_FLOWS` edge kind a real producer. v2.8 (Workstream A) shipped
SEMANTICALLY_RELATED and renamed the mis-named structural edge to `STRUCTURAL_TWIN`,
reserving `DATA_FLOWS`/`data_flows` as **producerless** (declared + validatable, no
emission). v2.9 builds the producer: **arg-to-param interprocedural flow** — a value
entering a function via parameter *i* that reaches the argument position of a call to
an in-repo callee, bound to that callee's parameter *j*.

**Honest framing (red-team fold):** this is a **syntactic param→param pass-through
reachability substrate** — the classical function-summary taint-composition primitive.
It precisely answers *"if a value enters F's param i, can it reach G's param j?"* by
walking edges. It is **NOT taint analysis**: it tracks no in-body origins (no
`src()`-style sources — that needs local-variable nodes, deferred), no field/heap
flow, no external source/sink modeling, no sanitization. Fixtures use **in-repo**
src/sink endpoints (or honestly mark external endpoints as unanchored).

**Why case-1-only (red-team fold, Q1+B2):** param→param forwarding is *exact* syntactic
data dependence — zero over-approximation. The summary over-approximation only enters
when modeling in-body origins, which require variable-level nodes (deferred). Shipping
case-1-only is the cheaper honest cut and a genuine signal, not theater.

### Edge contract (the load-bearing shape)

```
SrcNodeID  = caller's parameter node i     (a SYMBOL node — never a reference node)
DstNodeID  = callee's parameter node j     (resolved via emit-order adjacency; D1b)
EdgeKind   = "DATA_FLOWS"
Source     = "def_use"
Confidence = ~0.55                          (syntactic tree-sitter + in-repo callee)
Reason     = "arg{pos} -> param{j name}"    (human-readable; surfaces in explain-symbol-deep)
```

## FLOW — DATA_FLOWS producer (2 phases: 125 engine + 126 emission/reachability)

### FLOW-01: Intraprocedural flow-summary engine (Phase 125)

- [ ] **FLOW-01a:** New `internal/semantic/dataflow/` — leaf package, imports limited to stdlib + tree-sitter (mirrors `minhash/`/`relatedidx/`/`classifier/` boundary; NO `internal/*` beyond shared low-level helpers).
- [ ] **FLOW-01b:** `AnalyzeFlow(bodyNode, source) FlowSummary` — tree-sitter body walk producing, **case-1 only**, per parameter: `{reaches-return, reaches-call(calleeName, argPos)}` via assignment-chain + return + call-argument transitive closure. Derives the function's own param names/positions from the function-definition's parameter-list child node (owner known at extraction — independent of symbol emission order).
- [ ] **FLOW-01c:** New `SymbolFact.FlowSummary` field (`fact.go`); computed in the `FingerprintBody` path (or a sibling at the same extraction point) → all 11 providers inherit with **no per-provider edit** (mirrors `MinHash`/`Profile`/`ContextVec`).
- [ ] **FLOW-01d:** **Determinism is structural, not merely seeded** — no Go-map-iteration in the analysis path; ordering pinned. Proven by determinism, not same-input re-run.
- [ ] **FLOW-01e:** **Anti-vacuity:** a parameter that is not forwarded yields an empty summary for that param (`f(x){}` → no flows).
- [ ] **FLOW-01f:** **Param-index/emit-order pinning (red-team minor):** the `FlowSummary` arg-position MUST agree with the param-node emit order used by FLOW-02b to resolve callee params. Pin this contract in Phase 125 so Phase 126's lookup is consistent.
- [ ] **FLOW-01g:** Fixtures — `f(x){return x}` → x reaches return; `f(x){sink(x)}` → x reaches call `sink` arg0; `f(x){y:=x; g(y)}` → x reaches call `g` arg0 (transitive); `f(x){}` → none. Pure unit tests; no network.

### FLOW-02: Arg→param DATA_FLOWS emission (Phase 126)

- [ ] **FLOW-02a:** Batch pass `dataFlowEdges` in `semantic_similarity_edges.go`, mirroring the sibling passes. For each function's `FlowSummary`, for each `reaches-call(name, argPos)`, resolve `name` → callee node, resolve callee's `param[argPos]` node, emit the edge per the contract. Wired into `factsFromExtracted` batch emission (appended alongside the sibling passes at `semantic_wiring.go:2399-2401`).
- [ ] **FLOW-02b:** **Callee-param resolution via emit-order adjacency** (NOT DEFINES): during the per-file loop, derive `funcNode → ordered [paramNode]` from the consecutive `KindParameter` run after each function/method in `single.Symbols`; collect into a batch-wide `calleeNode→[paramNodes]` index. **Plan-time gate:** verify emit-order holds for all 11 providers; any provider where it doesn't degrades gracefully (no edge) rather than mis-binds.
- [ ] **FLOW-02c:** **Anti-mis-bind (D5):** when a bare callee name maps to >1 candidate node, emit **no edge** (DstNodeID=0). Fixture: two same-named callees → neither call mis-binds.
- [ ] **FLOW-02d:** **Non-positional handling (D6):** receiver offset (explicit args start at param[1]); variadic fan-in (trailing args → the one variadic param node); kwargs by name when the call uses keywords; **ambiguity ⇒ no edge**. Per-language fixture (Go receiver+variadic, Python kwargs).
- [ ] **FLOW-02e:** **Bounded + directed (D7/D8):** dedup on `(SrcNodeID, DstNodeID)`; bound by a total-edge budget (NOT `minhash.MaxEdgesPerNode`). Deterministic ordering (ascending NodeID processing).
- [ ] **FLOW-02f:** **Honesty:** external/unresolved callees → no fabricated edge (DstNodeID stays 0).

### FLOW-03: Read surface + guards + reachability (Phase 126, folded from 127)

- [ ] **FLOW-03a:** Confirm `explain-symbol-deep` surfaces `DATA_FLOWS` (`MapInternalKind` already maps it) + a test asserting the edge appears in `edges_outgoing`/`edges_incoming`.
- [ ] **FLOW-03b:** **Distinctness guard (anti-vacuity):** on a shared fixture, a `DATA_FLOWS` edge exists where no `STRUCTURAL_TWIN`/`SIMILAR_TO` similarity does (flow ≠ structural-shape ≠ token-clone). Mutation-confirmed.
- [ ] **FLOW-03c:** **Forwarding guard (anti-vacuity):** tainted-arg-passed fixture emits the edge; **non-forwarded param does NOT** (revert-and-fail RED).
- [ ] **FLOW-03d:** **Multi-hop reachability proof (folded Phase 127, M5):** a BFS/DFS over emitted `DATA_FLOWS` edges (each spans one call hop; consecutive hops share the callee-param node) answers source→sink reachability. Fixture: in-repo `src → f(x) → g(x) → sink` reachable end-to-end; **break a hop → reachability breaks** (revert-and-fail). No propagation engine, no CALLS threading.
- [ ] **FLOW-03e (optional):** A small, tested `ReachableFrom(seed, maxHops)` store/skill helper the deferred `trace-data-flow` verb will consume. Ship only if it falls out cheaply at plan time; otherwise the FLOW-03d proof walks edges directly in-test.

## Success Criteria

1. `DATA_FLOWS` edges are **emitted** on a real Go fixture (the kind goes from 0 producers → ≥1), with the case-1-only param→param semantics.
2. The callee-param resolution is **emit-order-adjacency-based, verified across all 11 providers** (not DEFINES).
3. Distinctness + forwarding guards are green AND mutation-confirmed RED when broken.
4. Multi-hop reachability proven (FLOW-03d), with the broken-hop revert-and-fail guard.
5. **Zero new Go dependencies** (`go.mod`/`go.sum` byte-unchanged).
6. **No schema migration** (`EdgeFact` unchanged; binding = node identity).
7. Generated-file `--check` gates pass (DATA_FLOWS already in the surface enum — no enum churn expected).
8. `go build ./...` clean; `go test ./internal/semantic/... ./internal/daemon/... ./internal/skill/semantic/...` green; `make vet` clean.
