<objective>
Generate all LSP 3.17 protocol types from the official metamodel JSON and build the JSON-RPC codec for LS communication.

Purpose: The LSP codegen is the foundation for every LS interaction in Phase 2. Without generated types, all symbol retrieval, editing, and diagnostic tools would need hand-written LSP structs (300+ types with complex unions). The JSON-RPC codec enables Content-Length framed communication with LS child processes.

Output: cmd/lspgen/ generator binary, protocol/gen/ generated Go types, protocol/patch/ quirk fixups, internal/kernel/jsonrpc/ codec package.
</objective>

  <action>
    **Per D-08:** Build a full LSP 3.17 metamodel code generator.

    **Step 1 — Download metaModel.json:**
    Download the official LSP 3.17 metamodel from https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/metaModel/metaModel.json and save to `protocol/metaModel.json`. Pin this exact version.

    **Step 2 — Create cmd/lspgen/ generator binary (per D-09):**

    `cmd/lspgen/main.go`:
    - Parse metaModel.json into Go structs matching its schema: `metaData`, `requests` (array), `notifications` (array), `structures` (array), `enumerations` (array), `typeAliases` (array)
    - Each type reference has a `kind` field: `base`, `reference`, `array`, `map`, `literal`, `stringLiteral`, `integerLiteral`, `booleanLiteral`, `tuple`, `and`, `or`
    - For `or` kind: generate Or_X_Y wrapper types with custom JSON marshal/unmarshal + typed accessors (AsTextEdit(), SetTextEdit(), etc.) per D-10
    - For `and` kind: generate embedded struct composition
    - For `literal` kind: generate anonymous struct types
    - For `reference` kind: resolve to named Go type
    - For `base` kind: map to Go primitives (string, int32, uint32, bool, float64, interface{})
    - Generate four output files into protocol/gen/:
      1. `tsprotocol.go` — All struct types, const enumerations, type aliases
      2. `tsclient.go` — Client-side method stubs (request sender signatures)
      3. `tsserver.go` — Server-side dispatch table (for handling notifications like publishDiagnostics)
      4. `tsjson.go` — Custom MarshalJSON/UnmarshalJSON for all union types (Or_X_Y)

    `cmd/lspgen/tables.go`:
    - Type name fixup table: maps metamodel names to Go-friendly names where needed
    - Field name overrides for Go naming conventions (e.g., `uri` → `URI`, `id` → `ID`)
    - Apply patch layer entries from protocol/patch/ (per D-11)

    `cmd/lspgen/typenames.go`:
    - Naming heuristics for unnamed/anonymous types (literal types get names based on parent + field)
    - Deduplication of identical literal types

    `cmd/lspgen/output.go`:
    - Format generated code with go/format
    - Write to protocol/gen/ directory
    - Add generation header comment with metamodel version

    **Step 3 — Create protocol/generate.go (per D-09):**
    ```go
    package protocol
    //go:generate go run ../cmd/lspgen
    ```

    **Step 4 — Create protocol/patch/ (per D-11):**
    `protocol/patch/rename_params.go` — Fix RenameParams mismatch (metamodel has `newName` as optional but it's actually required).
    `protocol/patch/compatibility.go` — Shims for any types where metamodel doesn't match real-world LS behavior. Start minimal, extend as needed.

    **Step 5 — Run the generator:**
    Run `go generate ./protocol/...` and verify the output compiles with `go build ./protocol/...`.

    **Per D-10 (union representation):** Use gopls-style pragmatic hybrid:
    - Default: Named tagged wrapper `Or_X_Y` with `Value interface{}` field, `AsX() (X, bool)` and `SetX(X)` accessors, custom JSON marshal that tries each type
    - High-frequency unions (DocumentChange, TextDocumentEdit | CreateFile | RenameFile | DeleteFile): Promote to explicit one-of struct with named fields

    **Important:** The generator must handle ~200 structures, ~40 enums, ~80 requests, ~30 notifications. This is a substantial code generator. Follow gopls's pattern of iterating over the metamodel arrays and emitting Go code via text/template or fmt.Fprintf.

  <action>
    Build a custom thin JSON-RPC 2.0 implementation (~300 lines total) for LS child process communication. Custom rather than go.lsp.dev/jsonrpc2 because that library is unmaintained (2022) and doesn't handle multiplexed daemon connections.

    `internal/kernel/jsonrpc/message.go`:
    - Define `Request` struct: `ID interface{}` (string or int), `Method string`, `Params json.RawMessage`
    - Define `Response` struct: `ID interface{}`, `Result json.RawMessage`, `Error *ResponseError`
    - Define `ResponseError` struct: `Code int`, `Message string`, `Data json.RawMessage`
    - Define `Notification` struct: `Method string`, `Params json.RawMessage` (no ID)
    - JSON-RPC 2.0: `"jsonrpc": "2.0"` field on all messages
    - Implement MarshalJSON/UnmarshalJSON for each type

    `internal/kernel/jsonrpc/codec.go`:
    - `ReadMessage(r *bufio.Reader) (json.RawMessage, error)` — Read Content-Length header, parse integer, read exact body bytes
    - `WriteMessage(w io.Writer, msg json.RawMessage) error` — Write `Content-Length: N\r\n\r\n` header then body
    - Handle edge cases: multiple headers before empty line, ignore Content-Type header, partial reads via io.ReadFull
    - Use `\r\n` line endings per LSP spec

    `internal/kernel/jsonrpc/conn.go`:
    - `Conn` struct wrapping `io.ReadWriteCloser` with `*bufio.Reader` for reading
    - `Send(ctx context.Context, method string, params interface{}) (id interface{}, err error)` — Assigns unique ID (session-prefixed per Pitfall 4 from research), marshals Request, writes via codec
    - `Call(ctx context.Context, method string, params interface{}, result interface{}) error` — Send + wait for response by ID
    - `Notify(ctx context.Context, method string, params interface{}) error` — Send notification (no ID, no response)
    - `Listen(ctx context.Context)` — Read loop dispatching responses to pending Call waiters and notifications to a handler callback
    - Internal pending map: `map[interface{}]chan *Response` for routing responses to callers
    - ID generation: Use atomic counter with session prefix string to avoid collisions (per research Pitfall 4)
    - Context cancellation: Close connection on context cancel

    `internal/kernel/jsonrpc/codec_test.go`:
    - Test ReadMessage with valid Content-Length framed message
    - Test ReadMessage with multiple headers (Content-Type + Content-Length)
    - Test WriteMessage roundtrip
    - Test Request/Response/Notification JSON marshaling
    - Test Conn.Call with mock ReadWriteCloser (write request, read response)
    - Test Conn.Notify sends notification without waiting
    - Test ID collision avoidance with different session prefixes
  </action>
