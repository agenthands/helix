  <action>
    Create `internal/kernel/fileops/` package with pure Go implementations. All operations take absolute paths and validate they're within an active workspace root (security boundary).

    **`read.go` (FIL-01):**
    - `ReadFile(path string) (string, error)` — Read entire file, return as string. Error if file doesn't exist or exceeds 10MB size limit.
    - `ReadFileRange(path string, startLine, endLine int) (string, error)` — Read line range (1-indexed, inclusive). If endLine is 0 or beyond EOF, read to end. Return lines with line numbers prefixed.
    - Path must be within workspace root.

    **`write.go` (FIL-02):**
    - `CreateFile(path string, content string) error` — Create file with content. Create parent directories if needed (os.MkdirAll). Error if file already exists (use separate OverwriteFile).
    - `OverwriteFile(path string, content string) error` — Atomic write: write to temp file in same dir, then os.Rename. This prevents partial writes on crash.
    - Path must be within workspace root.

    **`list.go` (FIL-03):**
    - `ListDirectory(path string) ([]DirEntry, error)` — Return list of entries with name, isDir, size, modTime. Non-recursive. Sort alphabetically with dirs first.
    - `type DirEntry struct { Name string; IsDir bool; Size int64; ModTime time.Time }`

    **`find.go` (FIL-04):**
    - `FindFiles(root string, pattern string) ([]string, error)` — Find files matching glob pattern relative to root. Use `filepath.WalkDir` with `filepath.Match` per path component, or `doublestar` library if `**` patterns needed. Return paths relative to root. Limit to 1000 results. Skip `.git`, `node_modules`, `__pycache__`, `.serena` dirs.

    **`search.go` (FIL-05):**
    - `SearchPattern(root string, pattern string, opts SearchOpts) ([]SearchMatch, error)` — Search files for regex pattern. Walk directory tree, read text files, apply compiled regex. Return file path + line number + matching line + context lines (before/after per opts).
    - `type SearchOpts struct { MaxResults int; ContextLines int; IncludeGlob string; ExcludeGlob string }`
    - `type SearchMatch struct { Path string; Line int; Text string; ContextBefore []string; ContextAfter []string }`
    - Skip binary files (check first 512 bytes for null bytes). Skip .git, node_modules. Limit to opts.MaxResults (default 100).

    **`replace.go` (FIL-06):**
    - `ReplaceInFile(path string, pattern string, replacement string, isRegex bool) (int, error)` — Replace all matches in a single file. Return count of replacements. Use atomic write pattern. If isRegex is false, use strings.ReplaceAll. If true, compile regex and use ReplaceAll.
    - Path must be within workspace root.

    **`fileops_test.go`:**
    - Use `t.TempDir()` for all tests (auto-cleanup).
    - Test ReadFile with existing and non-existing files.
    - Test ReadFileRange with valid range, out-of-bounds, zero endLine.
    - Test CreateFile creates dirs and errors on existing file.
    - Test OverwriteFile atomic write.
    - Test ListDirectory ordering (dirs first, alphabetical).
    - Test FindFiles with glob patterns including nested dirs.
    - Test SearchPattern with regex, context lines, binary file skipping.
    - Test ReplaceInFile with both regex and literal modes.

    **Security: All path operations MUST validate the path is within the workspace root using filepath.Rel and rejecting paths that start with ".." or are absolute paths outside root.**

    Add a shared `ValidatePath(root, path string) (string, error)` function that resolves symlinks and checks containment.

    Define Args structs with json + jsonschema tags for each tool (following Phase 1 pattern from internal/mcp/server.go):

    ```go
    type ReadFileArgs struct {
        Path      string `json:"path" jsonschema:"File path to read"`
        StartLine int    `json:"start_line,omitempty" jsonschema:"Start line (1-indexed, optional)"`
        EndLine   int    `json:"end_line,omitempty" jsonschema:"End line (1-indexed, inclusive, optional)"`
    }
    ```

    Register 6 tools:
    1. `read_file` — Calls ReadFile or ReadFileRange depending on whether line params provided
    2. `create_file` — Calls CreateFile
    3. `list_directory` — Calls ListDirectory, formats as text table
    4. `find_files` — Calls FindFiles, returns newline-separated paths
    5. `search_in_files` — Calls SearchPattern, formats matches with file:line:text
    6. `replace_in_file` — Calls ReplaceInFile, returns replacement count

    Each tool handler:
    - Resolves workspace root from context (the active workspace)
    - Validates path is within workspace
    - Calls the underlying function
    - Returns `*mcpsdk.CallToolResult` with text content on success
    - Returns structured MCP error on failure (using internal/mcp/errors.go patterns)

    Create a `RegisterTools(registry *mcp.ToolRegistry)` function that registers all 6 tools at once. This function will be called by the daemon during startup.

    **Important:** Follow the exact same tool registration pattern established in Phase 1 (internal/mcp/server.go). Use mcpsdk.AddTool generic for type-safe argument parsing.
