    **`process.go` — ProcessHandle for safe child process I/O (per research Pattern 1):**

    ```go
    type ProcessHandle struct {
        cmd       *exec.Cmd
        stdin     io.WriteCloser
        stdout    io.ReadCloser
        stderr    io.ReadCloser
        conn      *jsonrpc.Conn     // JSON-RPC over stdin/stdout
        done      chan struct{}      // closed when process exits
        exitErr   error
        mu        sync.Mutex
    }
    ```

    - `NewProcessHandle(command string, args []string, workDir string, env []string) *ProcessHandle`
    - `Start(ctx context.Context, sessionPrefix string) error`:
      1. Configure cmd with StdinPipe, StdoutPipe, StderrPipe
      2. Start process
      3. Create jsonrpc.Conn wrapping stdin/stdout with sessionPrefix
      4. Launch stderr drain goroutine (log at debug level, capture last 10 lines for crash reports)
      5. Launch conn.Listen goroutine
      6. Launch reaper goroutine: cmd.Wait(), store exitErr, close done channel
      7. On ctx cancel: SIGTERM -> 3s grace -> SIGKILL escalation
    - `Conn() *jsonrpc.Conn` — Returns JSON-RPC connection (only valid after Start)
    - `Wait() error` — Blocks until process exits
    - `Stop(ctx context.Context) error` — Graceful shutdown: send LSP shutdown request, wait 3s, send exit notification, wait 2s, SIGTERM, SIGKILL
    - `Done() <-chan struct{}` — Returns done channel

    **Critical per Pitfall 1:** Never do pipe I/O from the Wait/reaper goroutine. Separate goroutines for reading, writing, and waiting.

    **`worker.go` — LS worker with 5-state machine (per research Pattern 2):**

    ```go
    type WorkerState int
    const (
        WorkerStarting     WorkerState = iota
        WorkerInitializing
        WorkerReady
        WorkerShuttingDown
        WorkerStopped
    )

    type Worker struct {
        id          string
        language    string
        workDir     string
        process     *ProcessHandle
        state       atomic.Int32
        metrics     WorkerMetrics
        mu          sync.RWMutex
        pendingOpen []pendingDidOpen  // buffered during Initializing
        capabilities ServerCapabilities
    }
    ```

    - `NewWorker(id, language, workDir string, lsCommand string, lsArgs []string) *Worker`
    - `Start(ctx context.Context) error`:
      1. Set state to Starting
      2. Start ProcessHandle
      3. Set state to Initializing
      4. Send `initialize` request with InitializeParams (rootUri=workDir, capabilities=client caps)
      5. Store server capabilities from InitializeResult
      6. Send `initialized` notification
      7. Replay any buffered didOpen notifications
      8. Set state to Ready
    - `Request(ctx context.Context, method string, params interface{}, result interface{}) error` — Gate on Ready state. Forward via ProcessHandle.Conn().Call(). Update metrics.OnReuse().
    - `Notify(ctx context.Context, method string, params interface{}) error` — If Initializing and method is "textDocument/didOpen", buffer it. If Ready, forward via Conn().Notify().
    - `Stop(ctx context.Context) error` — Set ShuttingDown, send shutdown, send exit, stop process, set Stopped.
    - `State() WorkerState`, `Metrics() WorkerMetrics`, `Language() string`, `Capabilities() ServerCapabilities`

    **Per Pitfall 2:** Buffer didOpen notifications during Initializing. Replay on Ready. Never send requests to non-Ready workers.

    **`pool.go` — LS worker pool manager (per D-01):**

    ```go
    type Pool struct {
        mu          sync.RWMutex
        workers     map[string]*Worker     // keyed by worker ID
        leases      map[string]*WorkerLease // keyed by session ID
        circuits    map[string]*CircuitBreaker // keyed by language
        pressure    MemoryPressure
        config      PoolConfig
        logger      *slog.Logger
        ticker      *time.Ticker           // TTL check interval
        done        chan struct{}
    }
    ```

    - `NewPool(cfg PoolConfig, pressure MemoryPressure, logger *slog.Logger) *Pool`
    - `Run(ctx context.Context) error` — Start background goroutine for TTL checks and pressure eviction. Returns when ctx cancelled.
    - `AcquireLease(ctx context.Context, sessionID string, wsKey WorkspaceKey, dirty bool) (*WorkerLease, error)`:
      - Per D-02: If not dirty, look for existing warm worker for this language+workDir. If found, create shared lease.
      - Per D-02: If dirty, spawn new dedicated worker for this session.
      - If no warm worker exists, spawn new worker (check circuit breaker first).
      - Return WorkerLease binding session to worker.
    - `ReleaseLease(sessionID string)` — Release lease. If worker has no remaining leases, start idle TTL countdown.
    - `PromoteToDirty(sessionID string) (*WorkerLease, error)` — Per D-08: Session had clean shared lease, now needs dirty dedicated worker. Spawn new worker, transfer session's open documents, release old shared lease.
    - TTL check loop (per D-03, D-04):
      - Every 30s, iterate workers.
      - For each idle worker (no active leases): compute TTL from WorkerMetrics.TTL(baseTTL, ceiling).
      - If time since last use > computed TTL: stop worker, remove from pool.
      - Per D-07: TTL=0 means no idle timeout but pressure eviction still active.
    - Pressure eviction loop (per D-05):
      - Check MemoryPressure.Level() periodically (every 10s).
      - If pressure is High: evict workers in order: (1) RSS > hard cap, (2) unhealthy/stuck, (3) LRU with score==0, (4) lowest score/highest RSS ratio, (5) oldest idle.
    - `workerForKey(wsKey WorkspaceKey) *Worker` — Find warm worker matching key. Returns nil if none.
