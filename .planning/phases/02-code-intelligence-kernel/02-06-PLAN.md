Implement all symbol editing tools with tree-sitter body surgery, LSP-first insert, rename, safe delete, and post-edit diagnostic verification.

Purpose: Symbol editing is what differentiates Serena from basic file tools. Agents can make precise, semantic edits (replace just a function body, not the whole file) with safety checks (reference counting before delete) and verification (diagnostics after edit). This plan brings tree-sitter integration for precise body extraction.

    **`treesitter.go` — Tree-sitter body extraction engine (per D-14):**

    ```go
    type BodyExtractor struct {
        languages map[string]*tree_sitter.Language
    }
    ```

    - `NewBodyExtractor() *BodyExtractor` — Initialize with Go, Python, TypeScript, Rust languages.
    - `ExtractBody(source []byte, lang string, symbolName string, symbolRange Range) (startByte, endByte uint32, err error)` — Per D-14 (tree-sitter-first for replace-body):
      1. Parse source with language-specific parser
      2. Walk AST to find declaration node containing symbolRange
      3. Match by: node type is a declaration type AND node range encompasses symbol range AND name child matches symbolName
      4. Extract `body` child node (language-specific field name — see Per-Language Body Field Mapping)
      5. Return body start/end byte offsets
    - `FindDeclaration(root *tree_sitter.Node, source []byte, symbolName string, symbolRange Range) *tree_sitter.Node` — Recursive walk finding matching declaration node.
    - Language registration: map language string to tree_sitter.Language and to valid declaration node types per Pitfall 3.

    **Per-language query files (embedded via `//go:embed`):**

    `queries/go.scm`: Declaration types: `function_declaration`, `method_declaration`. Body field: `body` (block).
    `queries/python.scm`: Declaration types: `function_definition`, `class_definition`. Body field: `body` (block).
    `queries/typescript.scm`: Declaration types: `function_declaration`, `method_definition`, `arrow_function`. Body field: `body` (statement_block or expression).
    `queries/rust.scm`: Declaration types: `function_item`, `impl_item`. Body field: `body` (block).

    Note: These .scm files define the node types and field names. They are loaded by the BodyExtractor to know which AST node types to look for per language.

    **`replace.go` (EDT-01) — Replace symbol body (per D-14, tree-sitter-first):**

    - `ReplaceBody(ctx context.Context, lease *lspool.WorkerLease, extractor *BodyExtractor, uri string, symbolName string, newBody string) error`:
      1. Read file content
      2. Get DocumentSymbol via LSP to find symbol range (LSP-assisted discovery)
      3. Extract body range via tree-sitter BodyExtractor (tree-sitter-first for body surgery)
      4. Replace bytes from body startByte to endByte with newBody
      5. Write file with atomic write
      6. Send textDocument/didChange notification to LS worker (triggers re-analysis)
    - Per D-15: If tree-sitter extraction fails (no grammar for language), fall back to full symbol range replacement with warning.

    **`insert.go` (EDT-02, EDT-03) — Insert before/after symbol (per D-13, LSP-first):**

    - `InsertBefore(ctx context.Context, lease *lspool.WorkerLease, uri string, symbolName string, content string) error`:
      1. Get DocumentSymbol via LSP
      2. Find symbol by name in outline
      3. Insert content at symbol's range start position (per D-13: LSP range boundaries sufficient)
      4. Write file, send didChange
    - `InsertAfter(ctx context.Context, lease *lspool.WorkerLease, uri string, symbolName string, content string) error`:
      1. Same as above but insert at symbol's range end position
      2. Add newline separator between symbol and inserted content

    **`rename.go` (EDT-04) — LSP rename forwarding:**

    - `RenameSymbol(ctx context.Context, lease *lspool.WorkerLease, uri string, line, col int, newName string) (*RenameResult, error)`:
      1. Send textDocument/rename with RenameParams
      2. Get WorkspaceEdit response
      3. Apply all TextEdits across all files in the workspace edit
      4. Return summary of files changed and edits applied

    ```go
    type RenameResult struct {
        FilesChanged int
        EditsApplied int
        Files        []string
    }
    ```

    **`delete.go` (EDT-05) — Safe delete with reference check:**

    - `SafeDelete(ctx context.Context, lease *lspool.WorkerLease, uri string, symbolName string, force bool) (*DeleteResult, error)`:
      1. Find symbol via documentSymbol
      2. Unless force=true: call FindReferences (from symbols/retrieval.go). If refs > 0 (excluding the declaration), return error with reference locations.
      3. If safe (zero external refs) or force: remove symbol from file (delete from range start to range end)
      4. Write file, send didChange

    ```go
    type DeleteResult struct {
        Deleted    bool
        References int    // number of remaining references (if not deleted)
        RefLocations []SymbolLocation // where the refs are
    }
    ```

    **`verify.go` (EDT-06) — Post-edit diagnostic verification:**

    - `VerifyEdit(ctx context.Context, diagStore *diag.DiagnosticStore, uri string) (*VerifyResult, error)`:
      1. Clear existing diagnostics for URI
      2. Wait for new diagnostics (WaitForDiagnostics with 5s timeout)
      3. Filter to errors only (ignore warnings/info)
      4. Return result with error count and details

    ```go
    type VerifyResult struct {
        HasErrors  bool
        ErrorCount int
        Errors     []DiagnosticSummary
    }
    type DiagnosticSummary struct {
        Line    int
        Col     int
        Message string
        Source  string
    }
    ```

    ```go
    type ReplaceBodyArgs struct {
        Path       string `json:"path" jsonschema:"File path"`
        SymbolName string `json:"symbol_name" jsonschema:"Name of the symbol whose body to replace"`
        NewBody    string `json:"new_body" jsonschema:"New body content to replace with"`
    }

    type InsertBeforeArgs struct {
        Path       string `json:"path" jsonschema:"File path"`
        SymbolName string `json:"symbol_name" jsonschema:"Name of the symbol to insert before"`
        Content    string `json:"content" jsonschema:"Content to insert"`
    }

    type InsertAfterArgs struct {
        Path       string `json:"path" jsonschema:"File path"`
        SymbolName string `json:"symbol_name" jsonschema:"Name of the symbol to insert after"`
        Content    string `json:"content" jsonschema:"Content to insert"`
    }

    type RenameSymbolArgs struct {
        Path    string `json:"path" jsonschema:"File path where symbol is defined"`
        Line    int    `json:"line" jsonschema:"Line number of symbol (1-indexed)"`
        Col     int    `json:"column" jsonschema:"Column number of symbol (1-indexed)"`
        NewName string `json:"new_name" jsonschema:"New name for the symbol"`
    }

    type SafeDeleteArgs struct {
        Path       string `json:"path" jsonschema:"File path"`
        SymbolName string `json:"symbol_name" jsonschema:"Name of the symbol to delete"`
        Force      bool   `json:"force,omitempty" jsonschema:"Delete even if references exist (default: false)"`
    }

    type VerifyEditArgs struct {
        Path string `json:"path" jsonschema:"File path to verify after editing"`
    }
    ```

    Tools:
    1. `replace_symbol_body` — EDT-01: Replaces a symbol's body using tree-sitter. Reports what was replaced.
    2. `insert_before_symbol` — EDT-02: Inserts content before a symbol.
    3. `insert_after_symbol` — EDT-03: Inserts content after a symbol.
    4. `rename_symbol` — EDT-04: Renames symbol across all files. Reports files changed.
    5. `safe_delete_symbol` — EDT-05: Deletes a symbol if no references. Reports reference count if blocked.
    6. `verify_edit` — EDT-06: Checks for errors after an edit. Returns diagnostic summary.

    Each handler:
    1. Resolves workspace from path
    2. Acquires WorkerLease (dirty=true for mutation operations: replace, insert, rename, delete; dirty=false for verify_edit which is read-only)
    3. Calls the underlying edit function
    4. For replace/insert/rename/delete: automatically runs VerifyEdit after the operation and includes diagnostic results in the response
    5. Returns text summary of what changed + any new errors

    Create `RegisterTools(kernel *Kernel, extractor *BodyExtractor, diagStore *diag.DiagnosticStore, registry *mcp.ToolRegistry)` function.
