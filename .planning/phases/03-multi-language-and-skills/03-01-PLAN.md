    Per D-03, implement three-tier resolution:

    **installer.go:**
    ```go
    type InstallerConfig struct {
        AutoInstall bool   // default true; config/CLI can set to false
        BinDir      string // managed install directory (~/.serena/bin/)
    }
    type Installer struct {
        config InstallerConfig
        logger *slog.Logger
    }
    func NewInstaller(cfg InstallerConfig, logger *slog.Logger) *Installer
    func (i *Installer) Resolve(ctx context.Context, entry LSEntry) (command string, args []string, err error)
    ```

    Resolve logic:
    1. Tier 1: `exec.LookPath(entry.Command)` -- if found, return immediately
    2. Tier 2: If `i.config.AutoInstall && entry.Install != nil`, call `i.download(ctx, entry)`:
       - For "npm": `exec.Command("npm", "install", "-g", pkg@version)` then re-LookPath
       - For "pip": `exec.Command("pip", "install", pkg==version)` or `pipx install`
       - For "binary": HTTP GET URL for current platform, verify SHA256, extract to BinDir
       - For "cargo": `exec.Command("cargo", "install", pkg)`
       - For "gem": `exec.Command("gem", "install", pkg)`
       - Return path after install
    3. Tier 3: Return error with `entry.InstallHint()` message

    Platform detection: `runtime.GOOS + "-" + runtime.GOARCH` for binary download URL lookup.

    Per Pitfall 3 (LS init race on first activation): Resolve is called lazily (not at startup). Log progress for long downloads. The caller (pool) should handle timeout/progress.

    **installer_test.go:** Test:
    - Resolve finds "go" (always in PATH on dev machine) without download
    - Resolve with AutoInstall=false and missing binary returns error with install hint
    - InstallHint returns readable message for npm/pip/binary types
    - Platform key generation works (e.g., "darwin-arm64")
  </action>
