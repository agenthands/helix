        store  *ProfileStore

    Init loads embedded profiles:
    ```go
    func (s *profileSkill) Init(deps skill.SkillDeps) error {
        store, err := LoadEmbedded()
        // LoadOverrides from deps.GlobalDir + deps.ProjectDir if present
        s.store = store
        return err
    }
    ```

    Implement `Tools() []*mcp.ToolDef` returning two tools:

    **switch_mode tool** (per D-04, D-05):
    - Input: `{ "mode": string }` — target mode name
    - Validation: Check mode exists in store. Check current profile's AllowedModeTransitions allows the transition from current mode to target.
    - On success: Update session's CurrentMode, record ModeTransition, recompute AllowedTools via skill.ResolveTools using mode's Skills/Tools/ExcludeTools merged with profile's.
    - On failure: Return structured error with allowed transitions list.
    - Response: `{ "previous_mode": "read", "current_mode": "edit", "tools_available": 15 }`

    **get_token_budget tool** (per D-08, D-09):
    - Input: `{ "profile": string?, "mode": string?, "format": string? }` — optional overrides, format is "summary" or "detailed"
    - Computes: For each tool in resolved set, estimate schema size in tokens. Use len(json_schema_bytes)/4 as rough token estimate (good enough for optimization hints).
    - Response (per D-08): `{ "total_tokens": N, "tool_count": N, "per_tool": [{ "name": "find_symbol", "schema_tokens": 120, "description_tokens": 45 }] }`
    - Default format "summary" omits per_tool array. "detailed" includes it.

    The skill needs access to session state. Add a `SessionProvider` interface or use a closure/callback pattern that the MCP server can inject during Init. For now, the simplest approach: add a `SessionStore` to SkillDeps or use a package-level setter that the daemon wires up. Choose the approach that best fits existing patterns — if SkillDeps already has extensibility, add there. Otherwise use a SetSessionProvider function on the profileSkill.

    IMPORTANT: The switch_mode tool's RegisterFn must wire into the MCP SDK server. Follow the same pattern as server.go's registerPingTool — use mcpsdk.AddTool with typed args struct.
