    **Update `internal/config/loader.go`** (per D-10):
    The existing 4-layer precedence (defaults -> global -> project -> CLI) already works correctly for profile selection. The `profile` key in any layer will be overridden by higher layers. The key insight from D-10 is: "Phase 4 wires profiles into the precedence chain" — this means profile-specific defaults (like which tools are available) should be resolvable FROM the config, not injected AS config layers.

    Add a new exported function:
    ```go
    // ResolveProfile loads the ProfileStore and returns the active profile based on config.
    // This is called after Load() to get the profile that should govern the session.
    func ResolveProfile(cfg *SerenaConfig, globalDir string) (*profile.ProfileStore, *profile.Profile, error) {
        store, err := profile.LoadEmbedded()
        if err != nil { return nil, nil, err }
        // Try loading overrides from globalDir and project paths
        profile.LoadOverrides(store, filepath.Join(globalDir, "profiles"), filepath.Join(globalDir, "modes"))
        p, ok := store.Profile(cfg.Profile)
        if !ok { return store, store.DefaultProfile(), nil }
        return store, p, nil
    }
    ```

    This keeps the config system clean — koanf handles scalar config values, ProfileStore handles the rich profile objects. The profile name flows through koanf precedence; the profile content comes from the ProfileStore.
