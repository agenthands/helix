<interfaces>
After Plan 01 lands, the following TB-typed signatures are available from `test/integration`:

```go
// test/integration/harness.go
func StartTestDaemon(tb testing.TB, opts Options) *TestDaemon
func PrepareFixture(tb testing.TB, lang string) string
func requireGopls(tb testing.TB)

// test/integration/helpers.go
func callTool(tb testing.TB, session *mcp.ClientSession, name string, args map[string]any) *mcp.CallToolResult
func listSessionTools(tb testing.TB, session *mcp.ClientSession) []string
```

BUT: `test/integration` is `package integration_test` with `//go:build integration`. Benchmarks in `test/bench/` cannot import it as a library. The bench package must provide its own thin wrappers that either (a) duplicate the TB-generic startup logic or (b) move the TB-generic code into a new exported package like `test/bench/internal/harness`.

**Chosen approach** (per 09-RESEARCH.md Architecture recommended layout): Create `test/bench/bench_helpers.go` as `package bench_test` that re-implements the minimal daemon startup using the same public types from `internal/daemon`, `internal/config`, `internal/skill`, `github.com/modelcontextprotocol/go-sdk/mcp`. This mirrors `test/integration/harness.go` but without the build tag and without the integration test framework dependency. Keep the function surface small: `startBenchDaemon(b *testing.B) *benchDaemon`, `prepareGoFixtureB(b *testing.B) string`, `activateWorkspaceB(b *testing.B, bd *benchDaemon, fixture string)`, `callToolB(b *testing.B, session *mcp.ClientSession, name string, args map[string]any) *mcp.CallToolResult`.

Rationale: duplicating ~100 lines of daemon startup is simpler than splitting integration harness across packages, and it keeps `//go:build integration` on the integration tests unchanged. Plan 01 is still required because the concept/ergonomic of TB-typed helpers carries over to bench_helpers.go (and because existing integration tests should compile both ways as a sanity check).
</interfaces>
