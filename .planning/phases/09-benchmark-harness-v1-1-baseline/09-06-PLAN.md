<interfaces>
**benchfmt library** (`golang.org/x/perf/benchfmt`) — stable, benchstat itself is built on top.

Core types:
```go
type Reader struct { /* ... */ }
func NewReader(r io.Reader, fileName string) *Reader
func (r *Reader) Scan() bool
func (r *Reader) Result() *Result

type Result struct {
    FullName []byte
    Values   []Value // e.g., {Value: 1234.5, Unit: "ns/op"}, {..., Unit: "allocs/op"}
    // ...
}
```

Algorithm:
1. Parse baseline file into `map[string]map[string]float64` — outer key is bench name, inner key is unit (`ns/op`, `allocs/op`).
2. Parse new file into same shape.
3. For each bench present in both, compute delta: `(new - base) / base`.
4. If any `ns/op` delta > time_threshold OR any `allocs/op` delta > allocs_threshold, exit 1 with a machine-readable report of offending rows.
5. Statistical significance (p<0.05 per D-01) requires multiple samples per bench. benchfmt exposes per-sample values — group by name and compute Welch's t-test, OR shell out to `benchstat -alpha 0.05` for the p-value and parse it back. Per Pitfall 9, prefer the benchfmt-library path: compute Welch's t-test in-process using a small stats helper (or copy the tiny implementation from the benchstat source). No third-party stats dependency.

**p<0.05 enforcement (addresses revision WARNING 2):** CONTEXT.md D-01 explicitly requires p<0.05 gating. There is NO escape hatch. benchgate MUST compute statistical significance using one of:

1. **Preferred:** Use `golang.org/x/perf/benchmath` / `golang.org/x/perf/benchproc` / the `benchstat` library packages directly — these already implement Welch's t-test and are the exact statistics benchstat itself uses. Importing the library avoids reimplementing the test and inherits upstream correctness. Check `pkg.go.dev/golang.org/x/perf/benchmath` for the `Assumption` / `Comparison` types.
2. **Fallback only if upstream library lacks a stable exported API:** Implement Welch's t-test inline — it's ~30 lines of arithmetic (pooled variance, degrees of freedom via Welch-Satterthwaite, t-statistic, p-value via incomplete beta). Copy from the benchstat source under the same BSD license.

Do NOT ship a "TODO: add p-value later" escape hatch. Do NOT ship a threshold-only gate as a "v1 simplification". The gate must enforce both (a) delta > threshold AND (b) p < 0.05 from the first blocking CI run. Samples come from `-count=10` (PR) or `-count=20` (release) — benchfmt Reader exposes each sample's value, group by bench name + unit and feed into the t-test.
</interfaces>

This is the exact input format for benchgate. Baseline files are committed AS-IS from `go test -bench=...` output (plus `-count=N` for multiple samples).
