<interfaces>
**benchfmt library** (`golang.org/x/perf/benchfmt`) — stable, benchstat itself is built on top.

Core types:
```go
type Reader struct { /* ... */ }
func NewReader(r io.Reader, fileName string) *Reader
func (r *Reader) Scan() bool
func (r *Reader) Result() *Result

type Result struct {
    FullName []byte
    Values   []Value // e.g., {Value: 1234.5, Unit: "ns/op"}, {..., Unit: "allocs/op"}
    // ...
}
```

Algorithm:
1. Parse baseline file into `map[string]map[string]float64` — outer key is bench name, inner key is unit (`ns/op`, `allocs/op`).
2. Parse new file into same shape.
3. For each bench present in both, compute delta: `(new - base) / base`.
4. If any `ns/op` delta > time_threshold OR any `allocs/op` delta > allocs_threshold, exit 1 with a machine-readable report of offending rows.
5. Statistical significance (p<0.05 per D-01) requires multiple samples per bench. benchfmt exposes per-sample values — group by name and compute Welch's t-test, OR shell out to `benchstat -alpha 0.05` for the p-value and parse it back. Per Pitfall 9, prefer the benchfmt-library path: compute Welch's t-test in-process using a small stats helper (or copy the tiny implementation from the benchstat source). No third-party stats dependency.

**Simplification for Phase 9 scope:** If Welch's t-test is a rabbit hole, the initial gate can use a simpler rule: delta threshold alone, without p-value gating. Mark this as a TODO in benchgate main.go ("v1.2 PR gate: threshold-only; release gate adds Welch's t on -count=20 samples"). D-01 mentions p<0.05 but the practical CI story is "benchstat reports p-values; benchgate enforces thresholds on the diff." The phase-close deliverable is a working threshold gate; p-value refinement can land in a v1.2 patch if time permits.
</interfaces>

<baseline_format>
benchfmt text format is emitted by `go test -bench=...` directly. Example:
```
goos: linux
goarch: amd64
pkg: github.com/postfix/serena/test/bench
cpu: Intel Xeon
BenchmarkTools/find_symbol-4    1000    1234567 ns/op    456 B/op    7 allocs/op
BenchmarkTools/read_file-4       500    2345678 ns/op   1024 B/op   12 allocs/op
...
```
This is the exact input format for benchgate. Baseline files are committed AS-IS from `go test -bench=...` output (plus `-count=N` for multiple samples).
</baseline_format>
