<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Network → admin listener | Any loopback client can hit /healthz, /readyz, and (if enabled) /debug/pprof/*. Loopback-only enforcement is the sole defense until v1.3 auth. |
| pprof endpoint → runtime | pprof exposes heap/goroutine/CPU profiles which can leak process state. Gated behind EnablePprof=false default. |
| ctx cancellation → bound listener | server.Shutdown(5s) must reliably release the socket so repeated daemon starts don't collide. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04 | Information disclosure | /debug/pprof/* | mitigate | Endpoints registered ONLY when cfg.Observability.EnablePprof=true (D-10). Default false. Loopback-only bind (D-05) provides defense-in-depth. |
| T-10-05 | Spoofing | non-loopback bind | mitigate | validateAdminAddr rejects 0.0.0.0 and any non-loopback host; error message references v1.3 auth roadmap (Pitfall #6). |
| T-10-06 | Denial of service | bind failure tears down daemon | mitigate | Non-fatal errgroup wrapper (D-04): admin listener errors are logged and return nil so the supervisor never sees them. |
| T-10-07 | Denial of service | listener hangs on shutdown | mitigate | server.Shutdown(5s) pattern mirrors listenHTTP (Pitfall #2). Integration test asserts goroutine exits within 5s of ctx cancel. |
| T-10-08 | Tampering | /readyz lies about startup state | mitigate | ready atomic flipped ONLY after kernel goroutine spawned, listeners up, profile resolved (Pitfall #3). |
| T-10-09 | Information disclosure | /healthz body | accept | Response body is literal {"status":"ok"} — no hostname, version, or internal state exposed (D-13). |
</threat_model>
