<objective>
Build the `bench/evaluators/repomapeval` stdlib-only leaf evaluator that measures `internal/repomap` ranking quality (`get-repo-map` / `get-context` order) against a multi-language **gold** corpus authored from task ground truth, plus the `//go:build ignore` HELIX_BIN-gated capture regenerator that lives OUTSIDE the leaf.

The leaf scores **committed gold vs committed captured ranking** (committed-vs-committed, per the Phase 100 determinism contract). It computes recall@10, MRR, nDCG@10 (headline, per D-07), and a gold-retention-within-budget ratio (per D-08). A reversed ranker AND a seeded-random ranker BOTH must fail the gold corpus, with the forward ranking beating both by a committed absolute margin — the REPOEVAL anti-vacuity proof (D-09).

Purpose: REPOEVAL-01 (the leaf measures ranking quality, stdlib-only) and REPOEVAL-02 (broad gold corpus from ground truth + size floor + reversed/random discriminator that MUST fail). This is a measurement phase — every primitive (seeded RNG, exercise loading, the subsystem under test) already exists; the net-new code is metric math + corpus authoring + discriminators.

Output: the `repomapeval` package (metrics, rankers, corpus loader), committed gold + captured testdata for py/go/rust, a `CORPUS.md` documenting the size floor + file:symbol identity convention + parse contract, and the capture regenerator.

This plan is `type: tdd`. The metric functions and the discriminator margin are defined-I/O algorithms; author the corpus from ground truth FIRST, then write the failing metric/discriminator tests (RED), then implement to GREEN. **Sequencing matters: the corpus is authored before the scoring is wired, and the discriminator proves the corpus is non-trivial — never derive gold from tool output.**
</objective>
