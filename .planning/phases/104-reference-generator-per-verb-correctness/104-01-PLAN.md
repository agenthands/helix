<objective>
Fix the reference-generator group-collapse at its root cause so every `helix` verb's **Output** and **Use this, not that** lines in the generated `reference.md` are correct for that verb's actual semantics. Ten verbs currently inherit memory-query prose because `cmd/helix-cligen`'s `categoryToGroup` folds five ToolProvider categories (`memory`, `workflow`, `health`, `help`, `profile`) into the single `groupMemory` ID, and `cmd/helix-refgen/render.go` selects prose keyed ONLY on `GroupID`. The fix introduces per-verb override maps in the refgen renderer (consulted by keyed lookup before the group-default fallback), regenerates and commits `reference.md`, and ships two anti-vacuity guards that prove the override map is real.

Purpose: An agent reading `helix get-tool-help` should not be told the Output is "a ranked FTS5 search result set" or to use it "for durable project/session memory." Wrong routing prose erodes the whole product thesis (CLI > grep/sed/cat). This phase must also land BEFORE Phase 105's SKILL.md matrix rewrite so the two docs tell one consistent story.

Output: Edited `cmd/helix-refgen/render.go`, a new `cmd/helix-refgen/render_test.go`, and a regenerated `internal/cli/skills/helix/reference.md` — all in this single phase, gated by `--check` byte-reproducibility, the `reference ⊇ VerbToolNames()` ==50 contract, and `verify-cligen` SET parity.

Implements REFGEN-01. The success criteria are SC #1 (root-cause generator fix via per-verb override map), SC #2 (regenerated reference.md byte-clean under `--check`), SC #3 (contract + drift + blank-import parity stay green), SC #4 (override-map vacuity guards with deliberate break-the-invariant tests).
</objective>
