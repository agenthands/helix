<objective>
Replace `loggingMiddleware` with `TelemetryMiddleware` that emits RED metrics for every `tools/call` AND preserves the existing structured log lines in a single closure. Other MCP methods (tools/list, initialize, etc.) pass through without metric emission.

Purpose: METRIC-02. Resolves RESEARCH.md Open Questions A1, A2.
Output: TelemetryMiddleware wired into MCP server, outcome classification enum (7 values), label resolution from session snapshot.

**Resolved facts baked into this plan (from checker investigation of internal/mcp/middleware.go):**

1. **ProfileFilterMiddleware only filters `tools/list`** — it does NOT intercept `tools/call`. There is no deny path at tool-call time in v1.2. Therefore `outcome=denied` is NOT reachable via profile filtering in v1.2 and is DROPPED from the outcome enum. Closed enum is now 7 values: `{success, invalid_args, not_found, circuit_open, ls_crash, timeout, internal}`. A `denied` bucket may be reintroduced in v1.3 if per-call filtering lands.

2. **`loggingMiddleware` is already installed** via `InstallMiddleware(server, logger)` in `internal/mcp/server.go` at line 12–14. It wraps every request with start/duration/error logging. TelemetryMiddleware REPLACES it: the logging concerns (method, duration, error) are absorbed into the telemetry middleware which emits metrics AND calls logger.Info/Warn the same way for non-tools/call methods.

3. **Method filter:** Middleware handles `method != "tools/call"` as a minimal pass-through that still logs (preserving Phase 8 log behavior for tools/list, initialize, etc.) but emits NO metric. Metric emission is gated on `method == "tools/call"`.

4. **Middleware ordering with ProfileFilterMiddleware is irrelevant for tool-call semantics** because ProfileFilterMiddleware only touches `tools/list`. The D-06 "before ProfileFilter" constraint from CONTEXT.md was written assuming ProfileFilter had a deny-at-call path; since it does not, this plan is free to install TelemetryMiddleware in whatever order yields the cleanest code. Document the constraint as obsolete in a code comment.
</objective>
