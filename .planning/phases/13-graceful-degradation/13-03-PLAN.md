   - Create a daemon using `NewWithObsProvider` with a noop or tracetest provider
   - Run the daemon in a goroutine via `d.Run(ctx)`

   - Assert the socket file is removed

   NOTE: The test design depends on the daemon's architecture. Since we can't easily inject a slow tool handler into the MCP SDK from outside, the test should verify the shutdown path specifically:
   - Start daemon, wait for ready
   - Launch a goroutine that holds a resource (e.g., acquires a worker lease)
   - Send SIGTERM
   - Assert Run returns cleanly
   - Assert socket file is removed

   Alternative approach if direct tool injection is complex: Test the shutdown ordering by:
   - Creating a daemon with tracetest provider
   - Starting Run in a goroutine
   - Waiting for ready
   - Sending SIGTERM via `syscall.Kill(syscall.Getpid(), syscall.SIGTERM)` -- but NOTE this sends to the whole process which may interfere with the test runner. Instead, use a cancellable context:
     ```go
     ctx, cancel := context.WithCancel(context.Background())
     // ... start daemon ...
     // wait for ready
     cancel() // simulates SIGTERM (Run uses signal.NotifyContext which also cancels)
     ```
   This is actually MORE reliable for testing because signal delivery to os.Getpid() can kill the test process. Use context cancellation to simulate the shutdown trigger, since Run's errgroup propagates context cancellation identically to signal handling.
