# Plan 135-01 — Extraction foundation: langFromExt + C var→type co-capture

## Summary

Two decoupled, independently-testable changes, both proven against the REAL C
extractor in-process:

- **B1:** extend `langFromExt` to the C-family so the production index extracts
  `.c/.h/.cpp/.cs/.java`.
- **B3:** add an in-memory-only `extract.SymbolFact.DeclaredType` field and populate
  it for C variable/field/parameter symbols via tree-sitter **co-capture** (declared
  type + declarator in one query pattern), then a deterministic daemon-side helper
  that maps `(referencing symbol NodeID → declared type name)` from the raw
  `[]*ExtractedFile`. No persistence, no golden churn.

## Grounding (verified at HEAD)

- Co-capture works: the C function pattern already co-captures `@definition.function`
  + `@def.function.body` in ONE match; the provider reads both from one `m.Captures`
  (`c/provider.go:94-140`). Merging the variable's `type:` + `declarator:` into one
  pattern lands both captures in one match.
- `factsFromExtracted([]*extract.ExtractedFile{...}, repoID, "", nil, nil)` is directly
  callable in daemon-package tests (`semantic_extra_edges_test.go:130` etc.).
- `makeProductionBuildFn` runs in-process over a real workspace dir
  (`semantic_wiring_test.go:114`) — the B1 proof harness.
- `ToStoreFacts` (`internal/semantic/extract/to_store.go`) maps `SymbolFact`→store row
  field-by-field; a new in-memory field it does not reference is naturally dropped.

## Tasks

### Task 1 — B1: extend `langFromExt` (TDD)
- RED: add a daemon test asserting `langFromExt("x.c")=="c"`, `"x.h"=="c"`,
  `"x.cpp"/"x.cc"/"x.cxx"/"x.hpp"/"x.hh"/"x.hxx"=="cpp"`, `"x.cs"=="c_sharp"`,
  `"x.java"=="java"`; and that rust/kotlin/php/ruby extensions still return `""`
  (explicitly out — v2.13).
- GREEN: extend the `switch` in `langFromExt` (`semantic_wiring.go:1812-1825`); update
  the doc comment to list the C-family and note rust/kotlin/php/ruby are deferred.
- Guard: the provider registry already registers c/cpp/c_sharp/java (`daemon.go:383`
  area) — confirm `b.extractRegistry.Provider("c")` resolves so `classifyAndExtract`
  doesn't silently skip at the `provider, ok` gate.

### Task 2 — B1 proof: production extraction reaches a C file
- Add an in-process test mirroring `semantic_wiring_test.go:114`: seed a temp
  workspace with a real `.c` file (`struct Point { int x; int y; };` + a function
  using `struct Point`), run `makeProductionBuildFn(... "full" ...)`, assert the
  committed snapshot has ≥1 C symbol (before this change: zero).

### Task 3 — B3: `DeclaredType` field + C co-capture
- Add `DeclaredType string` to `extract.SymbolFact` (`fact.go`), documented as
  IN-MEMORY ONLY (like the `Fingerprint*` fields): populated in the provider while the
  AST is alive; NOT persisted; NOT part of `StableKey`/`SignatureHash`.
- C query (`c/queries.scm`): replace the standalone variable pattern with a
  co-capturing pattern that captures BOTH the declarator identifier
  (`@definition.variable`) AND the declaration's type node (`@def.variable.type`) in
  one match. Add analogous co-capture for `field_declaration` (field) and
  `parameter_declaration` (parameter) so their symbols carry the declared type.
  (Keep the existing `@type.annotation`/`reference.type` captures intact.)
- C provider (`c/provider.go`): when a `def.*.type` capture is present in the match,
  set `sf.DeclaredType = condenseWhitespace(typeNode.Utf8Text(source))` (strip
  `struct`/`union`/`enum` keyword + pointer `*` to the bare tag, matching what
  `parseAnnotation` would yield — reuse/extract the tag-normalization so 136's
  ChainTokens path and any Signature fallback agree). Leave `Signature` UNCHANGED
  (still the bare name) — do NOT change signature to avoid StableKey churn.
- Assert `ToStoreFacts` drops `DeclaredType` (add a test: build a `SymbolFact` with
  `DeclaredType` set, run `ToStoreFacts`, confirm the store row carries no type and the
  StableKey is unchanged vs. the same symbol without `DeclaredType`).

### Task 4 — B3: the var→type linkage helper + proof
- Add a pure, deterministic daemon helper (e.g. `linkVarTypes(extracted []*extract.ExtractedFile) []varTypeLink`)
  that walks the raw `ef.Symbols`, and for each variable/field/parameter symbol with a
  non-empty `DeclaredType`, emits `{RefSymbolStableKey/RefName, TypeName}`. Order-stable
  (iterate files then symbols in slice order; no map iteration in the emit path).
  NOTE: this helper is the INPUT contract for 136's producer — keep it a clean,
  separately-testable function; do NOT wire it into `factsFromExtracted` edge emission
  yet (that's 136).
- Tests (drive the REAL C provider, not hand-built facts):
  1. `struct Foo {…};` + `void g(struct Foo* p){…}` → link `(p, "Foo")`.
  2. `Foo x = init;` (typedef'd) → link `(x, "Foo")`.
  3. Anti-vacuity: `int n = 0;` (primitive type) OR a name with no type → NO link
     (break-the-linkage guard: assert zero links; if a link appears, RED).
  4. Determinism: run twice → identical `[]varTypeLink`.

### Task 5 — regression + hygiene
- `go test ./internal/semantic/extract/c/...` — ALL existing goldens byte-identical
  (the co-capture must not change emitted symbols/references/types JSON; if a golden
  moves, the mechanism is wrong — stop).
- `go test ./internal/daemon/...` affected tests green.
- `go build ./...` + `make vet` clean. `go.mod`/`go.sum` byte-unchanged.
