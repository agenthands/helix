# Plan 136-01 — Resolver ChainTokens + producer + driver + emit (in-process proof)

## Summary

Wire the type-resolver dispatcher into `factsFromExtracted` so a C-family type ref
becomes a committed `RESOLVES_TO` edge with a real target. Ordered: (A) resolver
package changes (`internal/semantic/types/*` — ChainTokens consumption + typeIndex
injection), (B) daemon producer/driver/converter/wire (`semantic_wiring.go`), (C)
clean cutover (remove the orphaned bootstrap dispatcher + dead seams), (D) in-process
differential + determinism proof.

## Grounding (verified at HEAD)

- All 7 full resolvers share `NewResolver(store types.EffectiveReader) *Resolver`
  (c/cpp/c_sharp/java/golang/python/typescript) with a `typeIndex map[string]graph.NodeID`
  field already present (test-mutated only). C/C++ `SameScope` is translation-unit
  (per-file); java/c#/py/ts/go use `SamePackage`.
- `FixpointResolve(ctx, lang Resolver, refs []ChainRequest, maxIter int) ([]ChainResponse, error)`
  (`fixpoint.go:27`) — routes through any Resolver (the dispatcher plugs in).
- `factsFromExtracted` (`semantic_wiring.go:1948`): dedup (`:2340`) → `nameToNode`
  build (`:2413`, keys = bare `s.Name` → definition NodeID) → `resolvePendingDst`
  (`:2432`). The wire point is AFTER `nameToNode`, in the same tail region, BEFORE the
  buildFn dense EdgeID stamp (`:1610`).
- Config: `cfg.SemanticIndex.TypeResolution.{MaxFixpointIterations=8, MinConfidenceForEdge=0.45, EmitUnresolvedEdges}`
  (`semantic/config.go:398-405`); daemon-side `semanticConfig` (`semantic_wiring.go:75`,
  defaults in `loadSemanticConfig:87`) does NOT yet carry them.
- Dead code to remove (ZERO non-test callers, verified): bootstrap dispatcher
  `daemon.go:603-628`; struct fields `typeResolver`/`semanticGraphRanker`
  (`daemon.go:197,203`); `Daemon.TypeResolver()` + `Daemon.SetSemanticGraph()`
  (`type_resolver_wiring.go:137,150`). Keep `typeStoreAdapter` + the per-language
  constructor wrappers (still used, or reused by the producer).

## Tasks

### Task A1 — resolvers consume ChainTokens (B2), uniform across 7 full resolvers
- In each full resolver's `ResolveChain`, at the annotation tier: if
  `len(req.ChainTokens) > 0 && req.ChainTokens[0] != ""`, use `req.ChainTokens[0]` as
  the annotation type name (skip `parseAnnotation(Signature)`); else keep the existing
  `parseAnnotation(Signature)` fallback. Preserve tier/evidence/confidence/D-12.
  Files: `c,cpp,c_sharp,java,golang,python,typescript/resolver.go`.
- Test (per language, at least C + Go): a `ChainRequest` with `ChainTokens:["Foo"]` +
  a typeIndex mapping `"Foo"→N` resolves at annotation tier to Target=N validated,
  WITHOUT relying on Signature. Keep the existing Signature-based tests green
  (fallback path).

### Task A2 — typeIndex injection path (uniform)
- Add `NewResolverWithIndex(store types.EffectiveReader, idx map[string]graph.NodeID) *Resolver`
  to each full resolver (sets both fields). Keep `NewResolver` as
  `NewResolverWithIndex(store, nil)`.
- Unit test: `NewResolverWithIndex` populates the index; a resolve uses it for Target.

### Task B1 — daemon: thread the type-resolution knobs
- Add the needed knobs to `semanticConfig` (`semantic_wiring.go:75`) —
  `TypeResolMaxFixpoint int`, `TypeResolMinConfidence float64`,
  `TypeResolEmitUnresolved bool` (or a nested struct) — defaulted in
  `loadSemanticConfig` (8, 0.45, false) matching `TypeResolutionConfig` defaults.
  (loadSemanticConfig is the single inlined-defaults site per its doc.)
- Thread them into `factsFromExtracted` via a new param (e.g. a small
  `typeResolveParams` struct) OR make the resolver-driver a `*semanticBundle` method
  the buildFn calls with `out` + `nameToNode`. Prefer the latter (keeps
  `factsFromExtracted` signature stable for its many test callers) — a
  `(b *semanticBundle) resolveTypeEdges(out *semanticstore.Facts, nameToNode map[string]uint64, nameCount map[string]int, extracted []*extract.ExtractedFile)`
  invoked from the buildFn right after `factsFromExtracted` returns and BEFORE the
  EdgeID stamp. NOTE: if a package-fn is required (to run inside factsFromExtracted
  where nameToNode lives), pass params explicitly — do NOT read globals.
- **Decision to make at code time:** nameToNode is local to factsFromExtracted. Either
  (i) run the driver INSIDE factsFromExtracted (add params), or (ii) return nameToNode
  from factsFromExtracted for the buildFn to drive. Pick the one that keeps the ~20
  existing `factsFromExtracted(...)` test callers compiling with least churn — likely
  (i) with a variadic/opts param, or a thin wrapper. Document the choice.

### Task B2 — batch-backed EffectiveReader
- Implement a `types.EffectiveReader` over the in-memory `out.Symbols`:
  `QueryEffectiveSymbol(repoID, nodeID) → types.SymbolFact` (Language/Kind/StableKey/
  FilePath/Signature) by NodeID lookup; `QueryEffectiveEdges` returns nil (Tier-1
  stays dead, L5). Deterministic; built once per batch from `out.Symbols`.

### Task B3 — reference producer + typeIndex from nameToNode
- Build `typeIndex map[string]graph.NodeID` from `nameToNode` (bare name → NodeID),
  skipping `nameCount[name] > 1` (anti-mis-bind; those names have no unique target).
- From `linkVarTypes(extracted)` (Phase 135), and a `RefStableKey → NodeID` map built
  from `out.Symbols`, produce `[]types.ChainRequest`:
  `{RepoID, Language, FilePath (via fileIDToPath), RefNodeID=<referencing symbol NodeID>,
  RefKind:"RESOLVES_TO", ChainTokens:[TypeName]}`. Skip links whose RefStableKey has no
  surviving NodeID (dropped by dedup) or whose TypeName isn't a unique nameToNode key.

### Task B4 — driver + converter + wire
- Group the ChainRequests per (PackageScope-or-file, Language). Iterate group keys in
  SORTED order; within a group sort refs by (RefNodeID, TypeName). Build a per-batch
  `types.NewDispatcher` with `NewResolverWithIndex(batchReader, typeIndex)` per
  language present. For each group, `FixpointResolve(ctx, dispatcher, refs, maxFixpoint)`.
- Convert each Resolved response (Confidence ≥ MinConfidenceForEdge) to a
  `semanticstore.EdgeFact{SrcNodeID:refNode, DstNodeID:resp.Target, EdgeKind:"RESOLVES_TO",
  SrcKind:<ref sym kind>, DstKind:"type", Source:<bounded>, Weight:1.0,
  Confidence:resp.Confidence, ValidationState:resp.ValidationState}`. GATE OUT dst=0
  (unreadable) rows (do not persist; L4). Append to `out.Edges` in the sorted order
  BEFORE the dense EdgeID stamp.
- No Go-map iteration in the emit path (D1): materialize sorted slices first.

### Task C1 — clean cutover: remove the orphaned bootstrap dispatcher + dead seams
- Remove `daemon.go:603-628` (the bootstrap `types.NewDispatcher` + log), the
  `typeResolver`/`semanticGraphRanker` struct fields (`daemon.go:197,203`) + their
  assignment (`daemon.go:1131` area), and `Daemon.TypeResolver()` +
  `Daemon.SetSemanticGraph()` (`type_resolver_wiring.go`). Keep `typeStoreAdapter` +
  the per-language constructor wrappers ONLY IF the producer reuses them; otherwise
  remove the now-unused wrappers too (no dead code). Re-grep to confirm zero remaining
  references before deleting. If any test references them, update/remove that test.
- If removal entangles unexpectedly (a caller appears), STOP and route up — do not
  leave a shim.

### Task D1 — in-process differential + determinism proof (the exit gate)
- New daemon test using the real C provider + `openDataFlowStore`-style real `*Store`:
  1. **Positive:** a single C file `struct Foo { int a; }; void g(struct Foo* p){}` →
     run the production build path (or `factsFromExtracted` + drive + commit) →
     `QuerySymbolEdgesOutgoing(p's node)` returns EXACTLY ONE `RESOLVES_TO` edge whose
     DstNodeID → `QueryStableKeyByNodeID` == Foo's stable key.
  2. **Negative (differential anti-vacuity):** `void h(int n){}` → ZERO RESOLVES_TO
     edges. Positive assertion ordered FIRST.
  3. **Determinism:** run the build twice → byte-identical `out.Edges` (or identical
     committed edge rows).
  4. **Anti-mis-bind:** a fixture with two same-named types (nameCount>1) → the edge
     is NOT emitted (no fabricated target).

### Task E — hygiene
- `go build ./...` + `make vet` (8 vettools) clean. `go.mod`/`go.sum` byte-unchanged.
- Affected packages green: `go test ./internal/semantic/types/... ./internal/daemon/...`.
- Existing extractor goldens byte-identical (unchanged — no extractor edits here).
- Run ONLY affected packages; the lead runs milestone-wide checks.

## Notes for the executor
- The dispatcher removal (Task C1) is a CLEAN CUTOVER, not optional — but re-grep
  before each delete; a surprise caller means STOP + route up.
- Keep the producer/driver deterministic: sort before you range. The EdgeID stamp is
  positional; nondeterministic edge order = non-byte-identical snapshot = FAIL.
- The batch reader makes tier-2..6 self-consistent pre-commit; do NOT point resolvers
  at the store adapter inside factsFromExtracted (uncommitted → stale).
- If the `factsFromExtracted` signature-vs-method decision (Task B1) is non-obvious,
  prefer the least-churn option that keeps existing test callers compiling, and
  document it in the SUMMARY.
