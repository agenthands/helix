# Plan 137-01 — Real-binary C-family E2E + docs reconciliation

## Summary

Prove the milestone through the real `helix` binary: index a seeded C fixture, then
`helix explain-symbol-deep` returns a `has_type` edge from the referencing symbol to
its type. Differential anti-vacuity + determinism. Then reconcile
`docs/type-resolution.md` to the Phase-136 production path.

## Tasks

### Task 1 — C-seeding E2E fixture builder
- Add a fixture builder (new test file `internal/cli/cli_type_resolution_e2e_test.go`,
  build `!windows`, pkg `cli_test`) that mirrors `newE2EFixture` but seeds a `.c` file
  instead of `main.go`. Reuse `resolveHelixBin`/sandbox primitives. Positive fixture
  content (one file, e.g. `types.c`):
  ```c
  struct Foo { int a; };
  int use(struct Foo *p) { return p->a; }
  ```
  (def + use in ONE translation unit → flat scope → validated edge).

### Task 2 — resolve the mode-gate mechanism (empirical)
- Determine how session mode is keyed across `helix` subprocess calls. Try, in order:
  (a) `helix switch-mode --target-mode=review` then `helix index-semantic-graph
  --mode=full` as separate subprocesses — if mode persists on the daemon, use this
  (fullest real-binary flow);
  (b) if it does NOT persist, drive `index_semantic_graph` via
  `forwarder.CallTool(ctx, socket, ..., "index_semantic_graph", {"mode":"full"})`
  (MCP path, same session as activate) — the INDEX trigger MAY use MCP;
  (c) else start the daemon in a profile permitting index.
- Document the working mechanism in the test comment + SUMMARY. The HEADLINE assertion
  (Task 3) uses the REAL BINARY for `explain-symbol-deep` regardless.

### Task 3 — the headline assertion (real binary)
- After activate + index: run `helix explain-symbol-deep
  --seed-json='{"file_path":"types.c","symbol_name":"p"}'` (or the correct rel path)
  as a REAL subprocess (`runCLIVerbInDir` with dir=repoDir). Parse the JSON output;
  assert `edges_incoming`/`edges_outgoing` contains an edge with
  `edge_kind=="has_type"` (ideally targeting `Foo`). This is SC4.
- Use `symbol_name` for the referencing symbol whose var→type link 136 produces
  (the parameter `p`); if the seed resolution needs a different anchor, adjust to the
  symbol the linkage actually attaches (verify against the 136 in-process test's node).

### Task 4 — differential anti-vacuity + determinism
- Negative fixture (separate seed or sub-test): `int use2(int n){ return n; }` — no
  named type. Assert `explain-symbol-deep` on `n` (or the file) yields NO `has_type`
  edge. Positive (Task 3) asserted FIRST.
- Determinism: index twice (re-run index), assert the `has_type` edge set is identical
  across runs (e.g. same target, same count).
