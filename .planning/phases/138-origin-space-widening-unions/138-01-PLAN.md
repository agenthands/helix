# PLAN 138-01 — Origin-space widening + kind-union extension + all-11 unit verification

## What (the deliverable)

Widen the `dataflow` leaf engine's taint origin space from a bare param index to a
discriminated `Origin` over `{param(idx) | callReturn(calleeName)}`; record in-body
producer→consumer flows (`InBodyFlow`); extend the tree-sitter kind unions to cover all
11 grammars; prove it all with pure unit tests incl. a cheap all-11 matrix. **No emission.**

## Grounded facts (from HEAD, do not re-derive)

- `taint` is `map[string]map[int]bool` (var → set of origin param indices), seeded in
  `AnalyzeFlow` (`summary.go:102-110`). Threaded through `walkFlow` / `processAssignment`
  / `processReturn` / `processCall` / `collectOrigins` — **all callers are internal to
  `summary.go`** (verified: no external caller of these unexported fns).
- `collectOrigins` returns `map[int]bool` (`summary.go:~269`); called ONLY by
  processAssignment/processReturn/processCall.
- `AnalyzeFlow` bails early at `len(paramNames)==0` (`summary.go:~98`) — MUST relax (see step 2).
- Unions live at `summary.go:54-83`. Current gaps (red-team B1, empirically confirmed):
  Python/Ruby `assignment` ∉ `assignKinds`; C/C++ `init_declarator` ∉ `assignKinds` (the
  present `init_declaration` is a typo matching nothing); Ruby `method_parameters` ∉
  `paramListKinds`; Kotlin `value_arguments` ∉ `argListKinds` + `property_declaration`
  needs a bespoke LHS/RHS split.
- Carry seam FLOW-04e is ALREADY wired: `SymbolFact.FlowSummary *dataflow.Summary`
  (fact.go:127) + `FingerprintBody` (fingerprint.go:54). Widening the struct flows through
  the pointer — **verify with the existing extract tests, do not re-plumb.**

## Steps (build order)

### 1. Types (`summary.go`)
- Add `Origin` — a comparable struct discriminant:
  `type Origin struct { Param int; Callee string }` where `Callee==""` ⇒ **param origin**
  (`Param` = 0-based index), `Callee!=""` ⇒ **callReturn origin** (`Param` unused, set 0).
- Add `type InBodyFlow struct { Producer string; Consumer string; ArgPos int }` (Producer =
  the callReturn callee name; Consumer = the call the value flows into; ArgPos = arg index).
- Add `InBodyFlows []InBodyFlow` to `Summary`.
- Change `taint` type everywhere to `map[string]map[Origin]bool`; `collectOrigins` returns
  `map[Origin]bool`.

### 2. `AnalyzeFlow` (`summary.go`)
- Relax the zero-param early return: **always walk the body**. Seed taint with param
  origins as today. Thread a `var inBody []InBodyFlow` and pass `&inBody` down.
- Final assembly: build `Summary` from param flows as today (drop dead params); set
  `out.InBodyFlows = dedupSortInBody(inBody)`. Return nil ONLY when
  `len(out.Params)==0 && len(out.InBodyFlows)==0`. (The v2.9 anti-vacuity gate generalized.)

### 3. `processAssignment` (D-COMPOSE, FLOW-04b + m2) (`summary.go`)
- After `splitAssignment`, before the generic origin propagation, try
  `unwrapToCall(rhs)`:
  ```
  func unwrapToCall(n *ts.Node) *ts.Node {
      for n != nil && (n.Kind()=="expression_list" || n.Kind()=="parenthesized_expression") {
          if n.NamedChildCount() != 1 { return nil }  // multi-call / ambiguous ⇒ refuse
          n = n.NamedChild(0)
      }
      if n != nil && callKinds[n.Kind()] { return n }
      return nil
  }
  ```
  If it returns a call node `C` with a non-empty `calleeName(C)` ⇒ set
  `taint[lhs] = {Origin{Callee: name}}` and **return** (D-COMPOSE: LHS = callReturn of the
  OUTERMOST call, NOT the inner args). Whitelist is STRICT: never descend selector/member/
  index/binary. `y := producer().field` ⇒ selector RHS ⇒ unwrapToCall returns nil ⇒ no
  in-body origin. `a, b := f(), g()` ⇒ multi-child expression_list ⇒ nil ⇒ no origin.
  `y := wrap(producer())` ⇒ call directly ⇒ `callReturn(wrap)` only.
- Else fall through to the widened generic path: `origins := collectOrigins(rhs)`; union
  into `taint[lhs]` (propagates BOTH param and callReturn origins through ident chains — the
  2-hop `b := transform(a)` case where `a` already carries `callReturn(producer)` still gets
  its OWN `callReturn(transform)` via the unwrap branch above; the generic path covers pure
  ident forwarding `b := a`).

### 4. `processCall` (FLOW-04c) (`summary.go`)
- For each arg position `i`, `collectOrigins(arg)` (widened). For each origin `o`:
  - `o.Callee == ""` (param) ⇒ append `CallArgTarget{callee, i}` to `flows[o.Param].CallArgs`
    (**v2.9 path unchanged**).
  - `o.Callee != ""` (callReturn) ⇒ append `InBodyFlow{Producer: o.Callee, Consumer: callee,
    ArgPos: i}` to `*inBody`.

### 5. `processReturn` (FLOW-04d, D-BRIDGE input) (`summary.go`)
- For each origin in the returned expr: `o.Callee==""` ⇒ `flows[o.Param].Returns = true`
  (reclaims the existing `Returns` computation — this is the return-bridge input Phase 139
  emits). callReturn origins reaching return are **NOT recorded** (locked out — no edge maps
  to it in v2.13; an unconsumed field is dead scaffolding).

### 6. Determinism (FLOW-04f) (`summary.go`)
- Add `dedupSortInBody([]InBodyFlow) []InBodyFlow` sorting by (Producer, Consumer, ArgPos),
  dedup adjacent — mirroring `dedupSortCallArgs`. No Go-map iteration in the output path.

### 7. Union extension (FLOW-04i / B1) (`summary.go:54-83`)
- `assignKinds`: **replace** the dead `init_declaration` with `init_declarator` (C/C++);
  **add** `assignment` (Python/Ruby).
- `paramListKinds`: add `method_parameters` (Ruby).
- `argListKinds`: add `value_arguments` (Kotlin).
- `splitAssignment`: add a **Kotlin `property_declaration` branch** — but VERIFY THE AST
  SHAPE FIRST by parsing `val local = producer()` and dumping the tree (see step 8's matrix
  harness). Implement the split to match REALITY (red-team observed the `variable_declaration`
  child holds the LHS ident and the `call_expression` is a sibling; the naive positional
  fallback may or may not already cover it — confirm empirically, then write the minimal
  branch that makes the Kotlin matrix row green). Do the same empirical check for C/C++
  `init_declarator` (fields `declarator`/`value`) and Python/Ruby `assignment` (fields
  `left`/`right`) — the positional fallback likely covers C/C++ and Python; Ruby/Kotlin are
  the risk rows.

### 8. Tests
- **`dataflow_test.go`** (extend, reuse `analyzeGo`): FLOW-04h Go fixtures — single in-body,
  in-body+param coexisting, 2-hop chain; m2 RED guards (nested-wrap positive, selector-RHS
  negative, multi-call-RHS negative); FLOW-04g anti-vacuity (dead local, pure param);
  determinism (re-analyze → reflect.DeepEqual identical).
- **`dataflow_matrix_test.go`** (NEW): a table `{lang, src, funcDeclKind}` over all 11
  providers. For each: `testutil.NewTestRegistry(t)`, construct the provider
  (`<lang>extract.NewProvider(reg)`), parse the `local := producer(); sink(local)` fixture
  (idiomatic per language), locate the enclosing function-decl node by `funcDeclKind`, run
  `AnalyzeFlow`, assert `InBodyFlows` contains `{producer, sink, 0}`. A language that cannot
  resolve is `t.Skip`-ped with a **recorded reason string** (the honest breadth ledger) —
  but the GOAL is all 11 green; a skip must be justified in the SUMMARY, not silent.
  Import the 11 providers: c, cpp, csharp, golang, java, kotlin, php, python, ruby, rust,
  typescript (`internal/semantic/extract/<lang>`). funcDeclKind per language (VERIFY when a
  row is red): go/ts `function_declaration`; java/c#/php/kotlin `method_declaration` /
  `function_declaration` / `method_declaration` / `function_declaration` (confirm); rust
  `function_item`; python `function_definition`; ruby `method`; c/cpp `function_definition`.
  Wrap fixtures so exactly one function exists (Java/C#/Kotlin need a class wrapper).
