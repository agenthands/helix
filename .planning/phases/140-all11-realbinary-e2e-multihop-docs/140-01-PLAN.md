# PLAN 140-01 — All-11 real-binary E2E + function-seeded multi-hop + docs

## What (the deliverable)

A HELIX_BIN-gated real-binary E2E oracle that CONFIRMS in-body-origin `data_flows` edges
surface via `helix explain-symbol-deep` for all 11 languages (target; skips tested +
recorded), proves a function-seeded `producer→transform→sink` multi-hop through the real
binary for ≥1 language, guards determinism, and the DATA_FLOWS docs updated for in-body origins.

## Grounded facts (from HEAD — do not re-derive)

- **Template:** `internal/cli/cli_type_resolution_e2e_test.go` (v2.12). Helpers on `e2eFixture`:
  `newE2EFixture(t, runID)`, `switchModeReview(t, ctx)` (MCP `switch_mode` target_mode=review),
  `indexFull(t, ctx)` (`index-semantic-graph --mode-arg=full`, asserts `status=="committed"`),
  `explainSymbol(t, ctx, absPath, name)` → `explainDeepResult{Seed, EdgesIncoming, EdgesOutgoing,
  FallbackReason}`, `explainEdge{From, To, EdgeKind, InternalKind}`, `containsToken`. Seed
  `file_path` MUST be ABSOLUTE. Overwrite the default main.go seed + `os.Remove(main.go)` to seed
  a per-language file.
- **Surface:** `MapInternalKind("DATA_FLOWS")=="data_flows"` (edge_kind_surface.go:66). Assert
  `edge_kind=="data_flows"`, `internal_kind=="DATA_FLOWS"`. In-body edge = producer.function →
  consumer.param (seed the CONSUMER param → the edge is INCOMING; explain scans both directions
  via a `hasTypeEdges`-style helper — write `dataFlowEdgesOf(res)`).
- **trace verb:** `handleTraceDataFlow` (tools_trace_data_flow.go:91); `TraceDataFlowArgs{Seed
  SeedInput, MaxHops}`. Function seed is mechanically accepted (no kind gate — REQUIREMENTS M2).
  CLI verb `trace-data-flow --seed-json` (verbs_gen.go:429). Seed by `{file_path, symbol_name}`
  where symbol_name is the producer FUNCTION.
- **Docs:** `docs/edge-types.md` — `data_flows` section (:25-34), reader section (:73-75).

## Steps (build order)

### 1. New E2E oracle `internal/cli/cli_dataflow_inbody_e2e_test.go`
- Build tag `!windows`, pkg `cli_test`, HELIX_BIN-gated (reuse `newE2EFixture`'s skip).
- Add a helper `dataFlowEdgesOf(res explainDeepResult) []explainEdge` (mirror `hasTypeEdges`,
  filter `EdgeKind=="data_flows"`, scan both directions).
- **Fixture table** — one entry per language `{lang, filename, src, consumerParam, negParam?}`.
  Each `src` defines top-level `producer()` (returns a value), `sink(param)` (takes one), and a
  `caller()` body `local := producer(); sink(local)` PLUS a negative arm (a second sink call
  with a literal / pure value that yields NO in-body edge). Idiomatic per language; class-wrapped
  for Java/C#/Kotlin so producer/sink/caller are resolvable. Filenames: `.go .ts .java .cs .rs
  .php .py .rb .kt .c .cpp`.
- **`TestCLI_E2E_InBodyDataFlow`** — a subtest per language (`t.Run(lang, ...)`):
  - `newE2EFixture` + overwrite seed with the language file (a per-language fixture builder like
    `newCTypeE2EFixture`); `mcpActivate` → `switchModeReview` → `indexFull`.
  - HEADLINE (assert FIRST): `explainSymbol(seed, consumerParam)` → `dataFlowEdgesOf` contains ≥1
    edge whose endpoints are function→param (the producer→consumer.param in-body edge). Assert
    `internal_kind=="DATA_FLOWS"`. Seed resolves `exact` (non-vacuous).
  - DIFFERENTIAL negative: a param/symbol with no in-body inflow yields 0 in-body data_flows edges
    while resolving `exact`.
  - A language that does not resolve E2E ⇒ `t.Skip(reason)` INSIDE its subtest — reason recorded,
    carried from Phase-138's FLOW-04i ledger. GOAL: 11/11 green; each skip justified in SUMMARY.

### 2. Function-seeded multi-hop through the binary (FLOW-06c, M2) — same file
- `TestCLI_E2E_InBodyMultiHop` (Go, the safe proven language): fixture with `src()` (returns),
  `transform(x)` (returns x — the return-bridge), `sink(v)`, and `caller(){ a:=src(); b:=transform(a);
  sink(b) }`. Activate/review/index.
- Run `trace-data-flow --seed-json={file_path:abs, symbol_name:"src"}` (the producer FUNCTION seed
  — mechanically accepted) as a REAL subprocess; parse the result; assert `sink` (or its param) is
  in the reachable set. Broken-hop guard: a variant fixture where `transform` does NOT return x
  (breaks the bridge) → sink NOT reachable (revert-and-fail RED).
- If the `trace-data-flow` result shape needs a small parse struct, add it (mirror
  `explainDeepResult`). Do NOT change the verb.

### 3. Determinism (FLOW-06d) — in TestCLI_E2E_InBodyDataFlow (Go subtest at least)
- Re-`indexFull`; re-`explainSymbol`; assert the in-body data_flows edge set (count + endpoints)
  is identical across re-index.

### 4. Docs (FLOW-06e) — `docs/edge-types.md`
- Update the `data_flows` section (:25-34): it is no longer only `def_use` param→param. Add the two
  new Source markers: `def_use_inbody` (producer.function → consumer.param — the return of an
  in-body call flows into a later call arg; v2.13) and `def_use_return` (param → enclosing-function
  — the multi-hop return-bridge; v2.13). Note in-body origins are now modeled (variable-level nodes
  / field-heap flow / source-sink taint remain deferred). Update the reader section (:73-75): a
  function seed may now reach in-body targets (full function-seed verb support is a fast-follow).
- Keep the doc honest: state the per-language proven set (from the E2E ledger) and the deferred
  surfaces.
