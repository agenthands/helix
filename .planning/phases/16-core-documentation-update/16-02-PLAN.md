**# Contributing to Serena**

Opening paragraph: Thank you, scope of contributions (same as current: isolated additions via PR, larger changes via issue first).

**## Prerequisites**
- Go 1.23+ (check go.mod for exact version)
- Language servers for testing (at minimum: gopls for Go fixture tests)
- protoc + protoc-gen-go + protoc-gen-go-grpc (only if modifying gRPC protos)

**## Development Commands**
Table or list of all commands:
- `go build ./cmd/serena` — Build the serena binary
- `go test ./...` — Run all tests
- `go vet ./...` — Run static analysis
- `gofmt -w .` — Format code
- `make build` — Build via Makefile
- `make test` — Run tests via Makefile
- `make docs` — Regenerate tool and language tables in README.md
- `make proto` — Regenerate gRPC protobuf code (only if modifying `api/proto/`)

Note: "Always run `go vet` and `go test` before submitting a PR."

**## Project Structure**
Brief orientation of the 4-layer directory layout:
- `cmd/serena/` — CLI entry point
- `internal/mcp/` — MCP runtime (Layer 0)
- `internal/daemon/` — Persistent daemon (Layer 0)
- `internal/forwarder/` — Stdio-to-gRPC proxy (Layer 0)
- `internal/kernel/` — Code intelligence kernel (Layer 1)
- `internal/kernel/lspool/` — LS worker pool
- `internal/kernel/symbols/` — Symbol retrieval tools
- `internal/kernel/edit/` — Symbol editing tools
- `internal/kernel/fileops/` — File operation tools
- `internal/kernel/diag/` — Diagnostic tools
- `internal/skill/` — Skill plugin system (Layer 2)
- `internal/langregistry/` — 52-language registry (Layer 2)
- `internal/profile/` — Agent profiles (Layer 3)
- `internal/config/` — Layered configuration (Layer 3)
- `internal/obs/` — Observability (metrics, tracing, admin)
- `internal/degrade/` — Graceful degradation
- `api/proto/serena/v1/` — gRPC IPC definitions
- `protocol/gen/` — Generated LSP 3.17 types
- `test/integration/` — MCP round-trip integration tests
- `test/bench/` — Benchmark suite

**## Running Integration Tests**
Explain the Go integration test harness:
- Location: `test/integration/`
- The harness starts a real Serena daemon with a Go fixture project
- Run all integration tests: `go test ./test/integration/ -v -timeout 120s`
- Run a specific test: `go test ./test/integration/ -run TestSymbolRetrieval -v`
- The harness uses `testing.TB` interface, shared by both integration tests and benchmarks
- Tests exercise MCP round-trips via stdio transport against live language servers
- Fixtures are in `test/integration/` (Go) with additional language fixtures available
- Note: Integration tests require gopls installed. Tests for other languages require their respective language servers.

**## Running Benchmarks**
Explain the benchmark harness:
- Location: `test/bench/`
- Run all benchmarks: `go test -bench=. ./test/bench/ -timeout 300s`
- Run a specific benchmark: `go test -bench=BenchmarkTools ./test/bench/ -timeout 300s`
- Benchmarks use `testing.B.Loop` (Go 1.24+) to prevent compiler elision
- Baselines committed in `test/bench/baselines/`
- CI runs benchstat regression gate via `.github/workflows/bench.yml`
- PR thresholds: >15% time regression or >25% allocs regression blocks merge
- Release thresholds: >10% time or >20% allocs

**## Adding a New MCP Tool**
Step-by-step walkthrough:
1. Choose the right layer: kernel tools go in `internal/kernel/{category}/`, skill tools go in `internal/skill/{name}/`
2. For kernel tools: implement the tool function, register via `RegisterTools(server *mcp.SerenaMCPServer, ...)` using `mcpsdk.AddTool`
3. For skill tools: implement `ToolProvider` interface with `Tools() []*mcp.ToolDef`, register skill via `init()` function calling `skill.Register(&MySkill{})`
4. Add the tool to the appropriate profile YAML files in `internal/profile/profiles/`
5. Run `make docs` to regenerate the README tool table
6. Add integration test coverage in `test/integration/`
7. Run `go test ./...` and `go vet ./...`

**## Adding Language Support**
- Language definitions live in `internal/langregistry/languages.yaml`
- See the memory guide: `.serena/memories/adding_new_language_support_guide.md`
- After adding, run `make docs` to regenerate the README language table

**## Benchmark CI Gate**
Explain how the benchmark gate works:
- `.github/workflows/bench.yml` runs on PRs
- Compares PR benchmarks against committed baselines via benchstat
- Uses tiered thresholds (PR vs release)
- `.github/workflows/capture-baseline.yml` captures new baselines (manual dispatch)

**## Scope of Contributions**
(Keep from current CONTRIBUTING): Isolated additions, small bug fixes, documentation improvements via PR. Larger changes: open issue first. One logical change per PR.
