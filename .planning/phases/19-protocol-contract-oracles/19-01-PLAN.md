**TestHandshake_InMemory** (per D-01):
- Start runner with `harness.RunnerOptions{SkipLS: true}` (no workspace needed for handshake)
- Call `runner.Session.InitializeResult()` to get `*mcp.InitializeResult`
- Assert: `result != nil`, `result.ProtocolVersion != ""`, `result.ServerInfo != nil`, `result.ServerInfo.Name == "serena"`, `result.Capabilities != nil`, `result.Capabilities.Tools != nil`

**TestHandshake_HTTP** (per D-01):
- Start runner with `harness.RunnerOptions{SkipLS: true}`
- Create HTTP session via `runner.NewHTTPSession(t)`
- Call `httpSession.InitializeResult()` -- assert same fields as InMemory
- Make one representative tool call: call `list_memories` via `httpSession.CallTool(ctx, &mcp.CallToolParams{Name: "list_memories", Arguments: map[string]any{}})` -- proves HTTP transport round-trip
- Assert `result.IsError == false` and response has content

**TestHandshake_ProtocolVersionMatch**:
- Start runner, get InitializeResult from InMemory session
- Start HTTP session against same daemon, get InitializeResult from HTTP session
- Assert both return identical ProtocolVersion and ServerInfo.Name

Create `test/oracle/protocol/session_isolation_test.go` (package `protocol_test`, build tag `//go:build integration || llm || llmjudge`):

**TestSessionIsolation_WorkspaceIndependence** (per D-02):
- Two separate `harness.StartRunner` instances (each creates its own daemon -- per Pitfall 3, single daemon is single-workspace)
- Runner A: `harness.RunnerOptions{WorkspaceDir: harness.PrepareFixture(t, "go"), SkipLS: true}`
- Runner B: `harness.RunnerOptions{SkipLS: true}` (no workspace activated)
- Call `harness.CallTool(t, runnerA.Session, "list_directory", map[string]any{"path": "."})` -- should succeed (workspace active)
- Call `harness.CallToolExpectError(t, runnerB.Session, "list_directory", map[string]any{"path": "."})` -- should fail (no workspace)
- This proves workspace state is independent across daemon instances

**TestSessionIsolation_ModeRestrictions** (per D-02):
- Runner A: `harness.RunnerOptions{SkipLS: true, Mode: "read"}` -- read mode
- Runner B: `harness.RunnerOptions{SkipLS: true, Mode: "admin"}` -- admin mode (or default "edit")
- List tools on both sessions via `harness.ListSessionTools(t, runner.Session)`
- Assert: Runner A's tool list does NOT contain edit tools (e.g., `replace_symbol_body`, `insert_before_symbol`)
- Assert: Runner B's tool list DOES contain edit tools
- Use `slices.Contains` or manual loop to check tool name presence

**TestSessionIsolation_MemoryIndependence**:
- Two separate StartRunner instances
- Runner A: write a memory `harness.CallTool(t, runnerA.Session, "write_memory", map[string]any{"name": "test-iso", "content": "runner-a"})`
- Runner B: call `harness.CallToolExpectError(t, runnerB.Session, "read_memory", map[string]any{"name": "test-iso"})` or check that it returns different/empty content
- This proves memory stores are independent across daemon instances

Create `test/oracle/protocol/reconnect_test.go` (package `protocol_test`, same build tag):

**TestReconnect_DaemonStatePreserved** (per D-03):
- Start runner with `harness.RunnerOptions{SkipLS: true}`
- Write a memory: `harness.CallTool(t, runner.Session, "write_memory", map[string]any{"name": "persist-test", "content": "before-disconnect"})`
- Close the MCP client session: `runner.Session.Close()`
- Create a new session against the same daemon: `newSession := runner.NewHTTPSession(t)`
- Read the memory via the new session: call `read_memory` with name `persist-test` on `newSession`
- Assert the content contains `"before-disconnect"` -- daemon state was preserved across client reconnect

**TestReconnect_NoWorkerLeakage** (per D-03):
- Start runner with `harness.RunnerOptions{SkipLS: true}`
- Record initial state (tool list should be available)
- Close session: `runner.Session.Close()`
- Create new HTTP session: `newSession := runner.NewHTTPSession(t)`
- List tools on new session -- assert not empty, proves daemon is functional
- Call a tool on new session to prove it works end-to-end

**TestReconnect_MultipleReconnects**:
- Start runner with `harness.RunnerOptions{SkipLS: true}`
- Loop 3 times: close session, create new HTTP session, list tools, assert not empty
- Proves daemon handles repeated connect/disconnect cycles without degradation

Use `testify/require` for all assertions. Defer `runner.Stop()` on all runners.
