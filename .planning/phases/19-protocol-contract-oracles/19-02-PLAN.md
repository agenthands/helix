**Helper function `compileMetaSchema(t *testing.T) *jsonschema.Schema`:**
- `c := jsonschema.NewCompiler()`
- `c.DefaultDraft(jsonschema.Draft2020)` -- ensures local resolution, no network fetch (Pitfall 2)
- `sch, err := c.Compile("https://json-schema.org/draft/2020-12/schema")`
- `require.NoError(t, err, "failed to compile Draft 2020-12 meta-schema")`
- Return `sch`

**Helper function `listAllTools(t *testing.T) ([]*mcp.Tool, *harness.Runner)`:**
- Start runner with `harness.RunnerOptions{SkipLS: true}` -- full profile, admin mode gives all tools (Pitfall 5)
- `ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)`; defer cancel
- `result, err := runner.Session.ListTools(ctx, &mcp.ListToolsParams{})`
- `require.NoError(t, err)`
- Return `result.Tools, runner`

**TestSchema_InputSchemaValidDraft2020** (per D-08, D-09 -- schema-validation path):
- Get meta schema via `compileMetaSchema(t)`
- Get all tools via `listAllTools(t)`
- For each tool, `t.Run(tool.Name+"_inputSchema", func(t *testing.T) {...})`:
  - `require.NotNil(t, tool.InputSchema, "inputSchema must not be nil for %s", tool.Name)`
  - `err := meta.Validate(tool.InputSchema)` -- per Pitfall 1, InputSchema is `any` (map[string]any), pass directly
  - `require.NoError(t, err, "inputSchema for %s is not valid Draft 2020-12", tool.Name)`

**TestSchema_OutputSchemaValidDraft2020** (per D-08):
- Get meta schema, get all tools
- For each tool where `tool.OutputSchema != nil`:
  - `t.Run(tool.Name+"_outputSchema", func(t *testing.T) {...})`
  - `err := meta.Validate(tool.OutputSchema)`
  - `require.NoError(t, err, "outputSchema for %s is not valid Draft 2020-12", tool.Name)`
- If no tool has outputSchema, the test still passes (no false failures per D-08)

**TestSchema_InputSchemaIsObject**:
- Get all tools
- For each tool, type-assert `tool.InputSchema` to `map[string]any`
- Assert it contains key `"type"` with value `"object"` -- all MCP tool schemas define object-typed inputs
- Assert it contains key `"properties"` (at minimum)

**TestSchema_RequiredFieldsExist**:
- Get all tools
- For each tool, get `InputSchema.(map[string]any)`
- If schema has `"required"` key, assert each required field name exists in `"properties"` map
- This cross-references declared required fields against actual schema properties (per CONT-02 "cross-referenced against actual accepted arguments")

Import: `context`, `strings`, `testing`, `time`, `github.com/modelcontextprotocol/go-sdk/mcp`, `github.com/stretchr/testify/assert`, `github.com/stretchr/testify/require`, `github.com/postfix/serena/test/harness`

**Package-level variable `actionVerbs`** (per D-11):
```go
var actionVerbs = []string{
    "activate", "analyze", "create", "delete", "edit", "find", "format",
    "get", "go", "insert", "list", "onboard", "prepare", "read", "rename",
    "replace", "retrieve", "safe", "search", "switch", "verify", "write",
}
```

**Helper function `hasActionVerb(desc string) bool`:**
- Lowercase the description
- Check if any verb from `actionVerbs` is contained in the lowered description
- Return true if found

**Helper function `listToolsWithMeta(t *testing.T) []*mcp.Tool`:**
- Start runner with `harness.RunnerOptions{SkipLS: true}`
- List tools via `runner.Session.ListTools(ctx, &mcp.ListToolsParams{})` with 10s timeout
- Return `result.Tools`

**TestSelectability_ActionVerbs** (per D-11 -- positive selection):
- Get all tools via `listToolsWithMeta(t)`
- For each tool, `t.Run(tool.Name, func(t *testing.T) {...})`:
  - `assert.True(t, hasActionVerb(tool.Description), "description for %s should contain an action verb: %q", tool.Name, tool.Description)`

**TestSelectability_UniqueDescriptions** (per D-11 -- disambiguation):
- Get all tools
- Collect all descriptions into `seen := map[string]string{}` (description -> tool name)
- For each tool: if description already in `seen`, fail: `t.Errorf("duplicate description between %s and %s: %q", seen[tool.Description], tool.Name, tool.Description)`

**TestSelectability_MinimumLength**:
- Get all tools
- For each tool: `assert.Greater(t, len(tool.Description), 20, "description for %s is too short to be LLM-selectable: %q", tool.Name, tool.Description)`

**TestSelectability_Disambiguation** (per D-11 -- similar tool pairs):
- Define similar tool pairs that must be distinguishable:
```go
similarPairs := [][2]string{
    {"search_symbols", "find_references"},
    {"get_symbol_overview", "get_hover_info"},
    {"read_file", "read_memory"},
    {"write_file", "write_memory"},
    {"find_files", "search_in_files"},
    {"list_directory", "find_files"},
    {"insert_before_symbol", "insert_after_symbol"},
}
```
- Build a `map[string]string` of tool name to description from the tools list
- For each pair, `t.Run(pair[0]+"_vs_"+pair[1], func(t *testing.T) {...})`:
  - Get descriptions for both tools (skip if either tool not found -- profile may filter)
  - Split each description into word sets (lowercase, split on spaces/punctuation)
  - Calculate Jaccard similarity: `intersection / union` of word sets
  - Assert Jaccard similarity < 0.7 -- descriptions must be sufficiently different
  - Also assert each description contains at least one word NOT in the other (they have distinguishing terms)

**TestSelectability_NegativeSelection**:
- For each tool, assert the description does NOT contain misleading terms:
  - Description should not contain "TODO", "placeholder", "not implemented", "deprecated"
  - `assert.NotContains(t, strings.ToLower(tool.Description), "todo")`
  - `assert.NotContains(t, strings.ToLower(tool.Description), "placeholder")`
  - `assert.NotContains(t, strings.ToLower(tool.Description), "not implemented")`
  - `assert.NotContains(t, strings.ToLower(tool.Description), "deprecated")`
