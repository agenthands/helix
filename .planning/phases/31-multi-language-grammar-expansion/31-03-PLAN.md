**PART A: Create 5 tag query files**

Apply same adaptation rules: `@name.definition.X` -> `@name`, strip predicates, strip `@doc`.

**`internal/repomap/queries/lua_tags.scm`** -- Adapted from tree-sitter-language-pack lua-tags.scm:
```scheme
(function_declaration
  name: [(identifier) @name
         (dot_index_expression field: (identifier) @name)]) @definition.function

(function_declaration
  name: (method_index_expression
    method: (identifier) @name)) @definition.method

(assignment_statement
  (variable_list
    name: [(identifier) @name
           (dot_index_expression field: (identifier) @name)])
  (expression_list
    value: (function_definition))) @definition.function

(function_call
  name: [(identifier) @name
         (dot_index_expression field: (identifier) @name)
         (method_index_expression method: (identifier) @name)]) @reference.call
```
Note: Strip `table_constructor` field function pattern -- may cause issues with tree-sitter query compilation.

**`internal/repomap/queries/zig_tags.scm`** -- Adapted from aider zig-tags.scm. The aider query uses `(FnProto)` which is unusual (PascalCase node names). Verify against the actual zig grammar node types. If the grammar uses lowercase, adjust accordingly.
```scheme
; Zig grammar may use PascalCase or lowercase node types
; Try this first; if it fails, inspect the grammar's node-types.json
(FnProto) @name @definition.function
```
IMPORTANT: The aider zig query is extremely terse and uses `(FnProto)` as a bare node match without field extraction. This may NOT work with Serena's extractor which expects separate `@name` and `@definition.X` captures. If the Zig grammar uses `(FnProto name: (IDENTIFIER) @name) @definition.function` or similar, use that instead. If no name field exists on `FnProto`, try:
```scheme
(function_declaration
  name: (identifier) @name) @definition.function
```
Test query compilation empirically. Start with simple patterns and iterate.

**`internal/repomap/queries/hcl_tags.scm`** -- Adapted from aider hcl-tags.scm. The HCL/Terraform query is complex with `#eq?` predicates. The `#eq?` predicate IS a standard tree-sitter predicate (unlike `#strip!`), so it should compile. Adapt:
```scheme
(block
  (identifier) @_block_type
  (string_lit (template_literal) @_resource_type)
  (string_lit (template_literal) @name)
  (body)) @definition.module
```
Note: The aider query uses `#eq?` to filter block types. Since go-tree-sitter may not fully support `#eq?` predicate matching, simplify to capture all blocks. If `#eq?` IS supported, use:
```scheme
(block
  (identifier) @_block_type
  (string_lit (template_literal) @name)
  (body) @definition.module
  (#eq? @_block_type "resource"))
```
Test both variants. If neither compiles, fall to a minimal query:
```scheme
(block
  (identifier) @name) @definition.module
```

**`internal/repomap/queries/swift_tags.scm`** -- Adapted from tree-sitter-language-pack swift-tags.scm:
```scheme
(class_declaration
  name: (type_identifier) @name) @definition.class

(protocol_declaration
  name: (type_identifier) @name) @definition.interface

(function_declaration
  name: (simple_identifier) @name) @definition.function
```
Note: Strip the complex nested method extraction patterns (class_body -> function_declaration etc.) as they create `@definition.method` on the outer class node which is semantically wrong for Serena's extractor. Keep only top-level patterns.

**`internal/repomap/queries/r_tags.scm`** -- Adapted from tree-sitter-language-pack r-tags.scm:
```scheme
(binary_operator
  lhs: (identifier) @name
  operator: "<-"
  rhs: (function_definition)) @definition.function

(binary_operator
  lhs: (identifier) @name
  operator: "="
  rhs: (function_definition)) @definition.function

(call
  function: (identifier) @name) @reference.call
```
