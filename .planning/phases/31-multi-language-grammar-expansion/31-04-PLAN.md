**Step 1: Create R binding (`internal/treesitter/bindings/r/`)**

The upstream `github.com/r-lib/tree-sitter-r` binding omits scanner.c from CGO includes. Fix by copying C source files and creating a corrected binding.go.

1a. Create directory `internal/treesitter/bindings/r/`
1b. Copy C source files from the upstream module cache:
    ```bash
    cp ~/go/pkg/mod/github.com/r-lib/tree-sitter-r@v1.2.0/src/parser.c internal/treesitter/bindings/r/
    cp ~/go/pkg/mod/github.com/r-lib/tree-sitter-r@v1.2.0/src/scanner.c internal/treesitter/bindings/r/
    mkdir -p internal/treesitter/bindings/r/tree_sitter/
    cp ~/go/pkg/mod/github.com/r-lib/tree-sitter-r@v1.2.0/src/tree_sitter/*.h internal/treesitter/bindings/r/tree_sitter/
    ```
1c. Create `internal/treesitter/bindings/r/binding.go`:
    ```go
    package tree_sitter_r

    // #cgo CFLAGS: -std=c11 -fPIC
    // #include "parser.c"
    // #include "scanner.c"
    import "C"

    import "unsafe"

    // Language returns the tree-sitter Language for R.
    func Language() unsafe.Pointer {
        return unsafe.Pointer(C.tree_sitter_r())
    }
    ```
    Note: includes are relative to the binding.go file (NOT ../../src/ like upstream).

**Step 1: Create R tag query (`internal/repomap/queries/r_tags.scm`)**

Adapt from `borrow/aider/aider/queries/tree-sitter-language-pack/r-tags.scm` using Serena capture convention.

Aider source:
```scheme
(binary_operator
    lhs: (identifier) @name.definition.function
    operator: "<-"
    rhs: (function_definition)
) @definition.function

(binary_operator
    lhs: (identifier) @name.definition.function
    operator: "="
    rhs: (function_definition)
) @definition.function

(call
    function: (identifier) @name.reference.call
) @reference.call

(call
    function: (namespace_operator
        rhs: (identifier) @name.reference.call
    )
) @reference.call
```

Convert to Serena format (strip `.definition.X` / `.reference.X` from `@name` captures):
```scheme
; Definitions
(binary_operator
    lhs: (identifier) @name
    operator: "<-"
    rhs: (function_definition)) @definition.function

(binary_operator
    lhs: (identifier) @name
    operator: "="
    rhs: (function_definition)) @definition.function

; References
(call
    function: (identifier) @name) @reference.call

(call
    function: (namespace_operator
        rhs: (identifier) @name)) @reference.call
```

**Step 2: Create Swift tag query (`internal/repomap/queries/swift_tags.scm`)**

Adapt from `borrow/aider/aider/queries/tree-sitter-language-pack/swift-tags.scm` using Serena capture convention.

Convert to Serena format:
```scheme
; Definitions
(class_declaration
  name: (type_identifier) @name) @definition.class

(protocol_declaration
  name: (type_identifier) @name) @definition.interface

(function_declaration
    name: (simple_identifier) @name) @definition.function

(class_declaration
    (class_body
        (function_declaration
            name: (simple_identifier) @name))) @definition.method

(class_declaration
    (class_body
        (property_declaration
            (pattern (simple_identifier) @name)))) @definition.property

(property_declaration
    (pattern (simple_identifier) @name)) @definition.property
```

NOTE: The aider query has complex nested patterns for protocol methods, init/deinit, and subscript declarations. Start with the simpler subset above. If any pattern causes a tree-sitter query compilation error (because the Swift grammar node types differ), remove the failing pattern and log a warning. Use the error-tolerant compilation pattern already established in Phase 31.

**Step 3: Create R body query (`internal/kernel/edit/queries/r.scm`)**

R functions are assigned via `<-` or `=`, not declared with a keyword. The function_definition node has a body field. Create:
```scheme
; R function definitions for body extraction
; R functions: name <- function(...) { body }
(function_definition
  body: (_) @body) @definition.function
```

NOTE: R does not have a `name` field on `function_definition` — the name comes from the `binary_operator` parent's `lhs`. The body query only needs `@body` capture for body extraction. If the grammar does not support this pattern, skip R body extraction (add no langConfig entry) — R functions rarely need body-level surgery.

**Step 4: Create Swift body query (`internal/kernel/edit/queries/swift.scm`)**

Swift has function_declaration with body (function_body), class_declaration with body (class_body).
```scheme
; Swift declaration types for body extraction
(function_declaration
  name: (simple_identifier) @name
  body: (function_body) @body)

(class_declaration
  name: (type_identifier) @name
  body: (class_body) @body)
```

If the field name is not "body" in the Swift grammar (check by parsing a Swift file), adjust. The Swift grammar may use unnamed children — check node types with `tree-sitter parse`.
