**2. BuildToolSchemaMap(tools []*mcpsdk.Tool) *ToolSchemaMap:**
Per D-07/D-08 and RESEARCH.md Pattern 2 (lines 176-219):
- Iterate tools, marshal `Tool.InputSchema` to JSON via `json.Marshal`, unmarshal to `map[string]any`
- Extract `properties` key as `map[string]any`, collect property names into `ValidParams`
- For each property, check if it has an `enum` key with `[]any` value; if so, extract string values into `EnumValues[paramName]`
- Set `maxDistance` to 2
- Skip tools whose schema fails to parse (continue, don't error)
- Return `*ToolSchemaMap`

**3. enrichProtocolError(req mcpsdk.Request, result mcpsdk.Result, err error) (mcpsdk.Result, error):**
Per RESEARCH.md Pitfall 1 and Pitfall 3:
- Extract tool name via `extractToolName(req)` (reuse from middleware.go)
- Look up tool in `schemaMap.tools[toolName]`; if not found, return original `(result, err)`
- Call `extractBadParams(err.Error())` to get bad parameter names
- For each bad param, call `bestParamSuggestion(badParam, info.ValidParams, schemaMap.maxDistance)`
- If a match is found (distance <= maxDistance), format suggestion per D-04/D-05: `err.Error() + "\nDid you mean: " + suggestion + " (instead of " + badParam + ")?"`
- Per D-06: only include the single best suggestion (lowest distance across all bad params)
- Per Pitfall 3: convert to `*mcpsdk.CallToolResult{IsError: true, Content: [TextContent{enrichedMsg}]}` and return `(result, nil)` -- converting protocol error to tool error
- If no suggestion found, return original `(result, err)` unchanged

**4. enrichToolError(req mcpsdk.Request, ctr *mcpsdk.CallToolResult):**
Per D-03 (intercept IsError=true):
- Extract tool name via `extractToolName(req)`
- Look up tool in `schemaMap.tools[toolName]`; if not found, return (no-op)
- Extract text from first TextContent in `ctr.Content`
- Try enum value correction: scan error text for patterns like `invalid value "X" for field "Y"` or similar. For each param with known enum values, check if the error text mentions the param name. If found, call `bestValueSuggestion(badValue, validValues, maxDistance)`.
- Try parameter name suggestions: call `extractBadParams` on the error text (may not match SDK format but worth trying)
- If suggestion found, per D-04: append `"\nDid you mean: " + suggestion + " (instead of " + badValue + ")?"` to the existing TextContent text. Never mutate the original text -- create new text = original + "\n" + suggestion line.
- Per D-06: only the top 1 best suggestion
- Update `ctr.Content[0]` with the enriched text

**5. SuggestionMiddleware(schemaMap *ToolSchemaMap, logger *slog.Logger) mcpsdk.Middleware:**
Per D-03, RESEARCH.md Pattern 1, and PATTERNS.md middleware pattern:
```go
func SuggestionMiddleware(schemaMap *ToolSchemaMap, logger *slog.Logger) mcpsdk.Middleware {
    return func(next mcpsdk.MethodHandler) mcpsdk.MethodHandler {
        return func(ctx context.Context, method string, req mcpsdk.Request) (mcpsdk.Result, error) {
            if method != "tools/call" {
                return next(ctx, method, req)
            }
            result, err := next(ctx, method, req)
            if err != nil {
                return schemaMap.enrichProtocolError(req, result, err)
            }
            if ctr, ok := result.(*mcpsdk.CallToolResult); ok && ctr != nil && ctr.IsError {
                schemaMap.enrichToolError(req, ctr)
            }
            return result, err
        }
    }
}
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-01 | Information Disclosure | SuggestionMiddleware | accept | Suggestions only reference parameter names from the tool's public JSON Schema -- no internal state, secrets, or implementation details are exposed. Parameter names are already visible in tools/list responses. |
| T-37-02 | Denial of Service | levenshteinDistance | accept | Levenshtein is O(n*m) but parameter names are bounded (<50 chars) and the tool count is bounded (~42 tools). Total computation per error is negligible -- no amplification vector. |
| T-37-03 | Tampering | enrichProtocolError | mitigate | Middleware only appends text to error responses, never modifies request flow or tool dispatch. The `extractBadParams` parser uses defensive string matching (strings.Index + Trim), not regex or eval. No user-controlled input is executed. |
| T-37-04 | Spoofing | ToolSchemaMap | accept | Schema map is built once at startup from server-registered tools -- not from client input. Cannot be influenced by agent requests. |
</threat_model>
