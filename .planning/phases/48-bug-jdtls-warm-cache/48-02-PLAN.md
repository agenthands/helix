    ```go
    // ExtraArgs injects -data <dir> so jdtls has a workspace-specific data directory.
    // Without this, jdtls may fail to index or conflict across workspaces.
    //
    // Test-only override: if the environment variable SERENA_TEST_JDTLS_DATA_DIR is set
    // to a non-empty path, it is used verbatim in place of workDir/.jdtls-data. This
    // lets integration tests (test/integration/jdtlscache) share a warm jdtls workspace
    // across test runs (Phase 48, BUG-03). Production never sets this variable.
    func (j *JdtlsAdapter) ExtraArgs(workDir string, args []string) []string {
        dataDir := os.Getenv("SERENA_TEST_JDTLS_DATA_DIR")
        if dataDir == "" {
            dataDir = filepath.Join(workDir, ".jdtls-data")
        }
        _ = os.MkdirAll(dataDir, 0o755)
        return append([]string{"-data", dataDir}, args...)
    }
    ```

Production deployments run under supervisors (systemd/launchd) with controlled environments. Risk bounded to local user who already controls the jdtls process. Document in code comment and USAGE.md (Plan 05). |
| T-48-02-02 | Information Disclosure | Malicious env value points to existing dir containing sensitive files | accept | jdtls writes its index to the dir; it does not exfiltrate pre-existing contents. Data dir is controlled by the calling user — standard local-user trust boundary. No new disclosure surface. |
| T-48-02-03 | Elevation of Privilege | Env var used to write into privileged path (e.g. `/etc`) | accept | `os.MkdirAll(dir, 0o755)` respects the invoking user's umask and cannot escalate. Failures are silent (`_ =`) — consistent with existing behavior. |
| T-48-02-04 | Spoofing | Non-absolute path smuggled via env var | accept | `os.MkdirAll` handles relative paths by resolving against cwd; jdtls accepts either. No spoofing surface — the jdtls process still indexes the path it was given. Documented expectation: callers (test harness Plan 03) pass absolute paths from `jdtlscache.ResolveDataDir`. |
| T-48-02-05 | Denial of Service | Env var points to non-writable dir, `os.MkdirAll` fails | accept | Current code already ignores MkdirAll error (`_ =`). Failure surfaces as jdtls startup error downstream — no new failure mode. |
