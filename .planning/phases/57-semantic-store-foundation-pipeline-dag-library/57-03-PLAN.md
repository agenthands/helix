## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| project YAML (`.helix/project.yml`) → SerenaConfig | Workspace-local config file under user's directory; could be untrusted if workspace is opened from a foreign repo. |
| user YAML (`~/.helix/helix_config.yml`) → SerenaConfig | User-owned; trusted. |
| CLI flag overrides → SerenaConfig | User-supplied; trusted. |

## STRIDE Threat Register (ASVS L1)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-03-01 | T (Tampering) | malicious project YAML sets `semantic_index.store.path` to traverse outside workspace | mitigate | Path traversal defense lives in P02 (`Open` validates `cfg.Store.Path` is local + does not contain `..`). Config layer trusts the path string; the store layer is the boundary that validates it. Cross-reference T-57-02-01. |
| T-57-03-02 | T (Tampering) | malicious project YAML sets `semantic_index.indexing.max_files` extremely high to force OOM | accept | Existing `degradation.memory_limit_mb` + GOMEMLIMIT bound process memory. SPEC §25 defaults are reasonable; hostile projects can already crash the process with other config knobs (e.g., `worker_pool.max_workers`). |
