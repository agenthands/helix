## VERDICT: FALLBACK-B-MULTI-BUILD-ID

The OSS CLI at v2.15.4 (and across the entire v2.15.x line) does **not** support the
`partial.by_target` config stanza, the `goreleaser release --split` invocation, or
the `goreleaser continue` / `goreleaser release --merge` reassembly step.

We therefore take **Fallback Option B** (planner-documented in `<canon>` + RESEARCH
Risks > MEDIUM A11): keep the v2.15.4 SHA pin as-is, refactor `.goreleaser.yaml` to use
**multiple `builds:` entries** (one per runner) with `id:` filtering, and have each
runner invoke `goreleaser build --id <runner-id>` with `--single-target` semantics
expressed via the per-build `goos`/`goarch` lists. The merge job runs `goreleaser
release --skip-build` to assemble archives, checksums, and signatures from the
pre-built binaries.

Fallback Option A (bump goreleaser pin to a Pro-equipped version) is **rejected**
because GoReleaser Pro is a paid commercial product, not a different OSS tag.

## EXACT INCANTATION (Wave 3 will execute these)

### Linux runner (ubuntu-22.04) — builds linux/{amd64,arm64} + windows/{amd64,arm64}

```bash

# Or for the gated reproducibility passes (Wave 5):
goreleaser build --snapshot --clean --id helix-non-darwin --output dist-pass-1/
goreleaser build --snapshot --clean --id helix-non-darwin --output dist-pass-2/
```

### macOS runner (macos-14) — builds darwin/{amd64,arm64}

```bash
goreleaser build --snapshot --clean --id helix-darwin
# Or (Wave 5 reproducibility passes):
goreleaser build --snapshot --clean --id helix-darwin --output dist-pass-1/
goreleaser build --snapshot --clean --id helix-darwin --output dist-pass-2/
```

### Merge job (linux runner, after both runners' artifacts are uploaded)

The merge job downloads both `dist-partial-*` artifact bundles into a single `dist/`,
then runs:

```bash
goreleaser release --snapshot --clean --skip=build,sign \
                   --release-footer-tmpl /dev/null      # archives, checksums.txt only
# Followed by the existing cosign keyless attestation pass over all 6 archives
# (the signs: block in .goreleaser.yaml runs unchanged here because --skip=sign is
# OMITTED on the actual tag-push merge; the snapshot variant skips sign by design).
```

For **real (non-snapshot) tag-push merges** the merge job invocation is:

```bash
goreleaser release --clean --skip=build         # build is already done; sign + publish run
```

The `--skip=build` flag is enumerated in the OSS `release --help` (see Probe path A
above — it's in the comma-separated `--skip` list), so this is a fully-supported OSS
mechanic.

**Note (planner discretion → Wave 3):** The exact way to materialize "pre-built binaries
in dist/" so that `release --skip=build` finds them is via the upload-artifact /
download-artifact pair on `dist/` itself; goreleaser writes its expected layout
(`dist/helix_<id>_<os>_<arch>/helix[.exe]`) during `goreleaser build`, and that layout
is what the merge job needs to see. Wave 3's `release.yml` author confirms layout
shape via a test run.

## CONFIG STANZA (Task 2 inserts this into `.goreleaser.yaml`)

Because we are on Fallback B (no `partial:` stanza available in OSS), Task 2 does NOT
insert a top-level `partial:` block. Instead Task 2 refactors the single `builds:`
entry into **two** entries with explicit `id:` per runner:

```yaml
# D-15 split-runner pipeline implemented via the goreleaser OSS multi-build-entry
# pattern (Fallback B per 59.1-02-SPLIT-PROBE-NOTES.md — split/merge is GoReleaser
# Pro only at v2.15.4 and we are not on Pro). Each runner invokes
# `goreleaser build --id <runner-id> --snapshot --clean`; the merge job runs
# `goreleaser release --skip=build` to assemble archives + checksums + signatures
# from the pre-built binaries uploaded by both runners.

builds:
  - id: helix-non-darwin
    main: ./cmd/helix
    binary: helix
    goos: [linux, windows]
    goarch: [amd64, arm64]
    env:
      - CGO_ENABLED=1
      - GOFLAGS=-mod=readonly
      # D-01 amended: zig cc covers linux+windows ONLY. Templated per-target CC
      # via Go-template conditionals on .Os and .Arch (Pattern A4).
      - >-
        {{- if eq .Os "linux" }}
          {{- if eq .Arch "amd64" }}CC=zig cc -target x86_64-linux-musl{{- end }}
          {{- if eq .Arch "arm64" }}CC=zig cc -target aarch64-linux-musl{{- end }}
        {{- else if eq .Os "windows" }}
          {{- if eq .Arch "amd64" }}CC=zig cc -target x86_64-windows-gnu{{- end }}
          {{- if eq .Arch "arm64" }}CC=zig cc -target aarch64-windows-gnu{{- end }}
        {{- end }}
    flags:
      - -trimpath
      - -buildvcs=false
    ldflags:
      - -s -w
      - -X main.version={{.Version}}
      - -X main.commit={{.Commit}}
      - -X main.date={{.CommitDate}}
    mod_timestamp: '{{ .CommitTimestamp }}'

  - id: helix-darwin
    main: ./cmd/helix
    binary: helix
    goos: [darwin]
    goarch: [amd64, arm64]
    env:
      - CGO_ENABLED=1
      - GOFLAGS=-mod=readonly
      # D-15: NO CC override — Apple clang on macos-14 is the host default.
    flags:
      - -trimpath
      - -buildvcs=false
    ldflags:
      - -s -w
      - -X main.version={{.Version}}
      - -X main.commit={{.Commit}}
      - -X main.date={{.CommitDate}}
    mod_timestamp: '{{ .CommitTimestamp }}'
```

The `archives:` block must reference both build IDs:

```yaml
archives:
  - id: helix
    ids: [helix-non-darwin, helix-darwin]
    formats: ["tar.gz"]
    name_template: "helix_v{{ .Version }}_{{ .Os }}_{{ .Arch }}"
    files:
      - LICENSE*
      - README.md
      - INSTALL.md
      - CHANGELOG.md
```

All other top-level blocks (`checksum:`, `signs:`, `changelog:`, `release:`) are
preserved verbatim.

## Why FALLBACK-B and not FALLBACK-A (bump pin)?

GoReleaser Pro is a paid commercial license, not a different OSS version. Bumping the
pin to any v2.x tag of the open-source repository will not unlock split/merge — the
feature is gated at runtime by the binary's edition, not by the version number. The
only honest way to take Path A would be to (a) acquire a Pro license, (b) configure
the workflow to fetch the Pro CLI artifact, and (c) inject the license key as a
GitHub Actions secret. That is materially out-of-scope for Phase 59.1 (Phase 59.1 is
a build-pipeline cleanup, not a vendor-relationship change).

FALLBACK-B keeps Helix on the existing OSS distribution, preserves the WR-04 SHA-pin
posture (the `goreleaser-action@<sha>  # v7.0.0` and the `version: 'v2.15.4'` in
release.yml are unchanged), and uses the OSS-supported `--id` filter as the runner-
partition mechanism. The architectural intent of D-15 (each runner builds only its
target subset; merge job stitches) is preserved entirely; only the syntactic mechanism
differs.
