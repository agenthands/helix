# Phase 59.1 Plan 03: release.yml Split-Runner Rewrite Summary

**One-liner:** Rewrite `.github/workflows/release.yml` from a single ubuntu job into the FALLBACK-B-MULTI-BUILD-ID three-job split-runner pipeline (release-linux + release-darwin + release-merge) with per-runner Pass-1≡Pass-2 reproducibility gate, tag-gated macOS job, and uniform cosign keyless attestation across all 6 archives in the merge job.

## Outcome

`.github/workflows/release.yml` is now a 437-line three-job pipeline that closes the `release.yml` half of the split-runner architecture (Wave 2 closed the `.goreleaser.yaml` half via the two-build-entry FALLBACK-B refactor at commit `a613e57c`). The FALLBACK-B-MULTI-BUILD-ID mechanism (D-20) is implemented exactly: per-runner `goreleaser build --id <runner-id>` + merge `goreleaser release --skip=build`. No path-A artifacts (`partial: { by_target: true }`, `release --split`, `goreleaser continue`) appear in the file — verified by negative grep.

## Three-Job Structure

| Job              | Runner       | Trigger gate                                    | Permissions                          | Build filter                |
|------------------|--------------|-------------------------------------------------|--------------------------------------|-----------------------------|
| `release-linux`  | ubuntu-22.04 | unconditional (all triggers)                    | `contents: read`                     | `--id helix-non-darwin` (4 binaries: linux+windows × amd64+arm64) |
| `release-darwin` | macos-14     | tag-push OR workflow_dispatch (D-16)            | `contents: read`                     | `--id helix-darwin` (2 binaries: darwin × amd64+arm64) |
| `release-merge`  | ubuntu-22.04 | tag-push OR workflow_dispatch + needs both      | `contents: write` + `id-token: write` | n/a — `release --skip=build` over merged dist |

`id-token: write` is granted ONLY on `release-merge` — the only job that mints Fulcio short-lived certs for cosign keyless signing (WR-01 minimal-permission posture).

## Per-Runner Pass-1≡Pass-2 Gate Logic

The reproducibility gate is forked one copy per runner (preserving the logic shape of the original release.yml lines 88-119). Each runner asserts byte-equality on its OWN subset of binaries:

- **Linux runner:** sha256 over 4 helix-non-darwin binaries → `/tmp/pass1-linux.sha256` vs `/tmp/pass2-linux.sha256` (uses GNU `sha256sum`)
- **macOS runner:** sha256 over 2 helix-darwin binaries → `/tmp/pass1-darwin.sha256` vs `/tmp/pass2-darwin.sha256` (uses BSD `shasum -a 256` — GNU `sha256sum` is absent on stock macos-14)

Cross-runner byte-equality is **NOT** asserted (D-17 invariant — different machines, different SDKs, different clang versions; the comparison is not meaningful).

## WR-07 Forensic Dump (per-runner)

On Pass-1≢Pass-2 divergence:

- **Linux runner dump:** per-file sha256, sizes, `go version -m` diff, first 512 bytes hex
- **macOS runner dump:** all linux dump items PLUS Apple-specific helpers — `xcodebuild -version` re-capture, `otool -l … LC_UUID`, `codesign -dv` (per D-10 amended Apple-toolchain timestamp hazards: LC_UUID + codesign timestamps)

Each dump is scope-tagged so logs are unambiguous: `WR-07, runner=linux, scope=helix-non-darwin` vs `WR-07, runner=darwin, scope=helix-darwin`.

## Cosign Keyless Attestation (D-19, Phase 58 REL-01 preserved)

The `.goreleaser.yaml` `signs:` block (cosign keyless: `--new-bundle-format`, public-good TSA `https://timestamp.sigstore.dev/api/v1/timestamp`, OIDC issuer `https://token.actions.githubusercontent.com`, `--bundle=${signature}`) is **unchanged** from the verified Phase 58 shape — Wave 2 already landed it. This wave only changes which job runs the sign pipe: now `release-merge` runs it once over all 6 archives uniformly (4 from linux runner + 2 from darwin runner), rather than the prior single-runner job.

The sign pipe runs ONLY on real tag-push (`if: github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v')`). On `workflow_dispatch`, the merge job invokes `release --snapshot --clean --skip=build,sign` — archives + checksums only, no cosign attempt (workflow_dispatch is rehearsal, not real release).

No Apple Developer ID code-signing, no notarytool, no `AC_PASSWORD` (D-19 — Apple notarization deferred to a future phase; Wave 4 documents the Gatekeeper "right-click → Open" workaround in INSTALL.md/README.md).
