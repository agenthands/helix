    ```markdown
    ## macOS Gatekeeper workaround

    Helix v1.10 darwin archives are **unsigned** — the release pipeline ships them with cosign keyless attestation (Sigstore) but does NOT use Apple Developer ID notarization. macOS Gatekeeper will block the first run with an error like *"helix" cannot be opened because the developer cannot be verified*.

    There are two acceptable workarounds. Pick one:

    **Option A — Right-click → Open (recommended for first install):**

    1. After downloading and extracting `helix_v*_Darwin_*.tar.gz`, open Finder.
    2. Right-click the `helix` binary → **Open**.
    3. macOS shows a confirmation dialog "*macOS cannot verify the developer of "helix". Are you sure you want to open it?*". Click **Open**.
    4. Subsequent invocations from the terminal succeed without further prompts.

    **Option B — Remove the quarantine attribute (CLI):**

    ```bash
    xattr -d com.apple.quarantine /path/to/helix
    ```

    This unsets the `com.apple.quarantine` extended attribute that Gatekeeper checks. After this, `helix daemon` (and any other invocation) runs without the dialog.

    **Why this is necessary:** Apple Developer ID notarization requires the Apple Developer Program (paid annually) and Apple-credential secret management in CI. Phase 59.1 explicitly defers notarization to a follow-up phase (tracked as `DEF-59-NOTARIZE` in `.planning/deferred-items.md`). cosign keyless attestation provides supply-chain verification (verify via `cosign verify-blob ...`) — it just doesn't satisfy Gatekeeper's Apple-specific cert path.

    **Linux + Windows users:** No equivalent workaround is needed. Helix linux/windows archives ship verbatim and run without OS-level quarantine.
    ```
