### CONTRIBUTING.md — FALLBACK-B canonical commands

```sh
# darwin host (Apple Silicon Mac) — produces darwin/{amd64,arm64} (2 binaries):
goreleaser build --snapshot --clean --id helix-darwin

# linux host (with zig 0.14.1+ on PATH) — produces linux/{amd64,arm64} + windows/{amd64,arm64} (4 binaries):
goreleaser build --snapshot --clean --id helix-non-darwin
```

The full 6-archive matrix only assembles in CI. The `make release-snapshot` darwin-host caveat is documented verbatim from `59.1-02-SUMMARY.md`: the `helix-non-darwin/windows_amd64_v1` zig cc link step fails at lld-link with C++ stdlib undefined symbols (libc++ vs libstdc++ in `libduckdb_static.a`) — **this is a darwin-host-local limitation, NOT a config defect** because the CI ubuntu runner invokes `--id helix-non-darwin` and never collides both stdlibs.

### INSTALL.md — Gatekeeper workaround (excerpt)

> **Workaround (one-time per binary):** use the right-click → Open Gatekeeper-bypass.
>
> 1. Open Finder and navigate to the extracted `helix` binary.
> 2. **Right-click** (or Control-click) on the `helix` binary.
> 3. Select **Open** from the context menu.
> 4. macOS will prompt: "Are you sure you want to open it?" — click **Open**.
>
> **Alternative (terminal):** `xattr -d com.apple.quarantine /path/to/helix`
>
> Apple Developer ID signing + notarization is tracked as `DEF-59-NOTARIZE` in `.planning/deferred-items.md`.
