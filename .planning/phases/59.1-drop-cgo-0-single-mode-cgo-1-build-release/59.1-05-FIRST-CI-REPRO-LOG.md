**Failure mode:** `zig cc -target x86_64-linux-musl` link step rejected `libduckdb_static.a`

```
##[error]The process '/opt/hostedtoolcache/goreleaser-action/2.15.4/x64/goreleaser' failed with exit code 1
```

**Root cause (executor-attributed; awaits architectural confirmation):**

`.goreleaser.yaml` lines 35–37 set `CC=zig cc -target *-linux-musl` for the
linux targets. zig's musl target ships libc++ (LLVM C++ runtime), NOT
libstdc++ (GNU C++ runtime). The duckdb-go-bindings module ships prebuilt
`libduckdb_static.a` (linux-amd64@v0.10502.0) compiled against libstdc++ on
glibc — its `std::*`/`typeinfo`/`backtrace`/`malloc_trim` symbols cannot be
satisfied by zig's musl+libc++ environment. The link line's `-lstdc++` flag
fails because zig bundles no libstdc++ for any target.

Wave 2 SNAPSHOT-BASELINE.md predicted this symptom on darwin hosts but
asserted "CI ubuntu runner does not hit it because it only invokes
`--id helix-non-darwin`" — that assertion was UNVERIFIED until this Wave 5
first-CI-repro and is now disproven. The issue is target-selection
(zig+musl + libstdc++-linked prebuilt lib), not host-selection.

**Gate verdict:** N/A — no Pass-1 binaries produced; Pass-1≡Pass-2 cannot
be evaluated. The release-linux job exited at the Pass-1 build step.
