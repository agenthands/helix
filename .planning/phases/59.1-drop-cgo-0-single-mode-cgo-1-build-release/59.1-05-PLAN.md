**`make release-smoke` target shape** (Wave 1 left a placeholder; Wave 5 wires it). The target:

1. Verifies a `dist/helix_v*_linux_amd64.tar.gz` archive exists (fails-loud if missing).
2. Extracts the archive into a temp directory.
3. Boots `./helix daemon` against a fixture repo under `testdata/fixtures/go/` (existing fixture from prior phases — verify path before wiring).
4. Hits the MCP `tools/list` endpoint via curl over HTTP transport (or stdio via the forwarder).
5. Asserts:
   - HTTP 200 / valid JSON-RPC response
   - `result.tools` array length >= 41 (Helix profile: 41+ tools per CLAUDE.md)
   - At least 23 tree-sitter-related tools or grammar entries (proxy: count tools that mention `tree-sitter` in their description, OR boot the daemon with verbose logging and grep `Registered grammar` count; planner picks the cleanest mechanism — the boot-log grep is more reliable because tool descriptions don't necessarily enumerate grammars)
6. Cleans up: kills the daemon, removes the temp directory.

**Choice of tools/list assertion mechanism:** the simplest reliable approach is to capture daemon startup logs (which print `Registered grammar: <lang>` lines for each of the 23 tree-sitter grammars), grep for grammar registrations, and count. The MCP `tools/list` endpoint is a sanity check that the daemon is responsive; the grammar count is the substantive D-04 assertion.
