## Phase Boundary

This phase **flips Phase 51.1 D-02** and converts Helix to a single-mode
**CGO=1** build & release. It closes `INT-BLOCKER-01` from
`.planning/v1.10-MILESTONE-AUDIT.md` (`internal/semantic/extract/provider.go`
unconditionally imports `tree_sitter.Language`, breaking
`CGO_ENABLED=0 go build ./cmd/helix`) by removing the CGO=0 build path
entirely instead of patching the missing stub.

Lands as an URGENT insertion before Phase 60 to stop further `_nocgo.go`
accumulation in the live-update / enrichment / graph phases.

- Switch `.goreleaser.yaml` from `CGO_ENABLED=0` to `CGO_ENABLED=1` for all 6

## Implementation Decisions

### Cross-compile toolchain

- **D-01 (Amended 2026-05-04): zig cc on a single ubuntu-22.04 runner — for linux + windows targets ONLY.**
  Release CI keeps a single ubuntu-22.04 runner for `linux/{amd64,arm64}`
  and `windows/{amd64,arm64}` (4 archives), each built with
  `CGO_ENABLED=1` and `CC="zig cc -target <triple>"`. Reasoning unchanged
  for those 4 targets: deterministic, hermetic, preserves WR-07
  forensic-dump-backed reproducibility.
  ~~Original D-01 also covered darwin via zig cc.~~ Wave 0 probe
  (`59.1-00-PROBE-NOTES.md`) demonstrated this is unsafe: darwin builds
  fail on `mach/mach_vm.h` (Apple Mach kernel header not in zig's bundled
  libc, license-blocked from redistribution) and on zig's `-L` sysroot
  rewrite of `duckdb-go-bindings` absolute lib paths. Both blockers are
  independent of zig version and target syntax. **Darwin builds move to
  D-15 (split macOS runner).**
- **D-02: Pinned-by-SHA `setup-zig` action with explicit version.** Mirrors
  the existing release.yml hardening posture (WR-04 ubuntu-22.04 pin, WR-07
  goreleaser-action pinned by SHA + exact version). Researcher selects the
  setup-zig action and zig version (zig 0.13.x or latest 0.14.x stable);
  planner records the SHA + version in the same comment style as
  `cosign-installer@7e8b541eb2e61bf99390e1afd4be13a184e9ebc5  # v3.10.1`.
- **D-03: zig is required for `make release-snapshot`, optional for `make build`.**
  Add a zig-presence detection clause to the Makefile alongside the existing
  goreleaser one, with an actionable install hint (`brew install zig` /
  `apt install zig` / `curl ziglang.org/...`). `make build` (current
  `go build ./cmd/helix`) keeps using the host CC so unrelated dev workflows
  don't take a new dependency.
- **D-04 (Amended 2026-05-04): Validation = `make release-snapshot` + linux-amd64 daemon smoke. darwin/windows stay structural-only.**
  The phase is not "done" until: (a) `goreleaser build --snapshot` produces
  all 6 archives across both runners (4 from linux runner, 2 from
  macos-14 runner per D-15), (b) `./helix daemon` started from the
  linux-amd64 archive answers an MCP `tools/list` showing tree-sitter-backed
  tools registering all 23 grammars (via `get_repo_map` on a fixture repo,
  or by inspecting startup logs). darwin/windows archives are validated
  structurally (archive shape, binary not-empty, `go version -m`
  buildinfo) — functional validation lands at user-install-time. The
  native macOS runner makes a darwin functional smoke technically reachable
  but it is **explicitly deferred** (see Deferred Ideas) to avoid widening
  CI surface this phase. Researcher picks the precise smoke tool (e.g.
  existing fixture under `testdata/fixtures/`) so the smoke is
  reproducible.

  to plain `.go`.** Smallest long-term surface; honest compile-time failure

- **D-06: Drop `//go:build cgo` from every test file that has it.** Phase
  51.1 D-03 added the tag so the test suite would compile under CGO=0; with
  CGO=1 mandatory the tag is dead weight. `go test ./...` now compiles and
  runs the full suite unconditionally.
- **D-07: Delete `treesitter.Available` and the daemon refusal that reads
  it.** After D-05 the binary literally cannot be built without CGO; the
  runtime check at `internal/daemon/daemon.go` step 6a is unreachable and
  pretends to be defensive. Remove the constant and the surrounding error
  block (lines containing `if !treesitter.Available`). Researcher confirms
  there is no caller of `treesitter.Available` outside that block before

- **D-08: Keep `cmd/vet-noduckdb` and `internal/lint/noduckdb` exactly as-is.**
  They enforce a package-boundary invariant (only `internal/semantic/store/`
  may import `duckdb-go`), not a CGO invariant. The Phase 57 D-12 module
  path lock stays binding.

### Reproducibility gate

- **D-09 (Amended 2026-05-04): Per-target within-runner Pass-1≡Pass-2 byte-identical gate.**
  Reproducibility boundary moves from "single runner builds all 6 archives
  twice" to "each runner rebuilds its own targets twice in the same job
  and asserts byte-identical." Linux runner: 4 archives twice
  (linux/{amd64,arm64} + windows/{amd64,arm64}). macos-14 runner: 2
  archives twice (darwin/{amd64,arm64}). Repro holds because: zig cc is
  deterministic when pinned (D-02) for the linux side; Apple clang on a
  pinned macos-14 image (D-18) is deterministic within a single workflow
  run for the darwin side; `mod_timestamp` is committed-from-git;
  existing `-trimpath` + `-buildvcs=false` + `-ldflags '-s -w -X main.commit=...'`
  flags continue to apply. WR-03 / WR-07 forensic-dump infrastructure
  remains the safety net, now running per-runner. Across-runner
  byte-equality (e.g. comparing two consecutive workflow runs against
  each other) is **NOT** required.
- **D-10 (Amended 2026-05-04): Phase merge is blocked until the per-runner gate passes on every runner.**
  If either runner's Pass-1/Pass-2 diverges, the WR-07 forensic dump
  (per-file sha256, tar-entry metadata, gzip header bytes, `go version -m`
  diff) is the triage path on that runner. Common culprits — paths
  embedded by C compilation, Apple-toolchain timestamps, non-deterministic
  ordering — are addressed with `-fdebug-prefix-map` / `-Wl,-no_uuid` /
  zig flags, NOT by softening the gate. Documenting a Pass-3-style
  limitation (Phase 58 REL-05 precedent) is explicitly rejected:
  reproducibility is a release invariant for v1.10, not a nice-to-have.
  If darwin codesign timestamps prove unrebuildable byte-identically
  within macos-14 (an Apple-toolchain hazard surfaced during execution),
  the resolution is to strip/freeze the offending field, not to drop the
  gate.

### Wave 1 contingency — split-runner pipeline (added 2026-05-04)

Added after Wave 0 darwin probe failure surfaced two zig-cc-on-linux
blockers (Apple Mach kernel headers + zig sysroot `-L` rewrite quirk on
duckdb-go-bindings absolute paths). Recovery path (a) chosen — split
macOS runner — explicitly trading D-01's single-runner constraint for
honesty about the darwin toolchain reality.

- **D-15: Split-runner release pipeline via goreleaser `--split`.**
  Two runners with split workspaces, single merge step:
  - **Linux runner (`ubuntu-22.04`, WR-04):** builds linux/{amd64,arm64}
    + windows/{amd64,arm64} via `CC="zig cc -target <triple>"`.
    `setup-zig` action SHA-pinned (D-02 unchanged). 4 archives.
  - **macOS runner (`macos-14`, D-18):** builds darwin/{amd64,arm64}
    natively via Apple clang against the Xcode 15.x SDK. 2 archives.
  - **Merge step (linux runner, cheaper):** stitches per-runner
    artifacts, produces single `checksums.txt`, runs the existing
    cosign keyless attestation pass uniformly across all 6 archives,
    publishes the GitHub Release. The user-facing artifact-name shape
    (`helix_v{Version}_{Os}_{Arch}.tar.gz`) and the `.sigstore.json`
    bundle layout are preserved verbatim — `helix upgrade`
    (Phase 58 REL-01) consumers see no change. Researcher picks the
    exact `goreleaser --split` mechanics (`continue-on-error`,
    workspace upload/download action SHA pin, merge-job output
    contract).
- **D-16: macOS job runs only on tag pushes and `release-snapshot` workflow_dispatch.**
  GitHub bills macos-14 at ~10× the linux rate; PR validation stays
  linux-only (zig cc covers the 4 non-darwin archives; darwin breakage
  on PRs is intentionally not gated and surfaces at tag-cut time).
  Workflow trigger gate: `if: github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v')`
  OR the snapshot dispatch path. Nightly canary is **deferred** (see
  Deferred Ideas) — reconsidered if Xcode-image drift causes silent
  breakage between releases.
- **D-17: Reproducibility re-anchored as per-target within-runner Pass-1≡Pass-2.**
  Codified in the D-09 / D-10 amendments above. The reproducibility
  *boundary* changes; reproducibility itself does not. Across-runner
  byte-equality is not asserted (different machines, different SDKs,
  different clang versions — that comparison is not meaningful).
  WR-07 forensic-dump runs in two places (one per runner) on
  divergence.
- **D-18: macOS runner pinned to `macos-14` (Apple Silicon, Xcode 15.x).**
  Mirrors the WR-04 explicit-version posture for ubuntu-22.04. `macos-14`
  is the runner-image label; image-internal Xcode/clang version is
  captured in the build provenance via `xcodebuild -version` and
  `clang --version` recorded into the per-runner forensic dump (D-10).
  Roll forward to `macos-15` is an intentional follow-up phase, NOT an
  auto-update; `macos-latest` is **rejected** explicitly per WR-04
  posture.
- **D-19: darwin signing/notarization stays as today — unsigned binaries + cosign keyless attestation.**
  Native macOS builds make Apple Developer ID notarization technically
  reachable, but it requires the Apple Developer Program ($99/yr)
  and Apple-credential secret management. Phase 59.1 is scoped to the
  CGO=1 build pipeline; signing/notarization is out-of-scope. The
  existing cosign keyless attestation (Phase 58) continues to apply
  uniformly to all 6 archives. Document the Gatekeeper "right-click →
  Open" workaround in INSTALL.md / README.md alongside the existing
  install instructions. Notarization is tracked as a deferred item for
  v1.10.x or later.
