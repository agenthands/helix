**Gathered:** 2026-05-04
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase **flips Phase 51.1 D-02** and converts Helix to a single-mode
**CGO=1** build & release. It closes `INT-BLOCKER-01` from
`.planning/v1.10-MILESTONE-AUDIT.md` (`internal/semantic/extract/provider.go`
unconditionally imports `tree_sitter.Language`, breaking
`CGO_ENABLED=0 go build ./cmd/helix`) by removing the CGO=0 build path
entirely instead of patching the missing stub.

Lands as an URGENT insertion before Phase 60 to stop further `_nocgo.go`
accumulation in the live-update / enrichment / graph phases.

**In scope:**
- Switch `.goreleaser.yaml` from `CGO_ENABLED=0` to `CGO_ENABLED=1` for all 6
  build targets (darwin/linux/windows × amd64/arm64), with `CC="zig cc -target ..."`
  per target.
- Add a pinned-by-SHA `setup-zig` action with an explicit pinned zig version
  to `.github/workflows/release.yml`, mirroring the WR-04 / WR-07 pinning
  posture used for `goreleaser-action` and `cosign-installer`.
- Document `zig` as a `make release-snapshot` prerequisite in `Makefile`
  (with install hint, like the existing `goreleaser` detection) and
  `CONTRIBUTING.md` "Releasing".
- Delete the **9** `_nocgo.go` stub files (`internal/treesitter/{registry,available}_nocgo.go`,
  `internal/repomap/{elide,extractor}_nocgo.go`,
  `internal/kernel/edit/treesitter_nocgo.go`,
  `internal/semantic/store/duckdb_nocgo.go`,
  `internal/semantic/extract/extract_nocgo.go`,
  `internal/semantic/extract/{golang,python,typescript}/provider_nocgo.go`,
  `internal/semantic/extract/testutil/grammar_nocgo.go`) and remove the
  matching `//go:build cgo` tags from their `_cgo.go` siblings (rename to
  plain `.go`).
- Add `//go:build cgo` to the currently-untagged `internal/semantic/extract/provider.go`
  (the literal `INT-BLOCKER-01` file) ONLY IF it isn't already removed by
  the flatten — final shape is plain `.go` with no constraint.
- Drop `//go:build cgo` from every test file currently tagged for that
  reason (Phase 51.1 D-03 deadweight).
- Delete the `treesitter.Available` constant and the daemon CGO=0 refusal
  block in `internal/daemon/daemon.go` (step 6a) that reads it.
- Smoke-test the new release path: `make release-snapshot` (locally + in
  CI) produces all 6 archives and `./helix daemon` on linux-amd64 answers
  an MCP `tools/list` with all 23 tree-sitter grammars loaded.
- Pin zig version such that `release.yml` Pass-1 ≡ Pass-2 byte-identical
  reproducibility gate continues to hold under CGO=1; merge is blocked
  until that gate passes (WR-07 forensic dump is the triage tool).
- Doc sweep flipping the invariant: `CLAUDE.md` (build prerequisites),
  `CONTRIBUTING.md` (Releasing), `README.md` (any CGO mention), `CHANGELOG.md`
  (v1.10.x entry), `.planning/PROJECT.md` (new Key Decisions row marking
  Phase 51.1 D-02 as superseded with strikethrough trail), and
  `.planning/milestones/v1.9-phases/51-packaging-goreleaser/deferred-items.md`
  (close DEF-51-03 candidate).

**Out of scope (other phases or future milestones):**
- Cutting an actual `v1.10.x` release tag — release-cut timing is a separate
  decision after this phase merges and the reproducibility gate passes.
- Restoring or expanding the CGO=0 path via a WASM tree-sitter runtime
  (Phase 51.1 deferred Path 4) — irrelevant under single-mode CGO=1.
- Re-enabling per-target native cross-toolchains (mingw, osxcross) instead
  of zig cc — explicitly rejected during discussion (single-runner zig cc
  preserves the existing reproducibility gate shape).
- Changing the `cmd/vet-noduckdb` analyzer or the `internal/lint/noduckdb`
  package — they enforce a *different* invariant (only
  `internal/semantic/store/` may import `duckdb-go`; package-boundary, not
  CGO).
- Switching `modernc.org/sqlite` to a CGO sqlite driver — modernc still
  works under CGO=1 builds; no functional reason to swap.
- Re-tagging integration tests that were already CGO-agnostic — this phase
  only removes `//go:build cgo` from tests that have it.

<decisions>
## Implementation Decisions

### Cross-compile toolchain

- **D-01: zig cc on a single ubuntu-22.04 runner.** Release CI keeps the
  current shape (one runner, one `goreleaser release`) but switches each
  build entry from `CGO_ENABLED=0` to `CGO_ENABLED=1` with a per-target
  `CC="zig cc -target <triple>"`. Reasoning: deterministic, hermetic,
  preserves the WR-07 forensic-dump-backed Pass-1/Pass-2 reproducibility
  gate without redesign, avoids the cost and reproducibility complexity of
  a 3-runner native matrix.
- **D-02: Pinned-by-SHA `setup-zig` action with explicit version.** Mirrors
  the existing release.yml hardening posture (WR-04 ubuntu-22.04 pin, WR-07
  goreleaser-action pinned by SHA + exact version). Researcher selects the
  setup-zig action and zig version (zig 0.13.x or latest 0.14.x stable);
  planner records the SHA + version in the same comment style as
  `cosign-installer@7e8b541eb2e61bf99390e1afd4be13a184e9ebc5  # v3.10.1`.
- **D-03: zig is required for `make release-snapshot`, optional for `make build`.**
  Add a zig-presence detection clause to the Makefile alongside the existing
  goreleaser one, with an actionable install hint (`brew install zig` /
  `apt install zig` / `curl ziglang.org/...`). `make build` (current
  `go build ./cmd/helix`) keeps using the host CC so unrelated dev workflows
  don't take a new dependency.
- **D-04: Validation = `make release-snapshot` + linux-amd64 daemon smoke.**
  The phase is not "done" until: (a) `goreleaser build --snapshot` produces
  all 6 archives, (b) `./helix daemon` started from the linux-amd64 archive
  answers an MCP `tools/list` and the response shows tree-sitter-backed
  tools registering all 23 grammars (e.g. via `get_repo_map` on a
  fixture repo, or by inspecting startup logs). darwin/windows archives are
  validated structurally (archive shape, binary not-empty, `go version -m`
  buildinfo) — functional validation lands at user-install-time. Researcher
  picks the precise smoke tool (e.g. existing fixture under
  `testdata/fixtures/`) so the smoke is reproducible.

### Stub cleanup

- **D-05: Delete all 9 `_nocgo.go` files + flatten their `_cgo.go` siblings
  to plain `.go`.** Smallest long-term surface; honest compile-time failure
  if anyone tries `CGO_ENABLED=0 go build`. After this commit no Helix
  source file carries a `//go:build cgo` tag (the per-grammar
  `internal/treesitter/bindings/{r,swift}/binding_nocgo.go` files are
  in-scope for this same flatten — researcher confirms whether they survive
  as plain bindings or fold into the package-level cleanup).
- **D-06: Drop `//go:build cgo` from every test file that has it.** Phase
  51.1 D-03 added the tag so the test suite would compile under CGO=0; with
  CGO=1 mandatory the tag is dead weight. `go test ./...` now compiles and
  runs the full suite unconditionally.
- **D-07: Delete `treesitter.Available` and the daemon refusal that reads
  it.** After D-05 the binary literally cannot be built without CGO; the
  runtime check at `internal/daemon/daemon.go` step 6a is unreachable and
  pretends to be defensive. Remove the constant and the surrounding error
  block (lines containing `if !treesitter.Available`). Researcher confirms
  there is no caller of `treesitter.Available` outside that block before
  deletion.
- **D-08: Keep `cmd/vet-noduckdb` and `internal/lint/noduckdb` exactly as-is.**
  They enforce a package-boundary invariant (only `internal/semantic/store/`
  may import `duckdb-go`), not a CGO invariant. The Phase 57 D-12 module
  path lock stays binding.

### Reproducibility gate

- **D-09: Keep the Pass-1/Pass-2 byte-identical gate exactly as today, just
  under CGO=1.** Reproducibility holds because zig cc is deterministic when
  pinned (D-02), `mod_timestamp` is committed-from-git, and the existing
  `-trimpath` + `-buildvcs=false` + `-ldflags '-s -w -X main.commit=...'`
  flags continue to apply. WR-03 / WR-07 forensic-dump infrastructure
  remains the safety net.
- **D-10: Phase merge is blocked until the gate passes under CGO=1.** If
  the first CGO=1 reproducibility run diverges, the WR-07 forensic dump
  (per-file sha256, tar-entry metadata, gzip header bytes, `go version -m`
  diff) is the triage path. Common culprits at compile time — paths
  embedded by C compilation, non-deterministic ordering — are addressed
  with extra `-fdebug-prefix-map`/zig flags, NOT by softening the gate.
  Documenting a Pass-3-style limitation (Phase 58 REL-05 precedent) is
  explicitly rejected: reproducibility is a release invariant for v1.10,
  not a nice-to-have.

### Documentation flip

- **D-11: Full doc sweep.** Update `CLAUDE.md` (Technology Stack: clarify
  build requires CGO=1, runtime is statically linked, single binary
  unchanged), `CONTRIBUTING.md` "Releasing" (zig install, new build flow,
  reproducibility-gate notes), `README.md` (any CGO=0 / "no CGO" prose),
  `CHANGELOG.md` (new v1.10.x entry framed as "build pipeline:
  single-mode CGO=1, replaces Phase 51.1 D-02 stub policy"),
  `.planning/REQUIREMENTS.md` (any REQ that references CGO=0 stub policy
  gets updated text or a struck row),
  `.planning/milestones/v1.9-phases/51-packaging-goreleaser/deferred-items.md`
  (DEF-51-03 candidate moves OPEN → RESOLVED with pointer to 59.1 PLAN /
  SUMMARY), and the Phase 51.1 SUMMARY.md (cross-reference back to 59.1 as
  the supersede event).
- **D-12: Reword "single binary" claim along the user/builder seam.**
  User-facing prose (PROJECT.md Core Value, README hero, CLAUDE.md intro):
  keep "single self-contained binary; no Python, Docker, or runtime
  dependencies." Build-side prose (CLAUDE.md Technology Stack /
  CONTRIBUTING.md Releasing): "helix builds with CGO=1; CI uses zig cc as
  hermetic cross-compiler; locally `make build` uses your host CC." Don't
  dilute the user-facing single-binary message.
- **D-13: PROJECT.md Key Decisions table — add a new row, mark 51.1 as
  superseded.** New row: `Phase 59.1: drop CGO=0 stubs, single-mode CGO=1
  release | INT-BLOCKER-01 from v1.10-MILESTONE-AUDIT.md — stub apparatus
  added cost without value once goreleaser pinned CGO=0 | ✓ Good — …`. The
  existing 51.1 row text gets a `~~strikethrough~~` of the "preserved" verb
  with an inline " — superseded by Phase 59.1 (v1.10)" tail. Preserves the
  decision history so future readers see the trail "we tried it, then
  changed our minds because the goreleaser+release-cut path made it
  pointless".

### Claude's Discretion

Researcher / planner have authority on:

## Specific Ideas

- "Drop CGO=0 — single-mode CGO=1 build & release" framing is the user's
  exact phase title. The cleanup is value-additive *and* defensive: it
  closes INT-BLOCKER-01 *and* removes the standing temptation for future
  v1.10 phases (live update, enrichment, graph) to keep adding `_nocgo.go`
  stubs that nobody tests.
- Zig cc on a single ubuntu runner is the user's explicit choice over a
  GHA matrix with native runners — chosen specifically to preserve the
  existing reproducibility gate without redesign.
- Phase 51.1 D-02's "daemon refuses CGO=0" invariant is the explicit
  flip-target. The PROJECT.md Key Decisions row for 51.1 gets a
  strikethrough + supersede tail in this same phase, so the decision trail
  is visible to future readers in one place.

</specifics>
