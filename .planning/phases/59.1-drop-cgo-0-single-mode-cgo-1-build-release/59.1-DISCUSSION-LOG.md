## Reproducibility gate redefinition

### Q3: How should the reproducibility gate work under split runners?

| Option | Description | Selected |
|--------|-------------|----------|
| Per-target within-runner Pass-1≡Pass-2 | Each runner rebuilds its own targets twice in the same job and compares byte-identical. WR-07 forensic-dump per-runner. Strictest interpretation of per-target reproducibility. | ✓ |
| Per-target across two independent runs | Two separate workflow runs; Pass-1 from run N, Pass-2 from run N+1. Catches runner-image drift. Higher CI cost; harder to gate a single PR. | |
| Drop byte-identical for darwin; keep for linux/win; add provenance for darwin | Apple toolchain non-determinism is a known hazard. Lean on SLSA provenance + cosign for darwin. | |
| Drop byte-identical entirely; switch to provenance+attestation | Biggest WR-07 redesign; cleanest long-run posture. | |

**User's choice:** Per-target within-runner Pass-1≡Pass-2. Codified into D-17 + the D-09/D-10 amendments. Across-runner byte-equality is explicitly NOT asserted.
