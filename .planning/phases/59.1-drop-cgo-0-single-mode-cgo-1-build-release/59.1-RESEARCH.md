## Summary

**Amended 2026-05-04:** Phase 59.1 is a release-pipeline inversion: flip Phase 51.1 D-02 (the daemon's `treesitter.Available` refusal under CGO=0) to the opposite invariant — single-mode CGO=1 — and re-wire the goreleaser path to compile all 6 archives under CGO=1 across **two runners** orchestrated by `goreleaser release --split`: an `ubuntu-22.04` runner builds linux/{amd64,arm64} + windows/{amd64,arm64} (4 archives) using `zig cc` as a hermetic cross-compiler, and a `macos-14` runner builds darwin/{amd64,arm64} (2 archives) natively using Apple clang against the Xcode 15.x SDK. A merge step on the linux runner stitches per-runner partial artifacts, produces the unified `checksums.txt`, runs the existing cosign keyless attestation pass uniformly across all 6 archives, and publishes the GitHub Release.

**The reproducibility gate moves from "single runner builds all 6 archives twice" to "each runner rebuilds its own targets twice in the same job and asserts byte-identical"** (D-09 / D-17 amended). Linux runner: 4 archives × 2 passes. macos-14 runner: 2 archives × 2 passes. Across-runner byte-equality is **not asserted** (different machines, different SDKs, different clang versions — that comparison was never meaningful and is explicitly NOT a gate). The WR-07 forensic-dump infrastructure (release.yml lines 88-119 in the original single-runner shape) duplicates per-runner.

The deletion side is mechanical, well-understood, and **already merged** (Wave 1 — `59.1-01-SUMMARY.md`): 12 `_nocgo.go` files, one `_nocgo_test.go` file, the `treesitter.Available` constant, the daemon step-6a refusal block, and `//go:build cgo` tags on 24 production + test files were removed. The `_cgo.go` siblings flattened to plain `.go`. The locally-vendored R/Swift bindings already lost their `binding_nocgo.go` siblings before this phase began (Phase 51.1 cleanup), so D-05's "fold into D-05?" question for them was moot — they only needed their `//go:build cgo` tag stripped from `binding.go`. INT-BLOCKER-01 closed in Wave 1.

**Why split-runner instead of the original single-runner zig-cc-all-6-targets pattern:** Wave 0 probe (`59.1-00-PROBE-NOTES.md`) demonstrated that zig cc on a Linux runner cannot safely produce darwin archives. **Two independent blockers**, both invariant under zig version (0.14.1 vs 0.16.0) and target syntax (`aarch64-macos` vs `aarch64-macos-none`):
1. **Compile-time:** `prometheus/client_golang/prometheus/process_collector_mem_cgo_darwin.c` includes `<mach/mach_vm.h>`, an Apple Mach kernel header that ships ONLY in the Apple SDK. zig's bundled libc does not include Mach kernel headers (and Apple's license forbids redistribution).
2. **Link-time:** zig cc with `--sysroot` rewrites bare `-L<absolute-path>` arguments as `<sysroot><absolute-path>`, so `duckdb-go-bindings`' vendored `lib/darwin-arm64@v0.10502.0` absolute path becomes nonsense. (zig issue ziglang/zig#3287.)

The user explicitly accepted the D-01 single-runner constraint violation: *"this looks like a case where the constraint is now more expensive than the problem it was meant to solve"* — choosing the more honest darwin toolchain model over the linux-only-with-private-secret-SDK pipeline (osxcross + Apple SDK redistribution). Reproducibility framing reframed: *"change the boundary, don't abandon reproducibility."*

**Primary recommendation:** Linux runner pins **`mlugg/setup-zig@d1434d08867e3ee9daa34448df10607b98908d29  # v2.2.1`** with **`zig version: 0.14.1`** (released 2025-05-21, ~12 months of bake time; 0.16.0 just released 2026-04-13 and is too fresh for a reproducibility-gated release pipeline). macOS runner pins **`runs-on: macos-14`** (Apple Silicon, Xcode 15.x via `sudo xcode-select -s /Applications/Xcode_15.x.app`); `xcodebuild -version` and `clang --version` are recorded into the per-runner forensic dump for build provenance. goreleaser uses **`partial.by_target`** (`goreleaser release --split` mechanic) to produce per-runner manifests; merge job downloads both partial artifact bundles, runs `goreleaser continue` (or equivalent `--merge` mechanic; planner confirms exact incantation against goreleaser v2.15.4 release notes). Use musl libc for linux + gnu for windows on the linux runner; Apple clang against the Xcode SDK for darwin on macos-14.

## Architecture Patterns

```

        │
        ├─ if !startsWith(github.ref, 'refs/tags/v') AND !workflow_dispatch:
        │     → SKIP macOS job entirely (D-16: cost gate)
        │
        ├──────────────── Linux runner (ubuntu-22.04, WR-04) ─────────────────
        │     │
        │     ├─ checkout (fetch-depth: 0)

        │     │                          gzip header, go version -m) → exit 1

        │     │
        │     ├─ checkout (fetch-depth: 0)
        │     ├─ setup-go (1.25.x — same pin)
        │     ├─ select Xcode 15.x (sudo xcode-select)
        │     ├─ record provenance (xcodebuild -version, clang --version, sw_vers)
        │     │
        │     ├─ Pass 1: goreleaser release --split --snapshot --clean --skip=sign
```

### Pattern 1: goreleaser per-target CC via templated env (linux runner only — amended scope)

**What:** A single `builds[].env:` block uses Go template conditionals to set `CC=zig cc -target <triple>` based on `{{ .Os }}` and `{{ .Arch }}` — but ONLY for linux and windows targets. darwin entries omit the CC override entirely (Apple clang on macos-14 is the host default).
**When to use:** Cross-compiling Go+cgo to multiple {goos,goarch} pairs where each target needs a distinct C toolchain — and the toolchain is reachable from the runner.
**Why this over `overrides:`:** Single readable block; matches the canonical `goreleaser/example-zig-cgo` shape; one diff hunk in `.goreleaser.yaml` instead of six.
**Example:**
```yaml
# Source: https://raw.githubusercontent.com/goreleaser/example-zig-cgo/master/.goreleaser.yaml
# Adapted for Helix split-runner architecture (D-15): musl for linux, gnu for windows;
# darwin entries get NO CC override (Apple clang on macos-14 runner is the host default).
builds:
  - id: helix
    main: ./cmd/helix
    binary: helix
    env:
      - CGO_ENABLED=1
      - GOFLAGS=-mod=readonly
      - >-
        {{- if eq .Os "linux" }}
          {{- if eq .Arch "amd64" }}CC=zig cc -target x86_64-linux-musl{{- end }}
          {{- if eq .Arch "arm64" }}CC=zig cc -target aarch64-linux-musl{{- end }}
        {{- else if eq .Os "windows" }}
          {{- if eq .Arch "amd64" }}CC=zig cc -target x86_64-windows-gnu{{- end }}
          {{- if eq .Arch "arm64" }}CC=zig cc -target aarch64-windows-gnu{{- end }}
        {{- end }}
        # darwin: no CC override — host Apple clang is correct on macos-14 runner
    goos: [darwin, linux, windows]
    goarch: [amd64, arm64]
    flags: [-trimpath, -buildvcs=false]
    ldflags:
      - -s -w
      - -X main.version={{.Version}}
      - -X main.commit={{.Commit}}
      - -X main.date={{.CommitDate}}
    mod_timestamp: '{{ .CommitTimestamp }}'
```
Note: combined with `partial.by_target` (Pattern 5 below), each runner only executes the subset of {goos,goarch} matrix it owns.

## Common Pitfalls (amended — added Pitfalls 7 and 8)

### Pitfall 1: Reproducibility-gate divergence on first CGO=1 run (per-runner)

**What goes wrong:** Pass-1 sha256 ≠ Pass-2 sha256 because the C toolchain (zig cc on linux runner; Apple clang on macos-14) embeds a build-time path or random ordering into one of the C objects.
**Why it happens:** Native C compilation injects more non-determinism than pure Go (file paths in __FILE__ macros, debug section ordering, build-id linker stamps, Apple-toolchain UUID stamps).
**How to avoid (linux runner — zig cc):**
1. Pin zig to a single exact version (D-02 — already mandatory).
2. Pin `ZIG_GLOBAL_CACHE_DIR` to a stable per-job path inside `release.yml` if cache misses cause divergence (e.g. `ZIG_GLOBAL_CACHE_DIR=$RUNNER_TEMP/zig-cache`).
3. The Go-side flags `-trimpath` and `-buildvcs=false` are already there.
4. If still divergent, add `-fdebug-prefix-map=$PWD=.` to `CGO_CFLAGS` to neutralize embedded paths.
5. If still divergent, add `-Wl,--build-id=none` (linux/windows) to neutralize build-id stamps.

**How to avoid (macos-14 runner — Apple clang) — NEW per D-15/D-17:**
1. Pin `macos-14` (D-18) so Xcode/clang version is stable.
2. Record `xcodebuild -version` + `clang --version` per workflow run (D-10 amended).
3. The Go-side flags `-trimpath` and `-buildvcs=false` apply equally.
4. If divergent, add `-Wl,-no_uuid` to neutralize Apple linker UUID stamps (Mach-O LC_UUID load command).
5. If still divergent, set `ZERO_AR_DATE=1` to neutralize `ar` archive timestamp embedding (Apple's `ar` defaults to current time in archive entries).
6. If still divergent, investigate `SOURCE_DATE_EPOCH` (matches `mod_timestamp: '{{ .CommitTimestamp }}'` semantics).

**Warning signs:** The WR-07 forensic dump (release.yml lines 88-119) is the diagnostic, **duplicated per-runner**. It surfaces per-file sha256 diffs, tar entry metadata diffs, gzip header bytes, and `go version -m` output diffs. The first divergent file's sha256 plus `go version -m` will tell you whether the diff is in Go-managed metadata, C-side debug info, archive-level (gzip mtime / tar order), or Apple-toolchain UUID stamps.

### Pitfall 2: windows-arm64 build fails because duckdb-go-bindings has no prebuilt static library for that target

**What goes wrong:** `goreleaser build` for `windows/arm64` fails at the Go link stage with "missing duckdb library for windows-arm64".
**Why it happens:** Documented above — duckdb-go-bindings/lib/ ships {darwin-amd64, darwin-arm64, linux-amd64, linux-arm64, windows-amd64} but NOT windows-arm64 [VERIFIED: https://github.com/duckdb/duckdb-go-bindings, fetched 2026-05-04].
**How to avoid:** D-14 platform-tag stub (`duckdb_winarm64.go`) — **shipped in Wave 1.**

### Pitfall 3: zig binary not found on contributor's path during `make release-snapshot`

**What goes wrong:** Contributor runs the dry-run, gets a goreleaser error mid-build instead of a clean upfront failure.
**How to avoid:** Pattern 3 above — add a `command -v zig` guard at the top of the `release-snapshot` Makefile recipe (D-03). **Note:** under split-runner architecture, the local `make release-snapshot` only assembles a partial matrix; the full 6-archive output is CI-only. Document this expectation in CONTRIBUTING.md.

### Pitfall 4: Stale `dist-pass-1/` from a prior local run feeds back into a comparison

**What goes wrong:** Local `make release-snapshot` after a partial run leaves `dist/` from a previous build; if the new build resolves to a *different* binary, the contributor sees a false "non-reproducible" diff.
**How to avoid:** `goreleaser release --snapshot --clean ...` (note `--clean`) already wipes `dist/` per invocation. Document this in CONTRIBUTING.md anyway — contributors who run two separate `goreleaser` invocations themselves (without `--clean` between) can hit this.

### Pitfall 5: Test files with `//go:build cgo && integration` (one such file exists)

**What goes wrong:** Mass-stripping `//go:build cgo` regex-style leaves `//go:build  && integration` (note the double space and dangling `&&`), which is a build-tag syntax error.
**Where:** `internal/daemon/daemon_semantic_test.go:1` had `//go:build cgo && integration`.
**How to avoid:** **Already handled in Wave 1** — the file was edited individually to `//go:build integration`.

### Pitfall 6: `treesitter.Available` referenced from a doc comment in a stub file we're deleting anyway

**What goes wrong:** After deleting `treesitter.Available` and the daemon block, a stale doc comment in `duckdb_nocgo.go` still says "mirrors the treesitter.Available pattern" → grep audit fails.
**Where:** `internal/semantic/store/duckdb_nocgo.go:30` and `internal/semantic/store/duckdb_nocgo_test.go:34`.
**How to avoid:** **Already handled in Wave 1** — these files were deleted, so the references vanished with them.

### Pitfall 7 (NEW): Apple-toolchain timestamp / UUID embedding breaks per-runner Pass-1≡Pass-2 on macos-14

**What goes wrong:** First Pass-1 vs Pass-2 comparison on the macos-14 runner shows a single-byte diff in each Mach-O binary; `otool -l` reveals an `LC_UUID` load command with a different UUID per pass. Or `ar`-style static archive entries embed the per-pass build clock.
**Why it happens:** Apple's `ld` defaults to embedding a unique UUID per link operation (deterministic over inputs but mutates per-run). Apple's `ar` defaults to embedding wall-clock time in archive entries.
**How to avoid:** Add `-Wl,-no_uuid` to LDFLAGS for darwin builds; set `ZERO_AR_DATE=1` in the macos-14 job env; verify both via the per-runner forensic dump after the first reproducibility iteration.
**Warning signs:** The WR-07 forensic-dump-darwin tarball lists every diff between Pass-1 and Pass-2 dist/. If exactly two files (helix_v*_darwin_amd64 + helix_v*_darwin_arm64 binaries) differ in exactly the byte ranges corresponding to LC_UUID — that's the signal.
**Hard guarantee:** D-10 amended ("If darwin codesign timestamps prove unrebuildable byte-identically within macos-14, the resolution is to strip/freeze the offending field, not to drop the gate"). The mitigation flags above are the legal path; gate softening is NOT.

### Pitfall 8 (NEW): Cross-runner byte-equality misuse

**What goes wrong:** A future maintainer adds a "compare linux-built dist/ vs macos-14-built dist/" step thinking it strengthens the gate; instead it always fails (different OSes / clang versions / SDKs produce structurally different binaries even for shared targets like windows from a hypothetical macOS path), produces noisy CI failures, and gets disabled — silently weakening any real reproducibility signal.
**Why it happens:** Misreading D-09 / D-17. The amendment EXPLICITLY says cross-runner byte-equality is NOT asserted.
**How to avoid:** Plan-checker / reviewer audit — if any new step in `release.yml` compares artifacts produced on different runners for byte-equality, REJECT the change. The only legal cross-runner comparison is the merge step's `checksums.txt` assembly, which records (not asserts equality of) per-target sha256s.
**Warning signs:** A diff hunk in `release.yml` that compares `dist-partial-linux/*.tar.gz` to `dist-partial-darwin/*.tar.gz` for any byte-level equality.
