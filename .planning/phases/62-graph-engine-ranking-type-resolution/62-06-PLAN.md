Phase 62 enforces sort-before-iterate religiously everywhere else (frontier.go, pagerank.go, weak.go, util.go.sortedNodeIDs, internal/graph/pagerank.go D-03); these three helpers are the sole violation.

Today's suffix set ("Repo", "Svc", "Mgr", "Ctrl", "Cfg", "Conf", "Hdlr", "Conn") happens not to overlap as suffixes of any common identifier so a single iteration deterministically picks at most one match. The moment a future suffix is added that shares a tail with another (or a refactor introduces overlap), Go's randomized map iteration order will return different `long` forms for the same input across runs — silently breaking the GRAPH-01 byte-equal determinism contract and the TYPES-04 emit-determinism invariant. This plan tightens determinism by structure rather than convention.

Purpose: Lock GRAPH-01 / TYPES-04 byte-equal determinism against future suffix-overlap drift; satisfy the "every node-keyed iteration in this package MUST funnel through a sorted slice" doctrine in the only three places it is currently violated.

Output: Three resolver.go files refactored to use `[]suffixRule` sorted ascending by `short`, plus three RED-then-GREEN unit tests asserting deterministic match priority on a deliberately overlapping fixture.
