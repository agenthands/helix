<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→MCP `tools/call` | Agent-controlled receipt IDs and arguments cross into the daemon |
| read-tool handler→Receipt store | Server-issued receipts originate here; bodies must never leak to the agent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-01 | Spoofing | ReceiptID forgery via brute force | mitigate | UUIDv7 base32-26 = 130 bits entropy (`crypto/rand`); ParseReceiptID validates prefix + length + alphabet; opaque body-store lookup so unknown IDs are rejected with `miss` outcome |
| T-66-02 | Tampering | Receipt replay across graph_version advances | mitigate | `Store.InvalidateOnGraphVersionAdvance(ws, newGV)` deletes all receipts with `GraphVersion < newGV`; `ValidateReceiptForOperation` returns `ErrGraphVersionMismatch` on stale GV |
| T-66-03 | Repudiation | Issuance source unclear in audit | accept | `IssuingTool` + `IssuingCallID` + `TraceID` recorded in receipt; metric counter records issuance class |
| T-66-04 | Information Disclosure | Receipt store error leaks scope contents | mitigate | Sentinels carry no scope payload; `helix_receipt_lookup_total{outcome}` uses closed-enum labels with no source content (drop-unknown gate) |
| T-66-05 | Denial of Service | Unbounded receipt store via issuance flood | mitigate | LRU 10k cap per workspace + 30s janitor + opportunistic-on-lookup expiry (D-06) |
| T-66-06 | Elevation of Privilege | Cross-workspace receipt forgery in multi-workspace daemon | mitigate | `WorkspaceKey` field on receipt; `Get` returns `ErrWrongWorkspace` if `receipt.WorkspaceKey != current` |
| T-66-07 | Tampering | Persistence of receipts to disk would bypass graph_version invalidation | mitigate | In-memory `sync.Map` only; REQUIREMENTS.md line 167 forbids persistence; no DB schema, no file write paths in this plan |
</threat_model>
