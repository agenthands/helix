<objective>
Wire the receipt-issuance closure (Plan 01 issue_sink) into all 7 read/diagnostics tools' success paths and add the uniform `Receipts []ReceiptID` field to all 6 destructive-tool argument structs (D-08).

Purpose: Without read-tool issuance, the guardrails would refuse every destructive call (since no agent could ever obtain a receipt). Without the Receipts field on destructive args, the JSON parser in deps_production.Evaluate cannot extract them. This plan makes the system end-to-end-loopable: agent calls a read tool → receives receipt ID → forwards it on a destructive tool → middleware validates → operation proceeds.

Output: 8 tool handlers issue receipts on success; 6 destructive tool arg structs declare `Receipts []ReceiptID` with omitempty; 2-3 representative tests prove issuance fires on success and is silent on error.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-66-24 | Tampering | Receipt issued from a tool that errored partway (defer block) | mitigate | Issuance ONLY on the explicit success-path line; never in defer (per RESEARCH Pitfall 4); test asserts no issuance on error path |
| T-66-25 | Spoofing | verify_edit issues diagnostics_clean despite ErrorCount>0 | mitigate | Issuance gated on `if errCount == 0 { IssueReceiptOnSuccess(...) }` — explicit conditional |
| T-66-26 | Information Disclosure | Receipt scope leaks symbol names or file paths to logs | mitigate | Issuance call passes only IDs/counts/booleans/file basenames — no source content; log entries (debug only) emit issuance class + workspace, never scope payload |
| T-66-27 | Denial of Service | Issue closure takes a per-call lock that contends under high QPS | mitigate | Plan 01 store uses sync.Map; issuance is lock-free per-key; janitor runs on a separate goroutine |
| T-66-28 | Elevation of Privilege | Diagnostics-clean receipt issued with empty FileSet (covers everything) | mitigate | Predicate validateScope (Plan 01) requires FileSetContainsAll — empty FileSet matches NOTHING; verify_edit handler MUST populate FileSet with the actually-edited URIs |
