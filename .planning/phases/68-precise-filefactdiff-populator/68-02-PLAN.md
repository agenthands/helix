## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → provider | os.ReadFile pulls workspace source files; same trust domain as existing batch extractor |
| provider → tree-sitter | CPU-bound pure-Go parse; no network, no shell |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-68-05 | T (tampering) | Source file on disk | accept | Workspace files are the trust domain; same threat surface as existing Extract call sites |
| T-68-06 | D (DoS) | Large source files | mitigate | Existing `partialFile(..., PartialReasonFileTooLarge)` convention in Go provider handles oversize files. ExtractFile inherits the size-limit check inside `provider.Extract`. |
| T-68-07 | I (info disclosure) | ErrorMessage in partialFile | accept | Error text contains os.ReadFile error which may include path; path is workspace-scoped, not secret |
| T-68-08 | E (elevation) | Path traversal via `path` arg | mitigate | Caller (live handler) supplies path already normalized by the live-event pipeline; provider itself does not interpret `..` segments — `os.ReadFile` follows OS path semantics. No new traversal surface introduced. |
</threat_model>
