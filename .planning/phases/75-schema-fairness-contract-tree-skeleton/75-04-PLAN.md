<objective>
Wave 1 of Phase 75: author the single compile-time fairness contract every benchmark runner
(Phases 80+) loads its effective model config from — `bench/runners/fairness_contract.go` with
a package-level `var DefaultContract = FairnessContract{...}` literal pinning `ModelID` (a DATED
snapshot, NOT an alias), `Temperature`, `MaxTokens`, `SystemPromptHash`, `Retry`, `Cache`, and a
`map[mode]ModeOverride` (D-09). The loader `Validate()` fatals on any override with an empty
`WaiverReason` (D-10). A `DeprecationGate(today, ...)` with an INJECTED clock fails when the
pinned snapshot is within 30 days of EOL (D-11/FAIR-02). A recompute test pins
`SystemPromptHash` to `sha256(system_prompt.txt)` so prompt drift is a hard CI error.

This plan defines the cost-table-row shape the gate consumes but does NOT author cost-table.yaml
(Plan 05 owns it) — the gate takes a row/date argument, keeping this plan's files independent.

Purpose: same-model-same-budget is enforceable only if there is exactly one config source.
Output: fairness contract struct + loader + deprecation gate + prompt-hash anchor + tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed contract → runner startup | Runners load `DefaultContract` at startup; a contract with an unjustified override (empty WaiverReason) or a near-EOL snapshot must hard-fail rather than run an unfair benchmark. `WaiverReason`/`ApprovedBy` are free-text display fields, never executed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-75-07 | Tampering (fairness integrity) | system prompt drift defeating the pin | mitigate | `SystemPromptHash` recompute test fails CI if `system_prompt.txt` changes without re-pinning; ModelID is a dated snapshot (no runtime alias). |
| T-75-08 | Repudiation | unjustified per-mode override | mitigate | `Validate()` errors on any override with empty `WaiverReason` (D-10); every override is logged to result.v2.json fairness.overrides[] downstream. |
| T-75-09 | Tampering | code injection via WaiverReason/ApprovedBy | accept | These are free-text display-only attestation fields; they are never `exec`'d, shelled, or used as a query — no injection sink (documented in the doc comment). |
| T-75-SC | Tampering | npm/pip/cargo installs | n/a | No package installs; stdlib crypto/sha256, time, strings only. |

No high-severity threats: the contract is repo-committed Go with no network/auth surface. The
fairness-integrity threats (drift, unjustified override, near-EOL pin) are mitigated by the
recompute test, the empty-WaiverReason gate, and the injected-clock deprecation gate.
</threat_model>
