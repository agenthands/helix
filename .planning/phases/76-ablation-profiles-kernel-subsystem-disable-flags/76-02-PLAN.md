<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| profile YAML (embedded or user-override) → ProfileStore | A malformed/unknown mode name in a profile's default_mode or transitions could silently produce a nil allow-list (no filtering), defeating the ablation arm. |
| ProfileStore → tools/list filter | The resolved tool surface defines what the agent sees; an under-excluded arm leaks a disabled-subsystem tool into the inventory. |

NOT HIGH: input is a trusted in-repo/operator YAML, not attacker-controlled network input (V5 input-validation control per RESEARCH Security Domain). |
| T-76-04 | Information Disclosure (measurement validity) | an under-excluded bench arm leaks an LSP/semantic/structured-edit tool into tools/list | mitigate | Golden tool-surface tests (Task 1) pin each arm's exact resolved surface; defense-in-depth pairs with the kernel guard (Plan 76-01) + null-object wiring (Plan 76-04). |
