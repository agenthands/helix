<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI workflow → GHCR registry | The publish job pushes + signs mirror images; only the agenthands/helix bench-mirror workflow identity may sign |
| publish identity (CI) ↔ verify identity (runtime) | The signing SAN/issuer/ref must match the runtime pin or verification fails closed |
| signing key material | cosign keyless = no long-lived private key (Fulcio short-lived cert via OIDC) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-84-04-01 | Spoofing | bench-mirror.yml signing identity | mitigate | cosign keyless OIDC (id-token:write) signs from the pinned workflow path + refs/heads/main; runtime verify.go pins the matching SAN regex + issuer — a mismatched signer is rejected |
| T-84-04-02 | Tampering | mirror image signing | mitigate | Each image signed BY DIGEST (`cosign sign repo@sha256:…`), never by mutable tag; runtime pins the same digest (CONTAINER-02) |
| T-84-04-03 | Repudiation | keyless transparency | mitigate | Rekor transparency-log entry (cosign keyless default) provides a public audit record of the signing event |
| T-84-04-04 | (Process integrity) | publish-vs-verify drift | mitigate | Top-of-file comment + BENCH.md document the SAN/ref coupling so a workflow rename/ref change is mirrored in verify.go's pin |
| T-84-04-SC | Tampering | cosign-installer action | mitigate | sigstore/cosign-installer SHA-pinned (v3.10.1) + cosign-release v2.4.1 — same pin as the audited Phase 58 release.yml; no new unpinned action |
</threat_model>
