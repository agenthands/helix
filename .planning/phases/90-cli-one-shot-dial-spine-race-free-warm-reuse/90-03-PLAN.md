<objective>
Build the dial spine: a `helix <verb>` invocation that issues a SINGLE MCP `tools/call`
through the warm daemon over the EXISTING gRPC `StreamMCP` bidi stream and returns the tool
result, with zero proto changes (CLI-01) and warm reuse after a cold auto-start (CLI-02).

Three new pieces wired from existing primitives (RESEARCH: this phase is ~80% wiring):
1. `grpc_client_transport.go` — the CLIENT-side mirror of `internal/mcp/grpc_transport.go`
   (same io.Pipe-pair shape, opposite direction): MCP SDK client writes JSON-RPC →
   `stream.Send`; `stream.Recv` → SDK client reads. No `firstMsg` replay (client-side).
2. `oneshot.go` — a `forwarder` helper: `ConnectOrStartDaemon` (now race-safe via 90-01) →
   `client.StreamMCP(ctx)` → wrap in the client transport → `mcp.NewClient(...).Connect()` →
   `session.CallTool(name, args)` → clean teardown (`defer session.Close()` THEN
   `defer conn.Close()`, RESEARCH Pitfall 3, so the daemon does not count an `error` session).
3. `verb.go` — the cobra "spine" command that maps a verb + flags to `{Name, Arguments}` and
   calls the one-shot helper, then renders the raw/JSON result (terse rendering is Phase 92;
   here raw/JSON is acceptable).

Dependency note: this plan depends on BOTH 90-01 (race-safe `ConnectOrStartDaemon`) AND
90-02 (the `internal/cli/root.go` cobra `AddGroup` scaffold). Task 2 registers the verb
command in `root.go`'s `AddCommand` block AND assigns it to one of the cobra groups added in
90-02, and it edits the SAME file (`internal/cli/root.go`) that 90-02 edits — so 90-02 must
land first (both are wave 1; this plan is wave 2, after both).

Purpose: CLI-01/CLI-02 — this is the load-bearing round-trip every later phase's generated
verbs ride on; it must reuse the wire and the dial path exactly.
Output: client transport + its unit test; one-shot helper; verb spine + flag-mapping unit
test; verb command registered in root.go.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI process → daemon over unix socket | the one-shot tools/call crosses into the daemon's dispatch + middleware stack |
| verb flags (agent-supplied) → tool Arguments | untrusted flag values become the tool args map |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-90-06 | Spoofing | one-shot session opening over StreamMCP | mitigate | The SDK client performs the standard MCP `initialize` handshake (Task 2) so the daemon's SDK server routes a properly-initialized session; hand-framing (which skips the handshake) is rejected as an anti-pattern. |
| T-90-07 | Tampering | proto wire change to carry tools/call | mitigate | Zero-proto invariant — the existing MCPMessage/StreamMCP carries arbitrary JSON-RPC; `git diff --exit-code api/proto/` gated in both task verifies and the phase gate. |
| T-90-08 | Repudiation/Telemetry pollution | unclean stream drop counted as an `error` session | mitigate | Ordered defers (`session.Close()` then `conn.Close()`, Pitfall 3) flush cleanly so `helix_session_lifecycle{outcome="error"}` does not climb per CLI call. |
| T-90-09 | Elevation of Privilege | verb invoking a destructive tool without profile/mode enforcement | accept | `tools/call` profile/mode enforcement is explicitly Phase 91 (SEC-01/02). This plan drives the EXISTING still-filtered MCP path inside the daemon (no new bypass introduced); the always-visible generated verbs that would expose this gap do not land until Phase 91, where enforcement ships in the same phase (STATE.md carried constraint). |
| T-90-10 | Info disclosure | opening a network surface for the CLI↔daemon link | accept | The one-shot dials the existing per-uid unix socket only (loopback/unix); no TCP bind is added — optional TCP bind is RETIRE-04 (Phase 94), gated and loopback-default. |
</threat_model>
