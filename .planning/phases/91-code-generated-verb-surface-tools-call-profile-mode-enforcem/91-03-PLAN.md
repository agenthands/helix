<objective>
Re-point the per-profile contract oracle so the per-profile goldens verify the
CLI VERB surface — the set of `helix <verb>`s visible and invokable under each
profile — instead of the MCP `tools/list` surface. The golden FILES
(`testdata/profiles/<profile>.<mode>.tools.golden`) already encode the per-profile
allowed tool set; they are reused unchanged as the CLI-surface oracle. A verb
whose underlying tool is outside the active profile must be both hidden (the CLI
catalog does not surface it for that profile) and refused (the 91-02 enforcement
middleware denies it server-side).

This plan CONSUMES the read-only accessor `internal/cli.VerbToolNames()` exported
by 91-01 to read the generated verb catalog from the integration package; it adds
NO code to `internal/cli` (the accessor is the 91-01 → 91-03 seam, keeping the
Wave-1/Wave-2 file ownership disjoint).

Purpose: SEC-02 — prove the CLI honors the resolved profile tool-subset
(`config.ResolveProfile`), the second half of the security gate (91-02 is the
server-side refusal; this is the contract oracle that locks the per-profile
surface in golden form).
Output: a re-pointed `test/integration/profile_golden_test.go` plus a helper that
maps the generated verb catalog (read via `cli.VerbToolNames()`) to the tool set a
profile session exposes.
</objective>
