<objective>
Build the three pure, dependency-free foundation pieces the Phase 92 renderer
sits on: (1) a tool-name → render-class map covering all 50 generated verbs, (2)
the locus parse + path-normalization + sort/dedup core that turns heterogeneous
daemon text into `(relpath, line, col, payload)` tuples, and (3) the serr.Kind →
exit-code + stderr-prefix mapper. These are leaf functions with defined I/O, so
they are built TDD (RED→GREEN) and have NO network or cobra dependency — the
integration wiring (replacing `renderResult`, flags, main.go) is 92-02.

Purpose: Freeze the parse grammar, the render-class taxonomy, and the exit-code
contract as testable units before the renderer wires them into the verb path,
keeping 92-02 focused on integration rather than algorithm design.
Output: `internal/cli/{render_policy,locus,exitcode}.go` + their `_test.go`
RED→GREEN suites.
</objective>

<phase_notes>
**Coordinate-convention reconciliation (CONTEXT/ROADMAP wording):** CONTEXT and
ROADMAP prose say "convert LSP 0-based at the render boundary". That requirement
is ALREADY satisfied by the daemon's existing `+1` at
`internal/kernel/symbols/tools.go:189-190` (`formatLocations` emits 1-based loci).
The CLI renderer (this phase) PARSES the already-1-based locus and does NOT
re-convert — re-converting CLI-side would double-shift and produce off-by-one
goldens. So "convert at the render boundary" is honored by parse-don't-convert,
not by a second conversion. This note exists so the CONTEXT phrasing and the
parse-don't-convert implementation are not read as contradictory.
</phase_notes>
