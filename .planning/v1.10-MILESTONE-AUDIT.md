## 3. Cross-Phase Integration Findings

Full report: `.planning/v1.10-INTEGRATION-CHECK.md`

### BLOCKER — INT-BLOCKER-01: CGO=0 build broken by Phase 59

**File:** `internal/semantic/extract/provider.go`
**Affects:** REL-01 (release pipeline), EXTRACT-01..05 (CGO=0 degraded path)

`provider.go` lacks a build tag and unconditionally imports `tree_sitter "github.com/tree-sitter/go-tree-sitter"`, whose `Language` type is in a CGO-only file. Sibling files (`extract_cgo.go` / `extract_nocgo.go`, per-language `provider_nocgo.go`) follow the split pattern; the shared interface file was missed.

```
$ CGO_ENABLED=0 go build ./cmd/helix
internal/semantic/extract/provider.go:31:36: undefined: tree_sitter.Language
```

**Consequence:** Phase 58 `.goreleaser.yaml` pins `CGO_ENABLED=0` across the build matrix. The **next** `goreleaser build` fails at every target. REL-01's signed-release criterion is at risk for any post-Phase-59 release attempt. The 2026-05-04 v1.10.0-rc1 release predated this regression — but new tags will fail until fixed.

**Remediation:** Either move `tree_sitter.Language` references into `extract_cgo.go` (and add a CGO=0 stub interface) or add `//go:build cgo` to `provider.go` plus a sibling `provider_nocgo.go` returning `serr.ErrUnsupported`.

### WARNING — INT-WARN-01: Lazy-init activation does not kick `ScheduleInitialExtraction`

**File:** `internal/daemon/daemon.go:438-455`
**Affects:** EXTRACT-01

`lazyActivateFn` updates kernel / repomap / session but skips `semanticScheduler.ScheduleInitialExtraction`; only the explicit `SetActivateCallback` path (line 462–489) calls it. Recoverable because `scheduler.RequireReady` auto-kicks on cold workspaces (`ready.go:109`), but every lazy-activated workspace pays cold-start delay on first semantic consumer, and any future tool that reads the store without `RequireReady` would see an empty store.
