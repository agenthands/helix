**Evidence:**

## Overall Assessment

**Status:** `gaps_found`

The four phases of v1.8 individually deliver their requirements but tell three
slightly different stories about the same product:

1. **Setup-CLI client list drift** (F-01, F-07) is the dominant finding — every
   doc lists a different count. Real source of truth is `setup_clients.go`
   with 7 registrars (incl. OpenCode). This needs one remediation sweep.
2. **Architecture parity** (F-10, F-11) between the two architecture blocks
   (README + CLAUDE.md) is close but not aligned: Layer 3 name differs and
   fileops count is stale in CLAUDE.md.
3. **Phase 41 has no verification artifact** (F-13) — the two docs it shipped
   (INSTALL, CONTRIBUTING) are implicated in multiple integration findings that
   a phase verifier would likely have caught first.
4. **Phase 40 gaps appear resolved but verifier metadata is stale**
   (F-04, F-05, F-06). A lightweight re-verify would close these.

None of the findings breaks a user's ability to install / configure / use
Serena — the docs are functional. But the cross-doc numeric drift
(5 clients / 6 clients / 7 clients; 40+ tools / 41+ tools; 6 fileops /
7 fileops) will confuse careful readers and is easy to fix with one
reconciliation pass across all six files before v1.8 ships.

**Proposed remediation order:**
1. F-13 (run Phase 41 verifier) — produces the missing artifact.
2. F-01 + F-07 (sync client lists across README/USAGE/INSTALL/CHANGELOG on
   OpenCode inclusion and a single canonical count).
3. F-11 (fix CLAUDE.md fileops count).
4. F-10 (sync README architecture block with CLAUDE.md Layer labels).
5. F-04/F-05/F-06 (re-verify Phase 40, flip status to passed).
6. F-02, F-03, F-08, F-12 (minor polish).
